# Project J NetworkPrediction override

Origin: installed Epic UE 5.8.3, build `58210709`, `Engine/Plugins/Runtime/NetworkPrediction`. Current validation uses installed UE 5.8.4, build `58902052`. Epic copyright headers are retained. Source/config/descriptor only; engine binaries and caches are not copied. This records the override's origin separately from the current host; it does not claim an automatic engine upgrade/rebase.

The project plugin overrides the installed plugin by the same name. `Plugins/Mover` is rebuilt in the same project plugin scope because engine modules cannot depend on project modules; its own lifecycle, settings and prediction patches are recorded in [its patch notes](../Mover/PROJECT_J_PATCH.md). Do not enable another independent presentation clock or modify the installed engine.

`Private/NetworkPredictionWorldManager.cpp` calls `Private/IndependentInterpolationClock.h` for Independent interpolation. The clock policy below preserves simulation, prediction/rollback and the configured buffering windows.

- Bootstrap a first received timestamp into its server epoch with the existing configured target buffer. A late join is not accumulated history from time zero.
- Adjust presentation clock rate within 0.9–1.1 to replenish the same target after jitter.
- Bound forward advancement to received history. A long frame cannot extrapolate beyond the latest received state; a stalled stream holds its last valid interval and resumes without rewinding.
- Keep existing warnings for a genuine invalid timestamp or excessive accumulated backlog. No log category is disabled and the 100/250ms project settings are unchanged.

Regression prefix: `ProjectJ.NetworkPrediction`. `ProjectJ.CaptureMoverBuffers` writes real receive/simulation/presentation CSVs for live verification; check held time and frame stalls as well as warning counts. This does not eliminate the underlying render/game-thread hitch or guarantee smoothness under arbitrary packet loss.

The fixed and independent interpolation services now own their existing per-instance state through stable `TUniquePtr` storage. Sparse-array growth can move inline instances after their presentation Sync/Aux addresses have been published to `FNetworkPredictionStateView`. Keeping the instance address stable prevents stale public view pointers during crowd registration. Unregister/re-register still owns view withdrawal and slot reuse; this adds no per-frame republishing pass, second presentation clock, instance cap or transport change. The independent endpoint-hold branch also copies its selected receive state into that owned presentation state before finalizing. The public view therefore matches the actual output while presentation writes remain separate from receive history; the interpolation clock and selected endpoint are unchanged. `ProjectJ.Foundation.Network.InterpolationViewLifetime` checks actual fixed/independent services, growth, retirement/reuse and independent cold/held/resumed outputs. Native regressions and the original real-client failure must both be checked before treating the fix as verified.

`NetworkPredictionReplicationProxy.{h,cpp}` and `NetworkPredictionWorldManager.h` also contain bounded, default-off model-wire observations used by the existing capture. They retain a latest snapshot with an explicit binding epoch, event serial, model frame/time and optional four float scalars. Receive observation follows successful model decoding; authority observation follows the simulated-proxy model serializer. These are model events, not packet/ACK counts or proof of delivery to an individual connection. Unsupported threads/types and overflow remain explicit. The instrumentation changes native bookkeeping/API and therefore requires rebuilding its consumers, but does not add fields to the gameplay wire format. Current integration evidence and unresolved remote-quality boundaries live in the [MMORPG work record](../../Docs/Architecture/Planning/Project_J_MMO_Architecture_Work_2026-10-26.md).

For an engine upgrade, compare pristine engine sources, reapply/revalidate the small patch, and rebuild both plugins. Remove both overrides together when the upstream implementation provides equivalent behavior. Never restore old binaries to avoid the rebuild.

## Lossless Iris blob delta (protocol8)

`NetworkPredictionNetSerializers.cpp` and the private `ProjectJNPBlobWordDelta.inl` add bounded lossless XOR-word delta transport for the existing quantized FReplicationProxy blob. Identical-length payloads up to the existing16384-bit cap use a raw changed-word mask only when strictly smaller; all other changed payloads use full raw bits. Current object/name/net-token exports retain the existing full export utility and side effects, and Iris alone owns ACK baselines. The NP model serializer, precision, cadence, interpolation buffers, and raw snapshot layout are unchanged. Empty/free paths reset the existing ByteCapacity metadata together with freed storage.

`np.ProjectJ.ReplicationBlobDelta` defaults to0 and controls encoding only; decoding always supports both new modes. Serializer Version1 and project realtime/compatible protocol8 reject protocol7 peers/replays. Encoder0 is a runtime rollback within protocol8; it is not an old-wire compatibility mode. The new nonempty delta-full framing adds one selector bit. Reverting the code requires coherent rebuilt peers.

`ProjectJNPBlobDelta` is a default-disabled CSV category. Quantize blob bits are per-model quantization work. Successful serializer-attempt bits can still be rolled back/retried by Iris and are not sent/acked bytes; current inline export bits exclude outer pending token exports. These counters must remain distinct from actual connection traffic and strict movement-quality results.

Full-mode sizes continue to follow Config.MaxQuantizedSizeBits;16384 is the word-delta helper limit, not a replacement full-mode cap. The current ordinary property registry uses the default16384 config, but custom serializer contexts can provide a different config. Full-cap word/byte arithmetic avoids overflowing the32-bit bit-count intermediate. The existing public NetworkPredictionReplicationProxy.h adds only the nonshipping static GetProcessEmptyDecodeCount getter. Its counter is process-wide and read-only, incremented on successful explicit HasData=false deserialization, never clone/free/model state. Shipping contains no counter or observation call. WrapperWrittenBits excludes current inline-export and payload-body bits from successful serializer-attempt spans; neither wrapper bits nor empty counts prove a per-connection delivery or model-specific event.

Regression prefix: `ProjectJ.NetworkPrediction.BlobDelta`. BoundedWordCodec checks helper bit reconstruction/truncation through16384bits. ActualInlineSerializer dispatches the actual registered serializer, initial/full and both new wire modes, empty/size changes, same-value deep cloning, malformed lengths, and immutable baselines with inline storage/empty exports. It does not claim heap, object/name/net-token reference, real ACK loss, old-binary handshake, or200-agent performance coverage. Those require the real Iris fixture and same-binary A/B. Verification is pending for this patch; keep encoding defaultOFF until native, real heap/reference/loss and performance evidence justify enabling it.

## Receive token resolve context (native forwarding)

The standard Iris property Apply path creates a fresh FNetSerializationContext without an internal receive context. FReplicationProxy's native external receive state now carries the two borrowed FNetTokenResolveContext pointers from its actual Dequantize context into custom Apply. Each Dequantize clears the native value first; default-state construction keeps it null. The context is not reflected/serialized, not added to the quantized baseline or64-byte observation, and not copied to the live NP target by Apply. Both peers/consumers require a coherent native rebuild; this does not change the wire protocol.

Apply uses the existing public FIrisObjectReferencePackageMapReadScope for the actual source exports/context. Its installed-engine contract invalidates current read exports on scope exit; it does not restore an outer nested read or the previous token context. No private accessor, package-map cache, guessed ServerConnection, connection/generation registry or retained source-state observer is added. Normal AP/SP/replay dispatch forwards its own receive context. Driver teardown during active Apply, nested external read restoration, multi-driver and replay runtime events require separate lifecycle verification; do not claim those complete from a normal socket run.

The actual low-density Iris lifecycle cohort must verify references/names/tokens, empty->nonempty, heap storage, re-entry, recreation and packet loss. A default-context native regression checks default/reset/copy semantics only; it does not replace a positive actual-connection test. Existing NP Apply ignores its inner archive failure after calling the model codec; that pre-existing partial-apply/error-propagation boundary is documented separately and is not changed by this context fix.

CSV retains SerializerErrorOrOverflowCount as aggregate write attempts and splits explicit SerializerContextErrorCount from SerializerWriterOverflowAttemptCount. Valid large objects can exceed an attempted packet's capacity and be rolled back/retried/split by Iris; those overflow attempts are observed separately, not rejected as model corruption. These are write-entry counters, not malformed-decode, FPS or sent-byte metrics. The low-density runner rejects context errors and inconsistent aggregate classification while keeping its actual model/lifetime/exit requirements. Positive12k-bit heap/model reception still requires the real run; no result is inferred from expected MTU behavior.

## Distinct word-delta receive coverage

The low-density fixture's cases1-3 now use a5001-bit body, retaining real heap storage (>4096-bit blob) while separating ordinary packet-sized delta opportunities from the unchanged8193/12001-bit grow/huge/empty/re-entry/recreation cases. Case1 reads the existing public baseline-throttle CVar and remains stable for two configured refresh intervals measured by actual server engine-frame advancement; it does not modify that policy, net speed, MTU, packet cap, cadence or buffer. A frame wait is an opportunity, not proof of an ACKed same-size baseline. The original13-case Exact/loss/lifetime requirements remain intact.

Encoder1 coverage now requires successful sender WordDeltaCount AND successful quantized WordDeltaDecodeCount on BOTH real clients. Decoder coverage counts only completed word reconstruction, not later model Apply; actual fixture receipts still verify every model field/ref/name/token separately. Encoder0 requires no word-mode send/decode events. No count gate is weakened.

The previous CSV name InitialFullSuccessfulAttemptBits included every call of Serialize, including ordinary full fallback, and never proved initial-object state. New captures use the accurate FullSerializeSuccessfulAttemptBits name. Old receipts/counter names are preserved with that interpretation correction. Installed huge-object preparation itself calls the same WriteObjectInBatch/ACK-baseline logic; no unconditional huge-mode delta bypass was established from source. Earlier WordLoss1 retained successful lifecycle convergence with zero word coverage and is not a passing word-delta run.

## Bounded independent interpolation text diagnostics

Only the independent endpoint-hold Display is aggregated per service/model: the original abs(time-gap)>100 predicate is unchanged. Every observed predicate contributes to total sim-ticks, early/late sign totals and peak absolute gap, with actual first/last observation QPC in each summary. Counts are sim/frame observations, not unique affected actors or packet loss. The existing default-disabled ProjectJNPBlobDelta CSV category records the same totals; no category registration/configuration or model state is added.

The first pending interval prints immediately; further summaries are limited to one per wall second per service/model, with one pending terminal flush when that service is destroyed. Unregister does not emit one line per actor or discard pending service totals. There are no per-instance episode fields, timers, global maps or managers. NO_LOGGING compiles the added state/calls out; optional CSV follows that build gate. Existing fixed SystemFault trace/log calls and all independent trace/clock/history/pose/view/cue paths remain unchanged. No root cause or quality improvement is claimed: this is diagnostic IO/formatting containment.

The out-of-sync identifier remains compatible with current strict log validators. Delayed summaries may conservatively classify an earlier startup interval as post-capture; first/last QPC retains the real observation range for analysis. This patch does not relax that existing line-based failure gate or implement startup reclassification. Terminal flush relies on normal service destruction; crash/forced-termination evidence can be incomplete and must not be counted as a passing capture. Existing raw/selected observations and strict motion gates remain required.
