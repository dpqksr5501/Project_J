# 내부 갱신·수명 정리와 콘텐츠 제작 도구 — 2026-09-19

직업·전직 확장 기반 이후, `Source`의 7개 모듈과 프로젝트 실험 플러그인을 대상으로 Tick/타이머, 작업 큐, 동기 로딩, 이벤트 구독, 상태 소유권을 검색하고 주요 실행 경로를 읽었다. 검색 결과를 전 파일의 의미 검증 또는 모든 콘텐츠의 플레이 검증으로 간주하지 않는다. BP·DA·레벨은 이번 작업에서 변경하거나 저장하지 않는다.

## 제작 자동화의 경계

**Tools → Project J → Create Class / Advancement Bundle**에서 기존 직업과 선택적 스타일·선행 전직을 지정한다. 새 ID·목적지와 참조를 검증하고, 직업/전직 루트·스타일·필요한 콤보를 미저장 상태로 생성·연결한다. 개별 공격·몽타주·능력 묶음·애니메이션은 공유하므로 모든 하위 에셋을 무작정 복제하지 않는다.

미리보기는 transient 초안만 만들며 템플릿을 변경하지 않는다. 생성 시에도 검증을 다시 수행하고 기존 패키지/ID를 덮어쓰지 않는다. 저장은 사용자의 표준 에디터 Save 작업이다. runtime 레지스트리의 config 배열은 자동 수정하지 않고 정확한 등록 줄을 제공한다. **생성 묶음 전체 Undo는 지원하지 않는다.** 생성 전 미리보기와 생성 후 Content Browser의 표준 삭제/저장 절차를 사용한다.

## 유지한 갱신과 이유

- 플레이어 Actor Tick: 방향별 속도, 공중 회전, 제자리 회전, 현재 프레임의 궤적·locomotion 의미 상태를 처리한다. 태그 변경 이벤트만으로 대체하면 입력 방향/속도/회전 변화가 누락된다.
- 궤적: 부모의 movement delegate를 이미 해제하고 플레이어 경로에서 생성한다. 같은 프레임 중복 생성 방지와 전용 서버 생성 제외를 유지한다.
- 입력 조정 Tick: Enhanced Input의 해당 프레임 콜백이 모두 끝난 뒤 Stop을 확정하는 일회성 실행이다. 상시 중복 Tick으로 취급하지 않는다.
- 로컬 카메라: 보간과 공개 BlueprintReadWrite 설정의 런타임 변경을 처리한다. 외부 직접 쓰기를 무효화하는 setter 전환 없이 유휴 Tick만 끄지 않는다. 원격 카메라는 이미 비활성이다.
- 장비/인벤토리/진행/UI: 이벤트 기반이며 UObject/GAS 변경은 게임 스레드에서 직렬 처리한다. 장비 표현의 독립 궤적 및 제한된 재시도만 필요한 기간 실행한다.
- NPC/Mass/타깃 점수: 제한된 중앙 수집·값 계산·결과 적용 구조를 유지한다. Mass 소유 시 기존 이동/메시 갱신을 꺼서 중복 소유를 피한다.
- 비동기 visual lease: 완료 후에도 소유자 소멸을 회수해야 하므로 모든 완료 lease의 유지관리 Tick을 삭제하지 않는다.
- 애니메이션 budget: montage/물리/로컬 소유권 등 자격 변경을 확인하는 정책 pass를 유지한다. 공개 엔진 상태를 별도 캐시에 복제하지 않는다.
- MMO 기반/Gateway: 값 기반 계약, 큐 제한, 취소/종료 경계를 유지한다. 새로운 worker나 전역 잠금을 추가하지 않는다.
- 실험/부하 fixture와 에디터 preview: 개발용 실행과 제품 실행을 구분한다. 측정용 Tick을 제품 중복 갱신으로 삭제하지 않는다.

## 범위와 확인할 점

### 궤적 컴포넌트의 현재 상태와 고도화 기준

`Project_JMotionMatchingTrajectoryComponent`는 기존 부모의 movement delegate를 해제하고 플레이어의 갱신 경로에서 생성한다. 같은 프레임 생성·후처리 중복 방지, 전용 서버/탑승 중 생성 제외, 원격 캐릭터의 최근 렌더 여부에 따른 생성 제어가 있다. 표시 재개·회전 모드 변경 시 기록을 재설정하며, 현재 handover 경로는 궤적과 서버 피격 기록을 함께 초기화한다. 샘플 시간 기반 값 질의와 비정상 입력 방어는 앞선 [내부 리팩터링](Internal_Refinement_2026-09-13.md)에 포함됐다.

현재 기본 이동을 위해 전면 교체하거나 새 스레드를 추가할 근거는 확인하지 못했다. 대시·넉백·수영·비행을 실제로 도입할 때 이동 문맥별 예측 규칙과 reset 조건을 보강한다. 이동 플랫폼, 급격한 프레임 저하, 네트워크 보정에서의 품질은 별도 시나리오 검증 대상이다. 해당 기능이나 모든 순간이동 경로의 연동이 이미 구현·검증됐다는 의미는 아니다.

### 검증 범위

- 클래스의 물리적 분리는 새 UObject 컴포넌트나 Tick을 추가하지 않는다. 이 변경만으로 캐릭터 클래스의 모든 책임을 분리했다고 주장하지 않는다.
- SSR RecordRateHz/MaxRecordTime은 BeginPlay에서 검증·고정하는 기본값이다. 실제 기록 빈도는 서버 프레임 속도에 제한된다.
- 이 문서의 구조 변화는 FPS/동접 수 향상률 측정이 아니다. 예를 들어 120fps에서 30Hz 기록을 요청하면 스케줄러 호출을 줄일 수 있지만, 전체 서버 비용이 75% 감소한다는 뜻이 아니다.
- 서버 간 이동은 기존 transport 계약을 보강한 것이며 라이브 서버 네트워크/DB 운영 구현을 추가한 것은 아니다.
- 실제 네트워크 PIE, ABP Event Tick, 탈것 이착륙과 강제 하차 공간 정책의 플레이 검증은 자동화 검사와 별개다.

## 검증

- 직접 UBT 실행: **Project_JEditor / Project_J Win64 Development 빌드 성공**. 게임 실행 파일도 실제 재링크했다.
- NullRHI 자동화: **81개 통과 / 테스트 오류 0 / 경고 0**, 요청한 필터 누락 0. 이번 신규 12개와 기존 회귀 69개를 포함한다.
- 모듈 DAG 및 MMO 목록 205개 / 20개 영역 검사 통과. runtime 모듈 의존성을 추가하지 않았다.
- GAS Task의 실제 World Tick 실행·종료 후 sleep, SSR 실제 주기·hitch·reset, 겹치는 애니메이션 요청·종료 복원, 탈것 입력/체력/표현, Handover 재진입, 제작 초안 격리를 검사했다. 기존 전직·장비·전투·Stop→Idle·NPC·군중 테스트도 포함한다.
- 첫 컴파일에서 테스트 fixture의 protected 접근/이름 충돌을 수정했다. 첫 회귀의 군중 예산 CVar 누락 5개와 원격 역할 fixture 설정 2개를 고친 후 최종 81개를 다시 검사했다. 제품 런타임을 바꿔 테스트 전제를 우회하지 않았다.

[검증 JSON](Internal_Polish_Validation_2026-09-19.json)에 최종 로그·보고서 해시와 변경 소스 해시를 기록한다. 소스 목록은 이전 미커밋 확장 기반도 포함한 통합 작업 상태다. 이전 확장 기반의 소스 해시는 당시 스냅샷이며, 이후의 이 변경까지 포함한 결과를 의미하지 않는다. 테스트의 오류·경고 수는 테스트 보고서 기준이며, 엔진 시작 로그 전체 또는 실제 네트워크 플레이 검증을 뜻하지 않는다.
