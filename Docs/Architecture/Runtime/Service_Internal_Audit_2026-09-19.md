# Core·MMO·서비스 내부 점검 (2026-09-19)

## 점검 범위

`Project_JCore`의 시각 에셋 임대, 타깃 점수 계산/공간 스냅샷, 메시지 라우터, 풀 정의 레지스트리와 `Project_JMMO`의 기능 의존성·예약·요청 추적·저장소 기반을 검토했다. 게임 모듈의 Gateway/Handover, Social, GameState/PlayerController/군중 프로파일링 및 Character UI 바인딩도 Tick·큐·콜백 수명 관점에서 확인했다. 에셋 내부 그래프와 운영 서버 구현은 점검 범위에 포함하지 않는다.

## 수정

- **Handover 활성 상태 판정 통합:** 이전 전송의 종료 기록이 남아 있으면 같은 액터의 새 활성 전송을 놓치던 조회를 기존 활성 판정 함수로 통합했다.
- **지연 응답 큐 재진입:** Loopback 전송 완료 항목을 큐에서 먼저 제거하고 콜백을 호출한다. 준비된 응답의 ID/시도 번호를 스냅샷으로 순회하므로 콜백에서 자기 요청·다른 준비 요청을 취소하거나 새 요청을 추가해도 배열 참조가 무효화되지 않는다. 새 요청의 지연 시간은 다음 Tick부터 소비한다.
- **상태 알림 재진입:** 상태 변경 알림 전 상태를 확정하고, 알림 후에는 전송 ID로 기록을 다시 조회한다. 알림에서 추가 전송이 맵을 확장하거나 현재 전송을 취소해도 이전 참조로 후속 전이를 실행하지 않는다. Tick의 순회 대상도 ID로 복사한다.
- **종료 수명:** 종료 플래그와 상태 분리를 먼저 적용한 다음 전송을 취소한다. 종료 이후 새 작업은 거절한다. 호출 중인 전송 객체는 지역 shared pointer로 유지하고 재귀 Tick은 차단한다.

## 유지한 구조와 이유

| 영역 | 유지 이유 |
| --- | --- |
| VisualAssetSubsystem | 요청이 없으면 Tick을 쉬고, 전달된 임대도 소유자 소멸 감지·회수가 필요하다. 부하 한도와 순환 방문 예산을 유지했다. |
| TargetScoringSubsystem | 작업이 있을 때만 Tick한다. 값 복사 기반 작업, 전역 작업 한도, 취소 토큰 및 월드 종료 처리가 이미 분리되어 있다. |
| Gateway | 프레임 Tick 대신 로그 플러시 타이머를 사용한다. 진행 요청 수 제한, 세션 종료 후 완료 억제, 최대 한 번 완료 처리를 유지했다. |
| Handover ticker | 전송 어댑터의 진행, ACK 제한 시간, 재시도와 종료 기록 만료를 담당한다. 어댑터의 유휴 유지 작업 계약을 바꾸지 않고 상시 ticker를 유지했다. |
| UI/MVVM | 속성 변경 이벤트로 갱신하며 UI 바인딩 컴포넌트 Tick은 꺼져 있다. 같은 값은 다시 알리지 않는다. |
| MMO 예약·저장소 | 임계 구역 안에서 콜백/I/O를 실행하지 않는 제한된 메모리 기반 구현을 유지했다. 운영 DB/분산 잠금 구현으로 간주하지 않는다. |
| 프로파일링 군중 | 명시적인 부하 테스트가 실행 중일 때만 Tick한다. 게임플레이의 중복 Tick으로 취급하지 않았다. |

## 검증

기존 `ProjectJ.Architecture.Handover.StateMachine`에 같은 액터의 재전송 조회 회귀 검증을 추가했다. `TransportReentrancy`는 콜백 중 자기/타 요청 취소와 새 요청 추가를, `NotificationReentrancy`는 상태 알림 중 기록 확장·취소·종료를 검증한다. 로컬 diff 공백 검사는 통과했다. 빌드 및 자동화 실행 결과는 상위 통합 검증 기록을 기준으로 한다.

이 변경으로 FPS나 동시 접속 수 향상을 측정한 것은 아니다. 이번 서비스 변경의 목적은 재진입 오류 제거와 상태 소유권 명확화다.
