### 이번 점검에서 재현한 문제

- 다른 월드의 액터를 투사체 소유자와 다단 적중 대상으로 넘기자 통과했다. 80발 시험에 외부 월드의 1발이 남아 81발이 됐다. 풀 진입 시 서버 월드·소유자·종료 상태를 확인한다. 충돌 콜백이 월드를 종료하면 남은 전달을 중단한다. 동기 충돌과 선택적 비동기 스윕을 모두 시험했다. 스레드는 탄도 수치 계산과 타깃 점수 스냅샷에 사용하고, 충돌 결과·GAS 적용·취소는 게임 스레드에서 처리한다. - HUD 카탈로그에서 중복 ID나 잘못된 프로필을 넣으면 런타임의 기본 UI 복구만으로는 제작 누락을 찾기 어려웠다. 선택 검증과 런타임 선택이 같은 유효성 규칙을 쓴다. 원형 스킬은 선택한 부여 에셋에서 실제 GAS 소스와 기본 공격 정의의 조합을 확인한다.

## 로컬 재검증과 제작 경로

**원거리 숲과 바이옴 이동.** 제작 MainWorld의 실제 HUD 캡처에서 오래된 HLOD 2개를 발견했다. UE 5.8.4의 `LogHLODRuntimeSubsystem Verbose`로 좌표 X0/Y−1과 X−1/Y−1의 두 Instancing 프록시가 존재하지 않는 원본 셀을 참조하고, 런타임이 둘을 숨기는 것을 확인했다. 메인 월드에 `WorldPartitionHLODsBuilder -SetupHLODs`, 이어서 `-BuildHLODs`를 실행해 셀 구성을 동기화하고 666개 프록시를 빌드했다. 맵에 콘텐츠를 추가할 때에도 같은 절차를 사용한다. 바이옴 검사기는 이제 실제 플레이 월드에서 엔진이 보고한 오래된 프록시 수를 관측점마다 남기고 0을 넘으면 실패한다. 원경에 남은 오브젝트 수와 플레이어가 본 화면을 함께 기록한다. **직업·스킬 확장.** `DA_ProjectJUIDefault`의 추가 슬롯에 직업 ID, 일반 입력 태그, 이름, 아이콘을 설정한다. 컨트롤러가 이미 제공한 슬롯의 순서와 프로필 저장 키를 유지한다. 새 캐릭터의 직업이 늦게 도착해도 표시를 다시 계산한다. 다른 직업들은 같은 키를 서로 다른 기술에 쓸 수 있다. 사용자가 직접 편집해 저장한 배치는 유지되므로 기존 캐릭터에서는 퀵슬롯 선택이나 배치 초기화를 통해 새 아이콘을 원하는 칸으로 옮길 수 있다. Ground Pulse에는 직접 제작한 128px 아이콘과 0.54초 효과음, 거리 감쇠, 서버 적중 시점의 GAS Gameplay Cue를 연결했다. 기존 로컬·파티·기타 플레이어 음향 예산을 사용한다. 실제 제작 맵에서 Enhanced Input의 CapsLock+T 입력과 HUD 6번 슬롯으로 사용해 마나 100→90→80, 두 번의 음향 재생 승인, HUD 아이콘과 전조를 확인했다. **경사·계단·절벽.** 같은 원형 전조를 쓰는 기술은 시작 시 둘레 32점을 월드 정적 충돌에 한 번씩 투영한다. 중심 충돌면 기준 ±50cm 안의 지지면을 따르고 끊어진 쪽은 점선으로 표시한다. 서버는 기존 수평 피해 반경, 수직 한도와 차폐 검사를 수행한다. 지형 표시를 위한 매 프레임 검사나 네트워크 필드를 추가하지 않았다. 계단과 허공이 섞인 둘레를 회귀 조건에 포함했다. [전조 회귀](../../../Source/Project_JCharacter/Private/Tests/Project_JPresentationRecoveryTests.cpp)

**지역 이동과 데이터 이관.** 한 맵 안에서 초지·산지·호수 사이를 달리는 것은 World Partition 스트리밍이다. 온라인 지역 서버 이동은 목적지 채널 선택, 티켓 소비, 세션 세대 갱신, 캐릭터 인계가 필요하다. 또 보스 배치 ID를 패치하는 일은 별도의 DB 이관이다. 로컬 PostgreSQL·Nakama에 등록한 두 공개 지역의 서비스 왕복에서 같은 캐릭터의 세션이 1→2→3으로 전진했다. 보스 이관은 네이티브 시험 DB 복사본으로 재실행해 보상·퀘스트 201행의 내용 보존과 오류 조건 5개의 거절을 확인했다. 라이브 서비스 데이터가 생기면 그때의 백업·배치 키와 대조한다. ### 경사면 전조 수정과 최종 회귀

**새 콘텐츠에 적용되는 범위.** 새 지상 공격은 AttackDefinition·GAS 능력·AbilitySet·클래스 부여·입력 매핑의 기존 연결을 사용한다. 전조 경계·만료·경사·서버 피해 검사는 `Ground Pulse` 이름과 무관하게 같은 원형 공격 구현을 사용하는 능력에 적용된다. 시험의 보스 이름, 목표 위치, 마나 30→20, 반경 480/490은 고정된 회귀 입력이다. 신규 월드에는 WorldDefinition 연결·WP 스트리밍·원경 대상의 HLOD 분류와 빌드가 필요하다. 신규 탈것은 실제 이동 소스가 속도·모드 변화를 스트리밍 제공자에 전달해야 한다. 검증기가 누락을 찾는 범위와 제작자가 새 에셋에 연결해야 하는 범위를 나눠 본다.

추가 경사 시험에서 18도 바닥 위의 경고가 수평으로 그려져 서버의 수평 피해 반경과 바닥 표시가 어긋나는 결함을 재현했다. 경고 액터의 최초 회전에 서버 충돌면 법선을 반영하고, 표시 컴포넌트는 해당 면에서 기존 피해 원통의 수평 반경·높이 한도에 맞춘다. 지형 트레이스는 기존 서버 쿼리 하나를 그대로 사용한다. 신규 전송 필드나 클라이언트 프레임별 트레이스는 추가하지 않았다. 같은 18도 시험에서 모든 끝점이 지면에 평행하고 수평 반경 350cm를 유지했다. 저옵션 4소켓 시험에서 늦게 들어오거나 복귀한 클라이언트도 같은 경사 법선 Z=0.951, 남은 시간 2.988초·1.066초로 표시했다. 최종 네이티브 39건 중 38건 일반 성공, 1건 PoseSearch 경고 동반 성공, 실패·미실행 0건이다. 이 방식은 중심에서 맞은 평면을 사용하므로 원 둘레에 절벽이나 단차가 걸치는 경우에는 별도 관찰이 필요하다. 두 인계 문서의 약속을 기준으로 실제 코드, 저장 에셋, 실행 진입점과 증거를 독립적으로 대조한다. 목표는 새 월드·구역·지상 탈것·비행 탈것·직업·스킬이 같은 제작 절차를 통해 최적화와 품질 기준을 적용받게 하는 것이다. 먼 숲과 랜드마크 유지, 고속 이동의 시각·충돌 연속성, 혼잡 상황의 필수 전조·서버 권위·보상을 함께 본다.

GPT‑6.2 Astra는 이번 독립 검증과 설계 판단을 맡는다. 재현한 결함, 필요한 개선의 우선순위와 다른 설계가 유리한 조건을 기록한다. 이후 구현·세부 구현·버그 탐지·디버깅·회귀는 GPT‑6.2 Sol에 넘긴다. 사용자의 최신 요청과 현재 작업 트리를 기준으로 삼고 과거 문서의 제안과 예시 명령은 이력과 재현 입력으로 읽는다. 현재 설계는 비교의 출발점이다. 워크플로가 단순해지거나 책임이 더 잘 맞는 구조가 있다면 기존안과 비교한다.

포털의 혼합 목적지 등록, 경고의 늦은 연결 도착과 높이 가독성, 기존 고속 이동의 선택적 감속, Shipping의 테스트 콘텐츠 포함은 확인 후보로 남긴다. 위 표에서 기존 구현이 실제로 충족하는 조건부터 표시하고, 재현 전에는 결함처럼 기록하지 않는다. Niagara Data Channels, Mass/VAT, 임포스터, 추가 배치 최적화, 직접 I/O 같은 대안은 각각 CPU/GPU/메모리·제작 비용과 권위/복구 영향이 보이는 같은 장면의 비교에서 판단한다. 시장과 엔진 기능을 다시 조사할 때는 원래 인계 7절의 공식·제작사·오픈소스·독립 자료를 현재 엔진 버전과 대조하고 새로운 근거를 붙인다.
