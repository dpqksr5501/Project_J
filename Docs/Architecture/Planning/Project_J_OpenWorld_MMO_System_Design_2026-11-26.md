# Project J 오픈월드·MMORPG 확장 설계

본문의 ‘현재’와 기존 수치는 설계 당시의 기준선이다. 이후 월드 정의 스캔 범위·이동 모드 조회·필수 경고 검사에 적용한 변경은 [기반 구현 인계](Project_J_OpenWorld_Foundation_Handoff_2026-11-26.md), 다음 콘텐츠의 작업 순서와 판정 기준은 [Sol 세부 구현과 시험](Project_J_OpenWorld_Sol_Implementation.md)에서 확인한다.

2026-11-26 · 설계안 2 · 기준 소스 `f6eb7bcba3d6be8ca6be46858230926341838daa` · 로컬 실측 기준 UE 5.8.4 Win64 Development

**설계 결정.** 새 지역을 만들면 작업자는 숲·랜드마크·상호작용 오브젝트가 플레이에서 어떤 역할을 하는지 정한다. 실제 먼 풍경은 언리얼의 World Partition(WP)과 HLOD가 그린다. 새 탈것은 현재 이동 상태와 속도를 기존 스트리밍 경로에 제공한다. 새 공격은 플레이어가 읽어야 할 경고의 의미를 정의하고, 직업·무기·스킨은 그 위의 연출을 고른다. Project J가 추가로 책임질 부분은 제작 의도가 누락되었는지 찾고, 해당 결과가 빌드·패키지·플레이까지 이어지는지 확인하는 일이다.

이 문서는 설계 및 구현 인수 기준이다. ‘채택’은 다음 구현의 기준을 뜻한다. 실측은 아래에 실행 조건을 붙였다. 과거 자료와 대화 원문은 사용자 바탕화면의 `Project_J_오픈월드_MMO_최적화_인계_2026-11-26.md` 4·7·9·10절에 있다. 기술 설계 및 후속 설계 판단은 GPT-6.2 Astra, 사용자의 구현 요청 이후 세부 구현·결함 탐지·재현·디버깅·수정·회귀는 GPT-6.2 Sol이 담당한다.

## 1. 어떤 경험을 보장할 것인가

수치의 원자료는 로컬 ArchiveStore 색인의 `AAAOverall_20261126_` 33개 항목과 [기존 감사](Project_J_PhaseAD_Codex_Audit_2026-11-25.md)에 있다. 과거 200개 렌더 캐릭터, 합성 연결, 실제 보스 실행은 각각 별개다. 최소 사양·목표 해상도·출시 프레임률·허용 반응 지연은 아직 제품 결정이므로 아래 비교 예산과 분리한다.

## 3. 월드 제작과 원경

### 대상 발견과 제작자 경험

1. **검사할 월드는 기능을 켰는지와 독립적으로 발견한다.** 저장 시에는 변경한 맵·외부 액터의 소유 맵을, 배포 검토 시에는 변경된 프로젝트 지도, 기존 Cook 대상, 게임 입구·포털·던전의 지도 참조를 살핀다. 출시 의도가 있으나 입구도 Cook 루트도 없는 새 지도는 변경 지도 목록에서 ‘용도 미분류’로 나온다. 테스트·에디터 전용·실내·플레이 가능한 WP 야외를 기존 제작 입력이나 지도 메타데이터에 선언한다. 일단 한 번 분류한 테스트 맵을 매번 예외 등록할 필요가 없게 한다. 외부 패키지 목록이나 참조를 읽지 못한 결과는 ‘검사 불가’로 기록한다. 조회 결과 0개를 성공으로 처리하지 않는다.
2. **엔진의 레이어 기본값부터 쓴다.** 반복 식생 구역에는 Instancing HLOD를, 정적 건축/랜드마크에는 실루엣과 재질을 유지하는 적절한 레이어를 지정한다. 제작자는 기본값을 상속하고 다른 표현이 필요할 때만 예외를 기록한다. 기존 수작업·PCG·생성 스크립트는 같은 역할을 전달한다. 생성기 소유 태그는 재생성 대상을 추적하는 용도로 유지한다. 검사 대상 식별에는 소유 태그 대신 구역의 역할, FoliageType/컴포넌트나 원본 자산, 공간 배치 속성을 사용한다. 역할이 모호한 수동 배치는 검사에서 위치·원본을 보여 주고 사람이 분류한다. 작은 풀이나 실내용 나무까지 일괄 강제하지 않는다.
3. **의도와 실제 설정을 따로 읽는다.** 원거리 필수로 분류된 대상을 먼저 선택하고, 그 후 Actor/컴포넌트 HLOD 참여, 유효 레이어·빌더 타입·메시의 최종 LOD·WPO 사용·종료 거리·그리드를 읽는다. Actor 직접 지정 및 Data Layer/World Settings 상속은 UE가 해석한 결과로 확인하고, 상충하거나 판정 불가하면 원인을 보여 준다. ‘HLOD 참여 꺼짐’ 자체가 검사에서 제외되는 현재 경로를 없앤다. 명시적 제외에는 대상·적용 범위·이유·대체 표현(필요한 경우)이 따른다. 기존 `HLOD_MainWorldForest`의 Instancing을 정상 기준점으로 삼는다. 가이드의 임포스터 이름으로 실제 에셋 이름을 일괄 변경하지 않는다.
4. **변경 범위만 따라 빌드한다.** 외부 액터 저장에서는 해당 액터·소유 맵, 공유 머티리얼·레이어·수종 변경에서는 이를 쓰는 구역과 프록시를 역추적한다. 이동·삭제는 이전 셀과 새 셀 양쪽을 무효화한다. 생성 입력·결과 패키지와 빌더/엔진 버전·의존성 변화로 재생성 필요 여부를 판정한다. 부분 실패는 기존 정상 산출물을 유지하고 릴리스 대상으로 승격하지 않는다. 수작업 수정은 GenerationRecord의 소유 범위 밖에서 보존한다. 82,758그루 일괄 빌드에서 기록된 91GB OOM을 고려해 대표 셀에서 피크 RAM과 작업 시간을 먼저 측정한다.
5. **출시 경로를 역으로 시험한다.** WorldDefinition 스캔이 현재 `/Game/World/MainWorld/Data`에 한정된다. 기존 Cook 규칙으로 도달하거나 새 월드의 승인된 콘텐츠 루트/명시 자산을 추가하는 방식으로 등록한다. 모든 `/Game` 자산을 AlwaysCook하지 않는다. 패키지에서 일반 입구로 새 맵에 도달하고, 소스 셀이 내려간 시점에 예상 프록시가 실제로 그려지고, 재진입하면 원본으로 돌아오는지 본다. strict 선택 manifest는 선언한 패키지에 대한 영수증이다. 배포 맵 도달성·외부 액터·생성 프록시 판정은 별도 결과로 연결한다.

**화면과 게임 상태.** 근경은 수종별 메시·바람, 중경은 저비용 메시·제한된 WPO/그림자, 원경은 숲의 색·수관·랜드마크가 기준이다. 거리 값은 기존 프리셋에서 시작해 화면 점유율·고도·시야각과 지상/상공의 촬영 결과로 정한다. 나무마다 잎을 남겨야 한다는 규칙은 없다. 새 수종은 우선 기존 Instancing으로 보고 수관이 무너지면 최종 LOD/Preserve Area, 픽셀·그림자 비용이 높으면 마스크 재질/WPO/VSM, 훨씬 먼 거리에서만 실패하면 임포스터를 같은 카메라로 비교한다. 도시·광산 반복 프롭은 셀·재질·그림자·충돌·변경 빈도가 맞는 묶음에서 ISM/HISM이나 Packed Level Blueprint를 선택한다. 거대한 한 묶음의 bounds가 컬링과 셀 해제를 막는지도 본다.

채집 나무·문·파괴 가능한 프롭에는 안정된 배치 ID와 서버 상태를 둔다. ISM 인덱스나 HLOD Actor는 재생성 시 달라진다. 재진입 시 서버 상태로 상호작용과 근경 표시를 복구한다. 개별 제거가 게임에서 중요한 성문처럼 정적 프록시의 모습이 플레이를 오도하는 대상은 별도 표현으로 분리한다. WP 셀 경계, WorldGen 연결 포트, 채널/인스턴스 ID는 각각 독립적이다. 별도 대륙은 기존 연결 포트 쌍·방향·단위(m→cm)·도착 위치를 확인하고, 다른 서버로 넘어갈 때는 세션 핸드오버를 거친다. 실내 non-WP 던전은 Cook·입장·복귀 검사를 받으며 원경 검사는 해당 없음으로 남긴다. **원본이 실제로 내려갈 수 있는지도 검사한다.** 멀리 떨어진 배치 Actor가 서로를 직접 참조하면 WP가 함께 로드하는 묶음이 생길 수 있다. 대표 셀에서 HLOD를 만들었는데도 원본이 계속 남으면 먼저 추가 스트리밍 소스·항상 로드 설정·Actor 간 참조를 확인한다. 공동 수명이 필요한 참조는 유지하고, 장소 식별만 필요한 참조는 기존 Place/배치 ID로 해결한다. 테스트는 원본 활성 → 프록시만 가시 → 재진입 후 원본 활성 순서를 기록한다. 프로필러에 프록시 개수가 잡혔어도 원본과 장시간 중복되면 별도로 집계한다. [Epic World Partition](https://dev.epicgames.com/documentation/en-us/unreal-engine/world-partition-in-unreal-engine)

**같은 장소의 상태가 바뀌는 경우.** 축제 전후의 광장이나 성문 개폐처럼 실제 플레이에서 쓰는 상태 조합만 골라, 유효한 Runtime Data Layer와 HLOD가 보여 주는 장면을 근경·원경에서 맞춘다. 인접 구역에서 전환 중 접근, 옛 프록시가 남음, 재접속 후 초기 상태도 포함한다. 개인 퀘스트 표시는 개인 상태를 소유한 경로에서 해석한다. 공유 충돌·문·전리품까지 바꾸는 사건은 기존 월드/인스턴스 권위가 적용한다. 두 플레이어의 진행도가 다를 때 한 명의 표시 변경이 다른 사람의 통행이나 보상에 영향을 주면 실패다. 개별 퀘스트마다 월드 레이어를 새로 만드는 비용도 피한다. [Epic Data Layers](https://dev.epicgames.com/documentation/unreal-engine/world-partition---data-layers-in-unreal-engine)

### 정책 필드와 제작 피드백

기존 `WorldDefinition`은 지역 정체성·도착과 일반 예측 튜닝을, 현재 스트리밍 컴포넌트의 `HighSpeedPolicy`는 속도별 2단 예측 프로필을 제공한다. 이번 설계에서 HLOD 레이어의 자산·빌더 타입·실제 전환 범위의 주인은 UE 레이어다. `RequiredFoliageHLODLayerName`과 임포스터 거리처럼 선언과 실제 소비가 갈라진 필드는 구현 전에 BP·직렬화 에셋·제작 스크립트 참조까지 대조한다. 새 검사는 실제 레이어와 역할의 허용 조건을 읽는다. 참조가 남으면 기존 필드는 이행용으로 읽고, 소비가 끝난 항목만 폐기한다. 일반 예측과 고속 프로필, 엔진 레이어에 같은 거리값을 세 번 입력하게 만들지 않는다.

제작자가 받아야 할 진단의 최소 단위는 **소유 맵과 셀/액터 또는 공격 에셋, 기대한 역할, 실제 해석 결과, 실패 단계, 고칠 위치**다. 예를 들어 ‘북쪽 숲의 수관은 원거리 필수인데 액터에서 HLOD 참여가 꺼져 있음’과 ‘상속한 Instancing 레이어는 유효하나 설치 패키지에 해당 프록시가 없음’은 수정 위치가 다르다. 의도적으로 근경 전용인 소품은 해당 사유로 통과하고, 의존 패키지를 읽지 못했으면 배포 대상만 재검사한다. 에디터 저장 단계에서는 빠른 안내를 주고, 동일한 문제로 저장 자체가 막혀 수리가 어려워지는 상황을 피한다.

## 4. 고속 지상·비행·도착

기존 두 제공자를 유지한다. 외곽은 `Loaded`로 패키지를 읽고, 더 가까운 진행 구간은 `Activated`로 액터 등록을 요청한다. 기존 Pawn/Movement가 제공하는 위치·속도·이동 모드가 입력이다. 지상은 수평 속도와 선회, 비행은 3차원 속도·강하·지면 이격을 사용한다. 새 지상 탈것이 기존 Pawn 속도를 제공하면 공용 경로를 탄다. 비행 판별은 현재 Mover/레거시 타입에 묶여 있다. 새 이동 계열이 생길 때 이동 모드 조회를 기존 이동 소유자의 공용 질의로 모으고, 클래스명별 예측 분기를 추가하지 않는다. 지면 이격이 불명확하면 상세 그리드를 유지한다. 다른 카메라는 원경 품질의 입력이 될 수 있으나 캐릭터의 충돌 준비나 전송 권한을 대신하지 않는다.

**튜닝 절차.** 앞선 구간의 유효 준비 거리는 진행 방향으로 가장 먼저 필요한 경계까지 잰다. 필요한 여유 거리는 대략 `해당 구간 속도 × 요청부터 사용 가능까지의 상위 지연 + 선회·제동 여유`다. 읽기 완료, GT 등록, 물리 충돌, 밉·PSO 첫 사용을 따로 측정한다. 상한 거리와 메모리 안에서 현재 속도 프로필의 lead/radius를 조정한다. 메모리나 등록 대기가 먼저 포화하면 요청 반경 확대는 악화 요인이다. 급선회는 기존 부채꼴과 후방 히스테리시스, 탑승 교체·텔레포트·월드 전환은 이전 샘플/요청 무효화로 처리한다. 월드 정의가 늦게 연결될 때 기존 제공자가 회복하는지도 확인한다. Project J의 지역 예측·준비 이동을 사용하는 월드에서 WorldState→Definition 연결이 하나로 해석되는지 확인한다. 이 기능을 쓰지 않는 non-WP 실내는 해당 연결이 없어도 정상이다. 잘못된 설정은 제작 위치와 함께 진단한다.

| 용도 | 준비가 늦을 때의 정책 | 안전성과 복귀 확인 |
|---|---|---|
| 일반 주행·비행 중 먼 장식 | 기존 프록시/낮은 밉을 유지하고 선택 장식의 품질을 늦게 올린다 | 지면·이동 시뮬레이션은 계속한다. 급격한 재승격은 프레임과 메모리 여유를 보고 나눠 적용한다. |
| 다리·절벽·착륙처럼 발을 디딜 곳 | 우선 충돌을 담은 셀 배치·선행시간·권위 충돌의 가용성을 고친다. 정상 경로 목표는 미준비 진입 0건 | 의도적으로 늦춘 조건에서 충돌 미준비가 재현되면 마지막 유효 위치에서 진입을 제한하는 Mover/서버 합의 경로를 그 구간에 설계한다. 클라이언트 보고만으로 통과 승인하거나 일반 지상 이동 전체에 감속을 켜지 않는다. 기존 비행 옵션은 기본 꺼짐을 유지한다. |

## 5. 전투 경고와 VFX

**공격 정의에는 ‘무엇을 읽을 수 있어야 하는가’를 둔다.** 기존 공격 DA에 경고 요구를 버전 호환 가능한 선택 필드로 둔다. 요구의 값은 경고 불필요, 시전자 주의, 방향·범위·시간을 읽어야 하는 위험으로 구분한다. 마지막 두 유형에는 의미 태그와 해당 공격 구간을 연결한다. 신규/변경한 배포 공격은 의도를 명시한다. 기존 직렬화 자산의 미지정 값은 기존 경고 동작을 보존하고 검토 대상으로 집계한다. 미지정을 일괄 ‘경고 불필요’로 승격하지 않는다. 일반 공격 모두에 바닥 원을 만드는 방식도 피한다.

**생산자는 한 곳이다.** 몽타주 주도 공격은 현재 Notify의 서버 시작/종료와 공격 인스턴스를 재사용한다. 제작 검사는 실행되는 몽타주 섹션·구간·재생 속도와 실제 타격 창에서 역으로 경고 태그, 선행 시간, 전용 서버 실행, 필터링, 중복/누락을 검사한다. 기존 B01 제작 스크립트는 첫 타격을 기준으로 경고를 배치한다. 그 스크립트의 0.35초를 전 스킬 규격으로 삼지 않는다. 몽타주가 없는 공격·지속 장판·투사체는 실제 권위 능력/위험 영역의 시작·갱신·종료를 사용한다. 실행 주체가 스스로 취소할 수 있어야 한다. 같은 경고를 Notify와 능력이 각각 시작하는 조합은 제작 오류다. [현재 Notify 검사](../../../Source/Project_JCharacterEditor/Private/Validation/Project_JCombatWarningAssetValidator.cpp) · [B01 경고 제작 경로](../../../Scripts/Editor/Bind-MMOTestBossCombat.py)

**검사 시작점은 실제 스킬 선택 경로다.** NPC 공격은 부여된 Ability Spec의 SourceObject가 공격 정의이면 이를 먼저 쓰고, 그 외에는 능력 기본 정의를 쓴다. 같은 능력을 쓰는 두 NPC가 다른 공격을 실행할 수 있다. 플레이어 콤보 노드·직업 추가 공격·NPC 활성화 오버라이드에서 선택되는 정의까지 검사를 연결한다. BP/능력에서 직접 호출 가능한 투사체 경로는 공격 DA를 인자로 받지 않는다. 이런 스킬의 필수 경고 요구는 실제 소유 능력이나 위험 영역에서 읽고, 기존 규칙을 재사용한다. 공격 DA를 가짜로 한 벌 더 만들 필요가 없다. 검사 사례는 정상 기본 정의에 잘못된 오버라이드를 씌운 경우, DA를 거치지 않는 정상 스킬, 경고가 필요하지만 생산자가 없는 스킬을 포함한다. [NPC 선택 순서](../../../Source/Project_JCharacter/Private/Combat/Project_JGameplayAbility_NPCAttack.cpp) · [투사체 진입점](../../../Source/Project_JCharacter/Public/Combat/Project_JProjectileManagerSubsystem.h)

**스킬 자원과 시각 효과는 포화 시 동작이 다르다.** 현재 권위 투사체 풀은 최대 2,048개이며 생성 실패는 ID 0으로 반환한다. 이 경로를 채택한 능력은 실패를 실제 시전자에게 일관된 결과로 돌려줘야 한다. 비용·쿨다운 확정 전에 생성 가능성을 확인하더라도 실제 생성 결과까지 확인한다. 이미 비용을 확정한 스킬은 그 스킬의 기존 취소/소모 규칙에 따라 정산한다. 재시도로 비용 차감·피해가 중복되거나 생성 실패 후 경고만 남으면 실패다. 시전자 사망·무기 교체 뒤에도 남는 장판/투사체는 위험 자체가 수명을 소유하고 시전자 표식과 독립적으로 끝난다. 이 수명은 해당 스킬의 제작 규칙으로 선언한다.

**시전자 주의와 공간 경고의 표현 계약은 다르다.** 기존 고정 표시는 시전자 주의에 재사용한다. 방향/범위가 필요한 공격은 서버가 결정한 위험 형상 또는 전조 범위, 고정/추적 기준 공간, 방향, 서버 기준 시작·위험 시각·종료 정보로 저비용 표시를 그린다. 전조 범위와 실제 무기 스윕이 다른 공격은 제작자가 의미와 허용 여백을 선언한다. 스킨에 타격 반경을 다시 입력하지 않는다. 동적 추적은 목표 고정 시점과 최종 방향을 정의한다. 필요한 값은 기존 공격 실행과 회복 상태에서 유도하고, 여러 동시 경고를 태그 하나로 구별할 수 없을 때만 기존 `AttackInstance/EventOrder`에 구간 식별자를 더한다. 관찰자는 월드/소유자·공격 인스턴스·구간·순서로 시작/종료를 대응한다. 늦게 relevant가 된 관찰자는 진행 중 구간의 남은 시간만 표시한다. 이미 끝난 공격의 비동기 로드나 패킷은 폐기한다.

필수 경고는 선택적 Niagara 에셋 로딩·풀·LOD·오디오 음량에 의존하지 않는 기본 표식을 가진다. 바닥 기울기·계단·벽 너머·색각·겹치는 공격에서도 방향과 시간 정보를 읽을 수 있게 윤곽·패턴을 포함한다. 관찰 대상은 실제로 영향을 받을 수 있고 게임 규칙상 볼 수 있는 연결이다. 시전자 Actor가 거리/군중 필터에서 제외된 경우에도 피해 대상에게 전조가 전달되는지 먼저 시험한다. 실패 시 기존 연결별 관련성에 제한 시간 동안 필요한 의존 관계를 추가한다. 은신자의 정체나 숨겨진 위치가 노출되면, 공개 가능한 위험 영역만 대상 연결로 전하는 기존 전투 경로를 사용한다. 짧은 경고가 한 번의 복제 갱신 사이에 시작·종료될 수 있으므로 **상태 복구만으로 최소 선행 시간을 보장한다고 가정하지 않는다**. 실제 손실·지연 조건에서 관측 가능한 선행 시간이 부족하면 송신 시점/우선순위 또는 공격 제작 시간을 수정한다. 필수 정의가 무효인 공격은 출하 전 오류이고, 서버가 실행 시 무효를 발견하면 해당 공격을 커밋하기 전에 기존 실패/취소 경로로 종료한다. 클라이언트별 렌더 ACK를 피해 판정 조건으로 두지 않는다. 현재 자신·보스·같은 파티/길드 등은 면제될 수 있고 기본 비면제 K는 60이다. **K가 제한하는 단위는 연결별 비면제 후보 액터다.** 40인 기록만으로 당시 포화 여부는 알 수 없다. 같은 장면에 NPC가 늘거나 Governor가 유효 K를 줄이면 40인 이하에서도 포화될 수 있다. 거리 조건을 통과한 비면제 후보, 면제 수, 실제 유효 K, 허용·제외 수를 비교한다. 기본 K에 충분한 일반 NPC를 배치한 표본과 적은 인원으로 K를 낮춘 대조군을 구분하고, 같은 길드가 모인 경우와 서로 무관한 경우에 허용/제외 수·송신량·목표 교체와 경고 도달을 비교한다. 변경한 K는 시험 결과에 명시한다. 길드 면제가 실제 병목이면 파티·길드 UI가 요구하는 요약 정보와 원거리 캐릭터의 전체 복제 필요성을 분리한다. 파티·대상·전투 공개 범위를 조용히 변경하지 않도록 관련 게임플레이 사례를 먼저 고정한다. 서버 Governor는 기존 히스테리시스로 선택 부하를 낮추고, 더 이상 여유가 없으면 기존 채널 입장 대기·분산 경로를 사용한다. 한 장소의 공격을 다른 인스턴스에 분산해 하나의 교전을 분할하는 결정은 파티·보스 상태·보상 소유권까지 달라지므로 별도 게임 설계 대상이다.

**인원이 흩어지는 경우도 별도 부하다.** 현재 필터는 추적 Actor를 프레임당 모은 뒤 연결별로 후보를 순회한다. K를 줄이면 전송 대상은 줄어도 후보를 순회하는 비용은 남을 수 있다. 같은 인원으로 한 보스 주변 밀집과 서로 먼 지역 분산을 비교하고, 후보 수집·연결별 선정 시간, 송신량, 서버 활성 셀·RAM/충돌을 함께 본다. 후보 탐색이 실제 병목일 때만 기존 공간 후보 조회와의 결합을 평가한다. 소유자·파티·보스처럼 거리 바깥에서도 필요할 수 있는 대상과 despawn/재등록 때 결과가 기존 정책과 일치해야 한다. ## 7. 한 대에서 품질을 판정하는 방법

**기능 합격선은 지금 정할 수 있다.** 원경 필수 대상으로 표시한 표본에서 원본·프록시가 모두 사라지는 관찰 프레임 0건, 정상 주행에서 지형 관통·잘못된 도착 0건, 필요한 경고 누락·종료 후 잔존 0건, 권위 결과 중복·타인 보상·이탈 뒤 재적용 0건을 요구한다. 가림·안개·게임 규칙에 의한 숨김은 관찰 조건에 기록한다. 거리 전환 때 형태가 튀는 문제는 소실 0건으로 판정할 수 없으므로 고정 경로 영상으로 별도 판단한다. 누락 검사는 정상·실수·명시적 예외 세 경우를 함께 통과해야 한다.

### 여러 시스템이 한 프레임에 몰릴 때의 인수 사례

각 사례는 표에 적은 구현 단위가 해당 경로를 변경할 때 수행한다. 에셋 한 건을 고칠 때마다 모든 시나리오를 실행할 필요는 없다.

| 상황과 담당 단위 | 관찰과 합격 기준 |
|---|---|
| **구역 전환과 전투가 겹침** (1·4·5) | 파티 일부는 포털로, 나머지는 지상으로 같은 정착지에 접근한 직후 첫 스킬을 쓴다. 도착 permit은 권위 요청 개수만 제어하므로 해제 시각·WP I/O 완료·GT 등록·장식 적용을 별도로 본다. 기존 시각 로더의 진행 중 로드/거절/시간 초과와 연출 예산의 대기·적용·폐기, 가장 늦은 필수 경고와 지면 준비를 대응한다. 오래된 일회성 장식은 뒤늦게 몰아서 재생하지 않고, 지속 효과는 최신 수명만 복구한다. 기존 예산으로 충족되면 새로운 스케줄러를 추가하지 않는다. |
| **전투 중 사용자 설정 변경** (3·5) | 같은 공격에서 원격 선택 효과 끄기·불투명도 최소·프리셋 복원과 오디오 음소거 또는 UI/경고 음성 그룹 포화를 각각 시험한다. 현재 그룹 상한은 8이며 전체 음성 한도에도 영향을 받는다. 실제 HUD 경로로 적용된 CVar와 화면을 함께 기록한다. 장식만 바뀌고 필수 표식의 시작·읽을 수 있는 시간·종료, 피해·보상은 일치해야 한다. |
| **전조가 누구에게 언제 보였는지 측정** (2·3·5) | 시작 전 이미 대상인 관찰자, 도중에 범위에 들어온 관찰자, 게임 규칙상 비공개인 관찰자를 따로 둔다. 첫 그룹은 화면에서 읽을 수 있게 된 첫 프레임부터 권위 타격 창까지의 여유를, 신규 진입자는 진입 후 남은 경고의 표시·만료를, 비공개 관찰자는 정보 노출 0건을 판정한다. 이미 발생한 위험에 스스로 진입한 경우의 유예 여부는 스킬 규칙이 정한다. 캡처나 시계 정렬이 빠진 구간은 미측정으로 센다. 네트워크 수신 이벤트만으로 픽셀 가시성을 판정하지 않는다. |
| **패치로 오래된 배치 ID가 남음** (1·4, 영속 배치 변경 시) | 채집·문 등 상태를 저장하는 대상만 확인한다. 이전 버전에서 상태를 만든 뒤 배치를 이동·복제·삭제한 새 구역으로 재입장한다. 이동은 기존 ID를 유지하고, 복제본/인스턴스는 상태 공유 의도에 맞춰 식별 범위를 구분하며, 삭제된 ID가 다른 배치로 재사용돼 상태가 옮겨가면 실패다. ID 교체가 불가피하면 이전→새 ID 매핑과 저장 버전 호환을 명시한다. |

시각 로더는 로드 시작 수와 완료 적용 수, 연출 예산은 원격 장비/효과의 프레임당 적용 시도를 제한한다. 두 한도의 수치를 합산해 GPU나 WP 처리 시간을 추정하지 않는다. 공통 원인 후보는 기존 trace와 카운터를 먼저 같은 시간축에서 확인한다. **수치 판정.** 초기 개발용 비교선으로 60fps의 프레임 간격 16.67ms와 30Hz의 틱 간격 33.33ms를 표시한다. 출시 합격선은 목표 기기·해상도·프리셋·장면이 정해져야 확정한다. 프레임의 p50/p95/p99·최대·초과 횟수와 연속 초과 길이, 서버의 틱 처리/간격, 프로세스별 메모리와 VRAM·I/O를 같은 구간에서 집계한다. 표본 수·준비 구간·빌드·하드웨어·RHI·실제 표시 방식과 소리 상태를 기록한다. 720p 오프스크린 결과를 실제 모니터 present 지연으로 해석하지 않는다. 비교는 같은 카메라/콘텐츠/인원에서 한 변수를 바꾸고 A→B→A 또는 반복 측정한다. 개선폭이 동일 구성 재실행 편차 안이면 유보한다. 로컬 프리셋 하향은 최소 사양 기기 실측을 대신할 수 없다.

**40인 지연을 분해하는 첫 작업.** 기존 CSV의 요청 발행→클라이언트 체력 기준 관측 p95 916.300ms와 권위 확정→관측 p95 318.047ms는 시작점이 다르다. 첫 값은 서버 시험 발행에서 시작하며 `round_trip_ms` 열도 실제 네트워크 RTT가 아니다. 공격/연결 키로 입력 생성(실제 계측이 있을 때) → 서버 시험 발행 또는 실제 입력 수신 → 공격 창·권위 피해 → Iris 대상 선정·패킷 송신 → 클라이언트 수신/GT 적용 → HP 관측/화면 표시를 연결한다. 체력 임계치 폴링 간격·배치 전송·누적 피해 혼동을 확인한다. 각 **매칭 행**의 차이로 구간 분포를 계산한다. 서로 다른 p95를 빼지 않는다. 누락/중복 행, 시계 기준, 추적 유무와 비용을 기록한다. 처음부터 tick rate·K·복제 우선순위를 변경하지 않는다. **예상 제작 비용과 변경 범위.** 1~2는 기존 데이터 읽기·작은 양성/음성 표본이 중심이다. 3은 공격 자산과 실제 연결, 4는 대표 구역 HLOD 빌드·Cook·주행 촬영, 5는 반복 실행과 1대 자원 경합이 비용의 중심이다. 전체 월드 재생성, 기존 모든 공격 재저장, 모든 SKU의 패키징을 선행조건으로 두지 않는다. 대표 범위에서 깨지는 의존성이 확인되면 영향받는 콘텐츠만 확대한다. 새 포맷이 배포되기 전에는 이전 필드 읽기와 옛 콘텐츠 결과를 유지한다. 기존 writer와 새 writer를 동시에 켜고 덮어쓰는 방식으로 이행하지 않는다.

**남겨야 하는 미결정.** 출시 최소/권장 기기, 해상도·FPS, 플레이 가능한 최고 속도, 어떤 랜드마크와 어떤 공격에 어느 정도의 가시 거리·최소 반응 시간을 보장할지는 콘텐츠/제품 목표로 결정한다. 첫 구현은 이 값 없이도 검사 누락과 수명 오류를 바로잡을 수 있다. 대규모 SKU별 검증·실회선 지연·100~200인 단일 교전은 장비와 실제 목표가 생긴 뒤 연다. 1대 40인은 현재 검증 범위다.

**재검토할 대안.** 현재 안은 UE의 원경·복제 기능과 기존 프로젝트 소유자를 보강한다. 엔진 기본 설정만으로는 대상 자체가 누락된 경우와 피해 경고 의미를 검출하기 어렵다. 반대로 모든 도메인을 통제하는 전역 최적화 관리자나 새 스트리머는 권위와 종료 수명을 중복시킨다. FastGeo, 신규 GPU 배치, DirectStorage, 커스텀 임포스터, 대규모 Mass/VAT 전환은 각각 컴포넌트 등록, 배치 제작, I/O, 원경 픽셀, 비상호작용 군중이 실제 병목일 때 별도 표본으로 다시 검토한다. 적용 엔진과 콘텐츠에서 품질·프레임·메모리·빌드 비용을 함께 개선하는 대안을 선택할 수 있다.

제작 기법의 비교 근거로 Fortnite의 수관 보존, Horizon의 절차적 배치와 아티스트 제어, Guild Wars 2의 월드 보스/맵 인스턴스 운용을 참고했다. 이 사례에서 채택한 것은 장면과 책임을 나누는 방식이며, 각 게임의 인원·거리 숫자를 Project J에 이식하지 않는다. 전체 공식·제작사·독립 측정·오픈소스 자료 목록은 기존 인계 7절을 유지한다.
