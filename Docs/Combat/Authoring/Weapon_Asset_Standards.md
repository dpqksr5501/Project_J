# 무기 메시·텍스처 제작 규격

확정일: 2026-10-24. 앞으로 추가하는 일반 무기는 **BaseColor·Normal 최대 2K, ORM 최대 1K**를 기본으로 제작·수입한다. 여기서 2K/1K는 무기에 사용하는 텍스처 해상도이며, 메시의 삼각형 수·실제 크기·LOD 규격은 별도로 관리한다.

## 기본 해상도와 재질 설정

2K는 2048×2048, 1K는 1024×1024다. 아래 해상도는 게임용 빌드의 기본 상한이며, 실제로 상주·샘플링되는 mip는 화면 크기·품질 설정·스트리밍 예산에 따라 달라진다.

| 텍스처 | 제작 원본 기본값 | 게임용 최대 크기 | sRGB | 압축 | TextureGroup |
| --- | --- | --- | --- | --- | --- |
| BaseColor | 2K | 2K | 켬 | Default | Weapon |
| Normal | 2K | 2K | 끔 | Normalmap | WeaponNormalMap |
| ORM | 2K 보존 | 1K | 끔 | Masks | WeaponSpecular |

- ORM 채널은 **R=Ambient Occlusion, G=Roughness, B=Metallic**이다. `WeaponSpecular`는 ORM에 사용하는 품질 그룹 이름이며 채널 연결은 위 계약을 따른다.
- Unreal에는 DirectX Normal을 사용한다. DirectX로 제작된 맵은 green 채널을 추가 반전하지 않는다. 다른 방식의 원본은 수입 시 방향을 확인한다.
- 기본 무기는 재질 슬롯 1개를 우선한다. 추가 슬롯·투명 재질·VFX는 실제 표현 필요와 렌더 비용을 확인해 결정한다.
- 같은 무기 외형은 메시·재질·텍스처 에셋을 공유한다. 로컬/원격 플레이어별로 동일 텍스처 사본을 만들지 않는다.

## 원본 보존과 Unreal 적용

1. 편집 원본과 FBX·베이크 텍스처를 보존하고, 프로젝트 안의 수입 원본 경로와 원본 식별 근거를 남긴다. 현재 대검의 예시는 [Basic 원본·수입 기준](../../../SourceArt/Weapons/Greatsword/Basic/README.md)을 따른다.
2. `Maximum Texture Size`는 BaseColor/Normal **2048**, ORM **1024**를 기본값으로 설정한다. 원본 ORM 2K를 보존하고 이 상한으로 게임용 크기를 조정한다. 재수입 뒤에도 상한·압축·채널 설정을 다시 확인한다.
3. `Mip Gen Settings=FromTextureGroup`, `Never Stream=false`를 기본으로 사용한다. 로컬 무기라는 이유만으로 최고 해상도 mip를 강제 상주시키지 않는다.
4. 플랫폼·품질별 하향 조정은 기존 Weapon 계열 TextureGroup과 DeviceProfile/품질 설정을 활용한다. 대상 하드웨어 측정 없이 전역 스트리밍 풀을 늘리는 방식으로 무기별 비용을 처리하지 않는다.
5. 원본 크기와 실제 빌드 크기를 구분해 확인한다. 2K 원본이 있다는 사실만으로 게임에서 항상 2K를 사용한다고 판정하지 않는다.

기존 무기 에셋을 이 문서 작성만으로 일괄 축소·재수입하지 않는다. 신규 제작과 개별 수정 때 적용하고, 이미 역할이 있는 원본·테스트 자산은 보존한다.

## 크기별 조정과 예외

| 대상 | 적용 기준 |
| --- | --- |
| 일반 검·대검·도끼·창 등 | BaseColor/Normal 2K, ORM 1K에서 시작한다. 무기 종류 이름보다 실제 카메라의 표시 크기로 판단한다. |
| 작은 단검·보조 무기·작게 표시되는 장비 | BaseColor/Normal 1K부터 비교한다. ORM은 1K 이하에서 필요한 디테일을 확인한다. |
| 근접 감상·연출 등에서 화면을 크게 차지하는 특별한 무기 | 기본값과 실제 화면을 비교한 뒤 필요한 맵만 상향한다. 상향한 해상도·사용 장면·외형 차이와 비용 근거를 해당 에셋 제작 기록에 남긴다. |

희귀도나 로컬 소유 여부만으로 해상도를 올리지 않는다. 4K를 일괄 기본값으로 삼거나 낮은 해상도 원본을 단순 확대해 기준에 맞추지 않는다. 여러 무기가 서로 다른 텍스처를 사용할 때의 메모리·스트리밍 부담도 별도로 확인한다.

## 메시 LOD와 장착 구조

- 지오메트리 LOD 제작·예외는 [메시 LOD 제작 기준](../../Animation/Authoring/Mesh_LOD_Authoring.md)을 따른다. 현재 기본 체인은 LOD0–2이며, 새 무기의 실루엣과 전환 품질은 해당 에셋에서 확인한다. 기본 대검의 삼각형 수를 모든 무기의 공통 상한으로 고정하지 않는다.
- 공용 `Project_JWeaponPresentationActor`를 사용하는 정적 무기는 로컬·원격 모두 화면 크기 기반 LOD를 사용한다. 명시적인 제작용 forced LOD는 해당 용도와 소유권을 유지한다.
- 메시 피벗·단위·손잡이/접지 소켓은 해당 무기의 장착·모션 계약에 맞춘다. 손 접촉 제작은 [무기 파지와 손 접촉](../../Animation/Authoring/Weapon_Hand_Contact_System.md), 실제 대검 장비 연결은 [대검 제작 가이드](GreatswordCombatAuthoringGuide.md)를 따른다.

## 신규 무기 검수

- 텍스처 실제 빌드 크기·압축·sRGB·Normal 방향·ORM 채널·mipmap·스트리밍을 확인한다.
- 실제 플레이 카메라의 근접·기본 거리·원거리에서 디테일과 LOD 실루엣/전환, 금속 반응을 비교한다.
- 장착·발도·납도·공격 중 손/의상 접촉과 재장착 후 연결을 확인한다. 기존 소켓·전투 권위·장비 수명 관리를 재사용한다.
- 군중에서는 같은 무기를 공유하는 조건과 여러 종류의 무기를 사용하는 조건을 구분한다. GPU 시간·프레임 시간·메모리/스트리밍을 각각 확인하며 개선율을 서로 바꾸어 표현하지 않는다.

기본 대검의 [200명 측정](../../Performance/Reports/ProjectJ_Weapon200_2026-10-24.md)은 이 기본값을 적용한 동일 무기 공유 조건의 근거다. 서로 다른 무기 200종의 텍스처 메모리, 모든 카메라·플랫폼·무기 스킨의 성능 승인을 뜻하지 않는다.
