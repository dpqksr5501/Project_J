# 로컬 분석·보관 자료의 중앙 관리

이 문서는 앞으로 생성하는 최적화·측정·빌드/실행 진단·제작 복구 등 로컬 보관 자료의 작업 기준이다. 날짜별 정리 결과는 [2026-11-04 기록](Storage_Cleanup_2026-11-04.md)에 둔다. 이 규칙 자체가 자동 정리 작업이나 원격 백업을 실행하지는 않는다.

## 단일 진입점과 공유 범위

- 실제 자료: `Saved/StorageCleanup_20261104/ArchiveStore`. 기존 PerformanceTraces·Measurements·Logs·DebugSymbols·AssetAndRecoveryBackups·OtherArchives·PackagePayloads·ShaderPayloads 분류를 재사용한다.
- 관리 기록: 부모 `Saved/StorageCleanup_20261104`의 ArchiveLocations.json, Compressed.jsonl, Deduplicated.jsonl 및 중앙 INDEX.csv/README. 새 날짜별 보관소나 별도 전역 캐시를 만들지 않는다.
- 공유 복원 도구: `Scripts/Maintenance/Restore-LocalArchive.ps1`. 소스/설정/제작용 에셋과 공유할 작은 요약·수치·출처는 Git에서 관리하고, 로컬 원자료·임시 압축·실행물은 Saved에 남긴다. 공유가 필요한 대형 자료는 기존 Archives/Validation 지침과 명시한 공개 범위를 따른다.

Saved는 Git에서 제외된다. clone이나 이번 commit/push만으로 로컬 원자료·명세가 다른 PC에 전송되지는 않는다. 로컬 아카이브를 외부 보관할 때는 실제 파일뿐 아니라 해시/위치/복원 명세도 함께 보관하고, 다른 경로로 복원할 때 경로를 대조한다.

## 새 자료 등록 순서

1. 실제 생성자·완료/취소 상태·사용 프로세스를 확인한다. 실행 중인 출력, 제작/저장 원본, 미확정 파일을 임시 파일로 취급하지 않는다.
2. 기존 중앙 목록의 SHA-256·크기·원래 경로·용도를 먼저 대조한다. 이미 보존한 내용은 기존 보존본을 재사용하고 필요한 참조만 추가한다. 같은 데이터의 새 압축본을 무조건 추가하지 않는다.
3. 새 압축이 필요하면 Saved의 명확한 임시 파일 한 개에서 완성한다. 압축 전 원본 경로/크기/SHA와 완성 압축본의 크기/SHA를 기록하고, 전체 해제 스트림의 원본 SHA를 확인한다. 완성/검증 전에 원본을 제거하지 않는다. 이미 압축한 파일을 재압축하거나 필요한 파일 전체를 한 ZIP으로 다시 묶지 않는다.
4. 기존 명세 형식에 맞춰 원자료와 중앙 보존본의 관계를 기록한다. gzip은 Compressed.jsonl의 original/archive·원본/압축 SHA/크기를, 동일 바이트 보존은 Deduplicated.jsonl의 original/preserved·SHA/크기를 사용한다. 보존본 경로 변경은 ArchiveLocations.json의 기존 oldPath→centralPath를 연결한다. 원래 경로가 중복 매핑되지 않는지 확인한다.
5. 같은 볼륨 안에서 이름 충돌 없는 중앙 위치로 이동한다. 이동 전에 매핑을 게시하고, 이동 중에는 기존 위치/새 위치 중 실제 존재하는 검증된 파일로 복원할 수 있게 한다. 원래 경로를 사용하는 소비자가 있으면 이주하거나 검증한 NTFS 호환 하드링크를 사용한다. 하드링크는 독립 백업이 아니며 수정 내용이 공유되므로 보관 자료는 불변으로 취급한다. 재귀적으로 junction을 따라 이동/삭제하지 않는다.
6. 이동 후 SHA와 실제 위치·기존 참조·복원을 확인하고 INDEX.csv와 필요한 README 집계만 갱신한다. 원래 보고서의 당시 hash/path나 실패 결과를 새 결과로 덮어쓰지 않는다. 원자료를 제거하는 단계는 보존본 검증 뒤에만 수행한다. 완료 기록은 기존 명세와 결과 문서에 짧게 남긴다.

중앙 파일을 임의로 옮기거나 ArchiveStore만 복사하고 명세를 버리지 않는다. 호환 링크는 폴더 논리 크기에 중복 집계될 수 있으므로 실제 볼륨 여유 공간과 파일 합계를 구분한다. 기존 호환 별칭을 이름만 보고 중복 사본으로 삭제하지 않는다. 중단된 이전 작업은 기존 파일·명세·프로세스 상태를 확인한 뒤 같은 자료를 재압축하지 않고 이어간다.

## 복원과 정리

프로젝트 루트에서 다음을 사용한다. 기존 로컬 Restore-File.ps1 명령도 공유 도구를 호출하는 호환 진입점으로 유지한다.

```powershell
& './Scripts/Maintenance/Restore-LocalArchive.ps1' -OriginalPath '명세에 기록한 원래 파일의 절대 경로'
```

도구는 중앙 위치·보존본 SHA·복원 결과 SHA를 확인하고 기존 원래 파일을 덮어쓰지 않는다. 새 보관 자료를 등록한 뒤 실제 복원까지 필요한 범위에서 확인한다. 전체 압축본을 다시 풀어 저장 공간을 늘리는 검증은 피하고, 해제 스트림 검증과 필요한 대표 복원으로 구분한다.

자료 폐기는 현재 사용자 요청과 보존 목적을 확인한 별도 판단이다. 보관 위치 중앙화가 원본/이력 삭제나 현재 빌드 캐시 초기화를 승인하지 않는다. 이미 폐기한 과거 Cook/package 생성물은 새 실행에서 재생성하며, 그 준비 완료 marker를 정상 입력으로 남기지 않는다. 공간 정리/압축은 향후 자원 증가의 원인 수정과 구분해 보고한다.
