# 보조 움직임 제작과 검증

머리카락, 의상, 액세서리의 움직임은 실제로 필요한 표현과 접촉에 맞춰 제작한다. 캐릭터의 몸체 포즈와 장비·소켓 연결을 먼저 검증하고, 파츠별로 누가 최종 본 또는 천 정점을 계산하는지 확인한다.

| 파츠 요구 | 사용할 경로 | 확인할 항목 |
| --- | --- | --- |
| 짧은 장식이나 형태가 거의 유지되는 천 | 기존 스킨·Leader Pose 또는 제작한 본 애니메이션 | 기본 동작, 방향 전환과 메시 LOD에서 실루엣 유지 |
| 머리카락, 끈, 일부 치마처럼 몇 개 본이 움직이는 파츠 | 기존 AnimGraph의 본 기반 후처리. 접촉이 필요하면 `RigidBody`와 전용 Physics Asset | 시뮬레이션 본, 앵커, 관절, 충돌 조합, 소켓과 핵심 포즈 보존 |
| 망토처럼 연속적인 천 표면 변형이 필요한 파츠 | 기존 Chaos Cloth와 해당 표면에 필요한 몸체 충돌 형상 | 고정 영역과 이동 범위, Cloth 섹션·LOD 바인딩, 로컬/원격 표현 |

## 충돌과 본 제작

1. 현재 BP에서 직접 재생 또는 리타깃 그래프, Leader Pose, 숨은 포즈 소스, 독립 Cloth를 확인한다. 같은 장식 본을 두 그래프나 컴포넌트가 한 캐릭터에서 동시에 쓰는지 확인한다. 게임플레이·IK·무기·필수 VFX 소켓의 본은 보조 움직임이 바꾸지 않게 한다.
2. 본 기반 물리는 시뮬레이션 본과 그 관절의 모든 끝점을 먼저 기록한다. 원본 Physics Asset에서 동적 바디와 충돌할 수 있는 조합을 확인한다. 기존 연결은 `bUseDefaultAsSimulated`, 월드 충돌·외부 Cloth 충돌, 관절 및 Collision Disable Table을 함께 확인한다. 두 끝점이 모두 키네마틱인 관절을 건너뛰는 기준은 이 프로젝트의 UE 5.8 `RigidBody` 경로에서 확인했다. 다른 물리 소비자가 같은 PA를 쓰면 각 소비 경로를 검수한다.
3. Chaos Cloth는 실제 Cloth 섹션이 쓰는 충돌 PA를 연다. 같은 몸체 형상이라도 망토와 몸통·장비가 접촉하는 위치가 다를 수 있다. 각 형상의 접촉 목적을 기록하고, 중복 또는 불필요 형상은 테스트 사본에서만 줄인다. 고정/이동 가중치, 물리 메시 정점, 스켈레톤·재질·섹션 바인딩은 비교 조건에 포함한다.
4. 먼저 에셋의 실제 작업량을 줄이고 기존 시각 예산은 유지한다. 원거리 갱신이나 정지·복귀까지 조정해야 하는 경우, 현재 품질 정책에 파츠별로 연결한다. 로컬·근거리·필수 접촉을 보호하고 거리 경계를 왕복할 때 재진입, 블렌드, 몸 관통을 확인한다. 캐릭터 수나 파츠 이름을 기준으로 전역 예외를 추가할 필요는 없다.

## 검증과 채택

- 사본을 정지·회전·달리기·공격·착지에서 원본과 같은 입력으로 비교한다. 파츠에 해당하는 경우 장착·해제, 체형·스케일, 컷이나 이동 전환, 각 실제 표시 LOD를 추가한다. 얼굴·목·등·어깨와 같이 접촉하는 표면을 근접에서 보고, 같은 결과 포즈를 쓰는지 확인한다.
- 프로덕션에서는 기존 BP가 참조하는 경로로 다시 연다. Data Validation, 실제 Cloth 섹션 바인딩, 마지막 포즈의 본·소켓, 장식의 동작을 확인한다. 공유 Physics Asset은 소유 범위를 확인하고, 충돌 역할이 다른 파츠에는 해당 파츠의 PA를 사용한다.
- 가까이서 보여야 할 원본을 유지하면서 원격 천 연산만 줄일 때는 해당 모듈 파츠의 `RemotePresentationMesh`에 검증한 경량 메시를 연결한다. 원본과 같은 스켈레톤·재질·렌더 LOD를 쓰고 몸체 충돌, 섹션 바인딩과 고정 영역을 확인한다. 캐릭터 소유권 변경 시 로컬은 원본을 사용하며, 원격 메시를 읽는 동안에도 원본이 보인다. 스펠블레이드 제작 흐름은 `Scripts/Editor/Build-SpellbladeClothPhysicsProxy.py`와 `Publish-SpellbladeRemoteCloth.py`에 있다.
- 부하 비교는 소규모에서 시작해 필요한 밀도로 올린다. 두 실행에 같은 장면, 카메라, 해상도, 스켈레탈 LOD, 품질 설정, 공격 입력과 CPU 추적 조건을 사용한다. 로컬/원격 보호 대상과 활성 파츠 수, Runner가 실제로 사용한 에셋을 기록한다. 원격 배치와 실접속은 해당 네트워크 테스트에서 별도로 검증한다.
- 전체 프레임, 게임 스레드의 Cloth 완료 대기, 머리카락/Cloth 작업 시간, 실제 샘플 수와 메모리 여유를 기록한다. 병렬 작업 시간을 더해 화면 프레임을 추정하지 않는다. 변동 폭이 큰 구간이나 승격 판단에 중요한 차이는 반복 비교한다.
- 선택형 `ProjectJ.ClothBudget.PauseOptInRemote`는 해당 의상 컴포넌트에서 `bAllowClothExecutionBudget`을 허용한 경우에만 적용된다. 허용 전에는 원격에서 기본 포즈로 블렌드될 때의 실루엣·몸 관통, 공격·회전·착지 중 시각 결과, 모드 해제 후 시뮬레이션 재개를 확인한다. 장식이 공격 방향이나 경고를 전달하면 계속 작동하도록 둔다.

스펠블레이드는 망토 Cloth를 유지하면서 몸체 캡슐 **16→10**, 머리카락 `RigidBody`는 시뮬레이션 본 4개와 머리 앵커를 유지하면서 캡슐 **49→5**로 정리했다. 치마는 기존 본 기반 후처리를 사용한다. 숫자는 해당 에셋에서 확인한 결과다. 메시 자체 Cloth를 사용하는 사례는 [Winger 제작](Winger_UE5_Export_2026-11-11.md#긴-뒤쪽-천의-chaos-cloth)에, 제작 승격과 실측은 [스펠블레이드 보조 움직임 검증](../../Performance/Reports/ProjectJ_Spellblade_Secondary_Motion_2026-11-24.md)에 기록했다.
