# Spellblade 전투 세트

다른 채팅에서 이어서 구현할 때는 [Spellblade 스킬 구현·개선 인계](Spellblade_Skill_Handoff.md)에서 원본 경로, 현재 입력과 몽타주, 미연결 후보를 먼저 확인한다.

Spellblade Longblade 장비는 `DA_CombatStyle_SpellbladeKit`를 사용한다. 기존 대검은 기존 스타일과 레이어를 사용한다. 에셋은 기존 Spellblade 경로 아래의 `CombatKit`에 보관한다.

| 에셋 | 검토 경로 |
| --- | --- |
| 공용 기준 시퀀스 30개 | `/Game/Anim_Assets/Spellblade/Animations/Sword/CombatKit/Sequences` |
| 실제 몸체용 시퀀스 | `/Game/Anim_Assets/Spellblade/Animations/Sword/CombatKit/Sequences/DirectBody` |
| 공격·이동·발도·납도 몽타주 | `/Game/Anim_Assets/Spellblade/Animations/Sword/Montage/CombatKit` |
| 상체 BS | `/Game/Animation_Logic/BSs/Spellblade/CombatKit/BS_Spellblade` |
| 이전 Greatsword BS | `/Game/Animation_Logic/BSs/Spellblade/BS_Greatsword_Legacy` |
| 전용 링크드 레이어 | `/Game/Animation_Logic/ABPs/Spellblade/ABP_Spellblade` |
| 공격 VFX 매핑과 공용 검 연출 프로필 | `/Game/DataAssetSets/Presentation/Spellblade/CombatKit` |
| 제작용 리타기터 | `RTG_SpellbladeLegacy_to_Manny_CombatKit`, `RTG_SpellbladeLegacy_to_DirectKit` |

[모션 출처 목록](Data/SpellbladeCombatKit/MotionProvenance.json)에 초기 변환 원본 파일명, SHA-256, 출력 에셋, 길이와 샘플 키 수를 기록했다. Longblade 상체 블렌드 스페이스는 `SK_Spellblade_Complete`용 준비 루프와 전후좌우 이동 루프를 사용한다. 하체는 공용 GASP 모션 매칭을 사용한다.

스크립트로 Blend Space의 샘플 배열을 교체할 때는 `RebuildBlendSpaceInterpolation`으로 보간 데이터를 재생성한 뒤 저장한다. Longblade는 기존 샘플 인덱스가 보간 데이터에 남아 고속 입력에서 범위를 벗어났다. 에디터 제작 도구에서 그리드·삼각형·선분 인덱스를 새 샘플 배열에 맞춰 검증한다.

| 입력 | Longblade 신규 연결 |
| --- | --- |
| 지상 좌클릭 | 일반 베기 `BasicCut01` → `BasicCut02` → `BasicCut03Ground` |
| 지상 우클릭 | `RightAttack` |
| 지상 좌·우클릭 동시 입력 | `ChordLunge` 진입. 기본 1·2타에서 분기 가능하며 R로 이어서 `ChargeRelease` |
| 전투 중 전력 질주 + 좌클릭 | `SprintAttack` |
| 지상 W + Shift + 우클릭 | `MovementDash`, 카메라 기준 정면 이동 대시 |
| Q / R / T | `QuickSkill` / `ChargeRelease` / `Finisher` |
| Q + 좌클릭 | Q의 `QuickSkill` 이후 `QuickFollow`. Q를 떼고 좌클릭해도 같은 연계 창을 사용 |
| 공중 좌클릭 / 우클릭 | `AirLight` / `AirHeavy` |

Longblade 커맨드 세트가 입력을 `Command.Spellblade.*` 태그로 변환한다. `GA_Spellblade`가 공격 입력을 받고, `GA_Spellblade_MovementDash`가 대시 커맨드를 받는다. 조합 키는 장착한 스타일의 커맨드에 따라 활성화하며, 연계 전용 조합은 현재 노드에 해당 전이가 있어야 일반 입력을 대신한다.

이동 대시 GA는 입력 이벤트에서 카메라 기준 전방 구간을 판정한다. 키보드에서는 W가 필요하며, 정지·좌우·대각선·후방 입력에는 기존 로코모션을 유지한다. 원격 서버는 Mover가 수신한 동일 입력 샘플의 이동 의도와 시야 방향으로 판정한다. GA가 승인과 몽타주 수명을 관리하고 Mover가 루트 모션의 이동량과 충돌을 처리한다. 첫 이동 스텝에 몸을 입력 시점의 카메라 정면으로 맞춘다. 몽타주의 전체 재생 시간은 0.05초 단축하고, 루트 이동이 끝나면 현재 이동 의도와 허용된 속도로 로코모션을 이어간다. Shift를 유지하면 대시 아래에서도 질주 의도를 보존하고 복귀는 이동 루프로 시작한다. 보행 스프링은 충돌을 반영한 복귀 속도로 다시 시작하며, 애니메이션의 회수 구간은 블렌드아웃까지 재생된다. 현재 이동 대시의 입력 태그는 `Command.Spellblade.ShortDash`이고, 콤보 그래프에 남은 `Attack.Spellblade.ShortDash`는 G 팔꿈치 공격의 에셋 식별자다.

전투 스타일이 부여하는 대시 GA의 클래스 기본값에서 `Forward Input Half Angle Degrees`와 `Preserve Sprint During Dash`를 설정한다. 첫 값은 허용하는 입력 범위이며 실제 돌진은 카메라 정면을 향한다. 두 번째 값은 캐릭터의 기존 질주 조건을 통과한 입력에 적용된다. 현재 Spellblade는 22.5°와 질주 유지 활성 상태를 상속한다. 무기나 전직이 독자적인 대시 설정을 필요로 하면 해당 스타일의 대시 GA 변형에서 값을 지정하고, 같은 입력을 사용하는 기존 GA 부여를 그 변형으로 교체한다. GA 인스턴스는 부여될 때 클래스 기본값을 가져오므로 에디터에서 값을 바꾼 뒤에는 새 PIE 세션에서 확인한다.

지상 전투 중 F는 Longblade 커맨드 세트가 상호작용 입력을 발차기로 해석한다. 발차기는 왼발 볼을 타격 기준으로 사용한다. E로 별도 4연격을 열고, 각 연계 창에서 좌클릭이나 E로 이어간다. 마지막 타와 전용 복귀는 같은 몽타주에 두 세그먼트로 작성했다. 복귀에는 별도 타격 창이 없다.

Z는 집중으로 마나를 초당 5, X는 재생으로 체력을 초당 4 회복한다. C는 가속으로 달리기·질주 속도를 15% 높인다. 효과는 각 시전의 자연 종료 뒤 6초간 지속된다. Z/X/C는 원본 속도의 단일 테이크를 사용하며 몽타주 길이는 각각 3.40초, 5.37초, 5.47초다. 같은 효과가 남아 있으면 해당 시전을 다시 시작할 수 없다.

G는 지상 오른팔꿈치 돌진으로 루트 모션 180cm를 사용한다. 우선 이동 입력 방향을 사용하고, 타격 뒤 좌클릭으로 기본 1타에 연결한다. V는 공중 내려베기다. 원본 상체 타격과 함께 첫 0.20초의 수직 하강을 캡슐에 적용한다. 원본 하강량은 약 102cm이며, 먼저 바닥에 닿으면 Mover가 착지를 처리한다.

지상 전투에서 Caps Lock을 누른 채 E로 Bash 4연격, Q로 Twin 2연격, V로 지면 강타를 시작한다. 후속 타는 Bash에서 E나 좌클릭, Twin에서 Q나 우클릭을 사용한다. 후속 E/Q에도 Caps를 계속 누를 수 있다. 기본 Q/E/V와 확장 입력은 같은 Enhanced Input 액션을 공유한다. 누를 때만 물리 키를 확인하고 해제는 선택된 입력과 짝을 맞춘다. Windows의 대문자 전환 상태와 Alt의 커서 전환은 각각 기존 동작을 따른다.

확장 지상 공격은 `DefaultSlot`에서 재생한다. Mover가 리타깃 시퀀스의 원본 XY 궤적을 지상 루트 모션으로 적용하고, 골반 높이·몸의 회전은 시각 포즈로 유지한다. 중간 타에 후속 입력이 없으면 같은 몽타주가 원본 복귀를 재생한다. 복귀 전 자세 유지 구간을 짧게 압축하고 발을 옮기는 부분은 상대적으로 천천히 재생한다. 피격·사망·탑승·공중 상태 제한과 검 판정은 기존 근접 전투 경로를 사용한다.

정지 샘플 `AS_LongbladeStance_Ready`의 원본은 `pdw_01_01_stand_idle_00.fbx`다. 양손이 가슴 높이에서 검을 드는 전투 준비 루프를 사용한다. `-ApplyStance -FbxRoot=<원본 애니메이션 FBX 폴더>`는 원본 오른손의 손바닥 좌표계에서 검의 방향을 옮기고, 생산 무기의 실제 오른손 부착과 왼손 그립을 사용해 양팔을 함께 굽힌다. 팔 길이와 루프의 움직임을 유지한다. 속도 500 샘플은 `move_run_f/b/l/r_00`의 직접 리타깃을 사용하므로 속도와 방향이 변할 때 실제 이동 포즈를 합성한다. 이동 포즈의 칼끝은 실제 무기 길이와 GASP에서 측정한 손 높이를 기준으로 여유를 확보한다. `Idle02` 및 이전 가드 샘플은 비교용으로 보존한다.

Longblade의 `CombatUpperBody`는 양쪽 `clavicle_l`·`clavicle_r`에서 시작하는 두 하위 체인을 로컬 공간에서 합성한다. 정지와 이동 모두 기본 포즈가 골반·척추·목·머리를 구동하고, 가드의 쇄골부터 손가락까지는 그 프레임의 가슴을 따라간다. 마스터 ABP와 무기별 링크드 레이어 경계에서 지속 가드와 발도·납도·시전 몽타주를 각각 처리한다. `-ApplyGuardLayer`와 `-VerifyGuardLayer`가 이 마스크를 관리한다. 기존 `spine_03`부터의 메시 공간 합성에서는 준비 클립의 가슴과 목 자세가 정지 중에도 적용됐다.

### 양손 운반 접촉

2026-11-07 원인 조사에서 원본 FBX, 직접 리타깃, 현재 가드 베이크를 같은 루프 시각에 비교했다. A/D의 위팔 방향은 원본과 직접 리타깃에서 유사했고 기존 베이크에서 몸통 대비 각도가 약 70–95° 달라졌다. 실제 Spellblade 메시를 단독 재생한 정지 가드 30% 프레임에서도 직접 리타깃과 기존 베이크의 검 방향이 달랐다. 가드 베이크에서 칼날이 얼굴 앞을 가로질렀다. 원본 메시의 비교용 검은 장착 오프셋 보정이 빠져 원본 검의 화면 위치를 판정하는 데 사용하지 않았다.

원본의 `Bip_Weapon_R` 공간에서는 양손 위치가 각 루프 내에서 거의 고정됐고 정지, 전진·좌우, 후진 사이에서 두 손 위치가 함께 달랐다. 정지 기준 왼손목 차이는 전진·좌우 약 14.8cm, 후진 약 28.3cm이며, 오른손목 차이는 각각 약 10.5cm, 19.1cm였다. `-TrialSourceCarry -FbxRoot=<원본 FBX 폴더>`와 선택적인 `-TrialSourceGripOrientation` / `-TrialSweepGripOrientation`은 임시 리타깃과 제작 키만 평가한다. 현재 공통 그립과 원본 정지 그립 및 중간값 세 가지를 비교했으며 모두 다섯 방향의 손목 기준을 만족시키지 못했다. 이 시험은 게임에 연결된 에셋을 저장하지 않았다.

후속 제작은 리타깃한 원본의 오른팔과 검 방향, 팔꿈치 방향을 출발점으로 쓰고 정지·전진 및 좌우·후진의 왼손 방향을 각각 굽는다. 가드 제작 시 칼날 중심선과 머리 사이에 여유를 두며 양팔의 도달 범위를 함께 검사한다. `-TrialSourceCarry -TrialStanceGrips -SaveStanceReview -FbxRoot=<원본 FBX 폴더>`는 미연결 미리보기를 만든다. `-InstallStanceGripTrial`은 비교를 마친 시퀀스의 자세 키를 기존 다섯 경로로 옮기고 `LeftHandCarryAuthoredRotation`을 쓴다. 런타임은 이 커브의 운반 구간에서 합성된 왼손목 방향을 보존하며 손바닥 위치만 맞춘다. 발도·납도와 공격 자체가 지정한 접촉은 해당 동작의 규칙을 따른다. 교체 전 패키지는 `SpellbladeStanceInstallBefore_*`로 복원할 수 있다.

전진 가드 제작은 `AS_LongbladeStance_Forward`에서 정지 가드의 가슴 방향을 제작 기준으로 사용한다. `spine_03`부터 `spine_05`까지 정지 가드 방향으로 섞은 뒤 로컬 키를 계산한다. 오른손과 검의 그립을 이 가슴 기준으로 잡아 양팔을 맞추고, 왼팔은 원본 팔꿈치 방향과 손목 중립 축을 함께 사용한다. 런타임 가드 마스크는 결과의 쇄골과 팔 키를 사용한다. `-TrialForwardGuard`로 복제본을 평가하고 `-ApplyForwardGuard`로 시퀀스에 저장한다. 전체 스탠스 재설치도 같은 제작을 사용한다.

쇄골 마스크 전의 전진 가드 비교에서 W 가속의 `spine_03`–`spine_05` 축 기울기 중앙값은 31.1°에서 27.6°, 지속 전진 표본에서는 19.4°에서 17.3°로 줄었다. 지속 전진의 칼끝 최저 높이는 34.5→115.2cm였고, 왼손목 굽힘 최대는 23.3°였다. 출발과 지속 이동은 기존 전방 출발 클립과 `BS_Neutral_Run_Loop_F`를 선택했다. W·대각선 입력·W→A 전환의 각 158개 표본에서 견갑 및 상의와 얼굴 교차는 각각 0건이었다. 보관소에서 `SpellbladeForwardGuard`로 당시 렌더와 측정을, `SpellbladeForwardGuardBefore_*`로 변경 전 에셋을 찾을 수 있다.

쇄골 마스크만 교체한 PIE에서 전속 좌우 이동과 W→A 전환의 칼끝이 바닥 아래로 내려갔다. 좌우 가드 시퀀스는 가슴 기준으로 검을 각각 18°와 32° 들어 올린다. 오른쪽 하체 루프의 기울기에 필요한 여유를 따로 측정했다. 두 손을 하나의 그립으로 유지하면서 양팔의 도달 범위와 왼손목 축에 맞춰 키를 베이크한다. `-ApplyStrafeCarry`와 전체 그립 재설치가 같은 제작 경로를 사용한다. 바닥 여유는 실제 이동 포즈에서 측정하고, 손 접촉은 기존 프로필의 검 부착과 그립 위치를 사용한다.

최종 평지 렌더링 PIE에서 좌우 반복 루프가 실제 선택됐고, 좌우 입력 및 W→A의 칼끝 최저 높이는 각각 23.8cm, 33.3cm, 11.7cm였다. 연속 가드가 활성인 표본에서 왼손 접촉 오차는 최대 0.02cm였다. 정지의 가슴–머리 축 기울기 중앙값은 변경 전 30.5°에서 최종 11.1°로 달라졌다. 각 실행에서 기본 Idle Break 선택은 달라질 수 있다. 발도·납도·재발도와 Z/X/C를 입력해 몽타주 재생을 확인했고, 세 시전의 활성 구간에서 가드 왼손 IK가 해제됐다. 정지·이동 및 발도·납도·시전의 최종 포즈 710개에서 견갑과 상의 각각의 얼굴 표면 교차는 0건이었다. 보관소에서 `SpellbladeArmGuard`로 비교 및 `SpellbladeArmGuardBefore_*`로 변경 전 패키지를 찾을 수 있다.

#### 스트레이프 키와 에셋 미리보기

`AS_LongbladeStance_Left`의 오른쪽 아래팔은 기존 키에서 프레임 사이 42.8°, 루프 경계에서 43.3° 바뀌었다. `Right`의 아래팔은 손의 방향과 팔 축이 조금만 변하는 구간에서 최대 56.5° 돌아갔다. 두 현상은 바닥 여유를 조정하기 전 패키지에도 있었다. 좌우 제작은 공통 가슴 상대 자세에서 팔꿈치 평면과 아래팔 회전을 구해 매 프레임의 양손 그립을 다시 맞춘다. 저장 전 팔과 손 회전의 프레임 간 변화와 루프 경계를 검사한다. 저장본의 오른쪽 아래팔 프레임 간 최대는 각각 7.6°와 7.9°, 루프 경계는 2.4°와 3.0°다.

Persona 에셋 브라우저의 호버 미리보기는 액터 없이 `UDebugSkelMeshComponent`를 만든다. Spellblade 메시의 후처리 ABP에 있는 UE 5.8 IK Rig 노드가 소유 액터에서 목표 생성 컴포넌트를 찾다가 두 번 크래시했다. 프로젝트 후처리 인스턴스가 `EditorPreview`의 액터 없는 컴포넌트에서만 후처리 실행을 막는다. `-VerifySpellbladeAssetPreviews`는 같은 컴포넌트의 메시 지정, 에셋 재생 및 BS 샘플 평가를 재현한다. Spellblade 시퀀스 143개, 몽타주 58개, BS 2개가 통과했고, 소유자 없는 후처리 76건에서 가드가 적용됐다. 검사 중 전투 VFX와 타격 노티파이는 소유 캐릭터가 없어 건너뛰었다.

전체 시퀀스의 팔 키를 스캔했을 때 동일한 축 방향 회전 급변이 남은 곳은 `SourceTransient/ArmRollTrial`의 제작 비교용 `ArmAudit_Finisher`와 `ArmAudit_QuickSkill`이었다. 무기 궤적을 포함한 공격 동작의 시각 품질은 이 키 검사와 별도다. 로컬 보관소의 `SpellbladeArmContinuityReview`에 에셋별 측정과 연결 목록을 기록했다. 미연결 ArmRollTrial 비교본 17개와 이전 ReadyGuard 검토본은 중앙 보관소의 `05_AssetAndRecoveryBackups`로 옮겼다. 기존 경로와 복원 정보는 중앙 인덱스에서 찾을 수 있다.

[Spellblade 애니메이션 연속성 감사](../../../Scripts/Audit/Audit-SpellbladeAnimationContinuity.py)는 현재 폴더의 시퀀스, Blend Space와 몽타주를 읽어 주요 몸통·팔·다리 본의 전 키를 검사한다. 패키지 참조로 도달 가능한 몽타주의 구간과 Blend Space 샘플을 별도로 표시한다. 참조 가능 여부는 어떤 입력이 실제로 그 몽타주를 선택하는지와 구분한다. 전완의 방향과 손목 회전이 거의 유지되는데 전완 회전만 뛰는 경우는 일반 회전 급변과 따로 표시한다. 큰 회전은 원본의 스윙과 비교하고 실제 합성 포즈를 확인한 뒤 수정 여부를 판단한다.

새 캐릭터는 같은 검사기에 JSON 프로필을 넘긴다. `asset_roots`는 검사할 시퀀스·몽타주·Blend Space의 폴더다. `consumer_roots`에 캐릭터 BP와 장비·스타일 데이터의 패키지 경로를 넣는다. 별도 경로의 능력이나 데이터가 사이에 있으면 `dependency_roots`에 그 폴더를 추가한다. `style_roots`는 해당 장비에 연결된 결과를 따로 표시할 때 사용한다. UE5와 다른 본 이름은 `bone_map`에 검사 역할 이름과 실제 본 이름의 대응을 지정한다. 결과는 `Saved/AnimationAudit/<프로필 이름>.json`에 저장한다.

```powershell
& $UnrealEditorCmd $Project -run=pythonscript '-script="Scripts/Audit/Audit-SpellbladeAnimationContinuity.py --profile Saved/AnimationAudit/NewCharacter.json"' -nullrhi -unattended
```

```json
{
  "asset_roots": ["/Game/Characters/NewCharacter", "/Game/Anim_Assets/NewCharacter"],
  "consumer_roots": ["/Game/Characters/NewCharacter/BP_NewCharacter"],
  "style_roots": ["/Game/DataAssetSets/CombatStyle/DA_NewCharacter"],
  "dependency_roots": ["/Game/DataAssetSets", "/Game/GAs/NewCharacter"],
  "bone_map": {"lowerarm_l": "Forearm_L"}
}
```

Spellblade의 공용 이동은 `SK_Spellblade_Complete`에서 마스터 ABP의 UE5 모션매칭을 직접 평가한다. 전투 W는 `BS_Neutral_Run_Loop_F`, A/D는 `M_Neutral_Run_Loop_LL/RL`을 실제 선택했다. 전투 가드 소스의 일부 하체 키에서 루프 경계 각도 차이가 있어도, 현재 가드 레이어는 쇄골·양팔을 합성하며 하체의 이동을 이 소스로 교체하지 않는다.

후속 감사에서는 시퀀스 145개의 14,284키, 몽타주 58개, Blend Space 2개를 확인했다. 시작 장비·스타일에서 도달 가능한 몽타주는 32개이고 Blend Space는 현행 `BS_Spellblade` 한 개다. 전완 축 회전 후보 두 개는 모두 비교본이었다. 원본 FBX 18개와 대응하는 강한 회전 구간을 비교했으며 기본 2타 왼쪽 위팔은 원본 112.3°와 현행 121.8°, 질주 공격 왼손은 원본과 현행 모두 약 134.8°였다. 질주 공격의 오른쪽 전완은 98.9°에서 113.6°로 커졌다. 원본에 이미 큰 회전이 있는 공격을 공용 리타깃이나 합성 규칙에서 일괄 완화하면 무기 궤적과 타격 구간이 달라질 수 있다. 이 감사에서는 에셋을 다시 저장하지 않았다.

후속 수정은 [공격 팔 제작기](../../../Scripts/Authoring/Refit-SpellbladeAttackArms.py)로 기본 2타의 왼팔과 질주 공격의 오른팔을 각각 다시 베이크했다. 어깨·손과 팔 길이로 가능한 팔꿈치 위치를 계산하고, 자세 사이의 이동이 작은 경로를 연결한다. 원래 손 변환으로 손목 키를 다시 만들고 원본 구간 양 끝을 보존한다. 30Hz 키에서만 손을 맞추면 키 사이에 7cm 이상의 차이가 생겨 두 공격만 120Hz로 제작하고 기본 압축 재생률도 일치시켰다. 별도 플랫폼 오버라이드는 같은 샘플링을 확인할 수 없으면 제작을 중단한다.

같은 120Hz 표본에서 기본 2타의 왼쪽 위팔 최고 회전은 31.85°에서 24.22°, 질주 공격의 오른쪽 전완은 30.22°에서 21.57°로 줄었다. 240Hz 표본의 무기 기준점 오차는 최대 0.85cm와 0.98°였다. 시퀀스 길이·커브·노티파이와 몽타주 타격 구간을 보존했다. 재로드 뒤 기본 2타 437키와 질주 공격 473키가 압축 재생에 사용되는 것을 확인했다. 원본 복원은 중앙 보관소의 `SpellbladeAttackRefitRestoreMap`을 따른다.

`-AuditSharedArmRetarget`로 원본 17개와 직접 리타깃 결과를 각 클립의 9개 시간 표본에서 비교했다. 기본 1타 오른쪽 전완의 표본 간 최대 축 회전은 117.2°에서 159.1°, 발도 오른쪽 손목은 80.3°에서 115.4°로 커졌다. 팔이 이미 도는 원본 구간을 직접 리타깃이 증폭한 예이며, 실제 프레임 간 변화량이나 보정된 플레이 에셋의 판정값으로 사용하지 않는다. 이전 3본 일대일 매핑 시험에서도 대표 표본의 수치가 같았다. 재제작 시 원본 대비 전완 비틀림과 손목 자세를 별도로 비교하고, 완성 시퀀스에서 팔꿈치 방향과 무기 그립, Blend Space 전환을 다시 검사한다. `SpellbladeRigAuditRetargetResults`에 비교값을 보관했다.

에디터에서 `Stance_Left`와 `BS_SpellbladeKit_CombatUpperBody` 탭을 열고 닫은 뒤, 실제 Spellblade로 평지 PIE를 진행했다. A/D 반복 루프와 W→A 전환의 칼끝 높이는 최소 23.6cm였고, 가드 중 왼손 접촉 오차는 최대 0.15cm 미만이었다. 발도·납도와 Z/X/C 재생, 시전 중 가드 접촉 해제를 확인했다. 좌우·대각선·W→A의 포즈 164개에서 견갑·상의와 얼굴 표면 교차는 없었다. `SpellbladePreviewComparison`과 `SpellbladeContinuityBefore_*`로 측정 및 변경 전 에셋을 찾을 수 있다.

후속 확인에서 선택된 샘플은 `-90 / 500`이었고 실제 BS 미리보기의 초록 십자는 약 `-52 / 500`에 있었다. Left 단독에서 상완·아래팔의 길이는 일정했다. Left와 Forward 또는 Idle을 합성할 때 오른쪽 아래팔의 로컬 회전 간격이 180° 경계를 넘으며 보간 방향이 뒤집혔다. Quinn과 Spellblade 모두 같은 현상이 재현됐다.

Left의 무기 팔은 Right와 같은 가슴 상대 팔꿈치 기준 자세로 베이크한다. 각 프레임의 양손 그립과 칼끝 제작 보정은 그 자세에서 다시 맞춘다. 제작 시퀀스는 각자의 루프 연속성과 함께 다른 가드 샘플과의 회전 간격을 검사한다. `-VerifyStance`는 Ready를 기준으로 회전 표현의 부호를 맞춘 뒤 모든 키 조합이 160° 미만인지 확인한다. 최종 다섯 가드 샘플에서 최대 138.9°였다. `-AuditSpellbladeArmPreview`는 실제 Persona 컴포넌트로 BS의 재생 위치를 훑는다. 97개 시간 표본에서 `-52 / 500`의 오른쪽 팔꿈치 최대 변화는 Quinn 85.0°→0.92°, Spellblade 87.0°→0.96°였다. 두 BS를 각각 현재 ABP와 이전 ABP에 연결한 뒤, 현재 BS는 두 메시에서 36개 입력 조합, 이전 BS는 Quinn에서 27개 조합으로 검사했다.

에디터를 다시 열어 두 ABP가 새 BS 경로를 참조하고 옛 패키지와 리디렉터가 없는지 확인했다. 최종 평지 PIE에서 A/D, W+A, W→A와 발도·납도·Z/X/C를 확인했다. W→A 가드에서 오른쪽 팔꿈치 프레임 간 변화는 최대 4.34°, 칼끝 높이는 최소 26.6cm였다. 왼쪽 이동·W+A·W→A 포즈 155개에서 견갑·상의와 얼굴 교차는 없었다. 보관소의 `SpellbladeArmPreviewSweep`과 `SpellbladeBlendBefore_*`에 측정과 이전 에셋을 남겼다.

평지 렌더링 PIE의 정지·전후좌우 안정 구간에서 왼손목 꺾임 최대는 방향별 15–25.5°였고, 손바닥 위치 오차는 표기 정밀도에서 0.00cm였다. 머리 본과 칼날 근사 선분의 간격은 같은 구간에서 31–51cm였다. 이 간격은 갑옷 표면의 관통 판정을 대신하지 않는다.

수정 전 X 4.33초와 C 3.87초의 칼날 접근은 시전 시퀀스 단독에서도 각각 4.72cm와 3.46cm로 재현했다. 손목 이동과 회전만으로는 수정량이 크거나 여유가 부족했다. `-TrialCastWeaponClearance`는 위험 구간별로 Longblade 가드의 오른쪽 쇄골부터 손목까지의 로컬 자세 후보를 평가한다. `-ApplyCastWeaponClearance`는 기준을 통과한 자세 키를 X/C의 연결 시퀀스에 저장한다. 정지와 이동 중의 PIE에서 머리 본과 칼날 근사 선분의 최소 간격은 X 23.1cm, C 22.9cm였고 목 본 기준으로는 각각 27.7cm, 29.4cm였다.

`-ApplyCarryElbowClearance`는 Ready의 손목 변환과 검 위치를 보존하며 왼팔꿈치 방향을 아래로 조정한다. 평지 PIE에서 정지 가드의 대표 구간에서 팔꿈치 높이 중앙값은 어깨보다 7.8cm 위에서 2.2cm 아래로, 왼손목 굽힘 중앙값은 23.7°에서 8.2°로 바뀌었다. 정지·이동 Z/X/C 정상 완료, 시전 중단 후 무장·손 접촉 복귀, 발도·납도 및 대시를 포함한 23개 시나리오를 실행했다. 시전의 변경 직전 패키지는 `SpellbladeCastArcBefore_*`, Ready는 `SpellbladeCastArcElbowBefore_*`로 복원할 수 있다.

시전의 지면 여유는 시퀀스 단독과 이동 합성에서 분리해 측정한다. 수정 전 Z의 칼끝 프로브는 시퀀스 단독에서 −25.8cm, 평지 이동 시전에서 −35.6cm까지 내려갔다. X는 해당 구간에서 단독 시퀀스 기준 30cm 위였으나 이동 합성에서 −4.2cm까지 내려갔다. `-TrialCastGroundClearance`는 현재 검 소켓으로 칼끝의 여유가 부족한 자세에서 오른쪽 전완을 팔꿈치 축으로 회전하는 후보를 만든다. `-ApplyCastGroundClearance`는 손목의 전완 상대 자세를 보존하면서 검의 궤적을 저장한다. 120Hz 검사에서 머리·목과 검의 간격 및 최대 손목 위치 변화를 확인한다. 적용 후 정지·이동 평지 PIE의 칼끝 프로브 최저점은 Z 5.7cm, X 9.7cm, C 13.1cm였다. 변경 전 패키지는 `SpellbladeCastGroundBefore_*`로 복원할 수 있다.

### 견갑과 얼굴 표면 검사

`-AuditShoulderSurface`는 Complete와 분리형 파츠의 LOD0 상부 삼각형, 바인드 변환 및 가중치를 Saved에 내보낸다. `-AuditCastShoulderStages -FbxRoot=<Greatsword_A 폴더>`는 원본 견갑·얼굴과 현재 메시에서 원본 FBX·직접 리타깃·연결 시퀀스의 변형 본을 30Hz로 평가한다. [표면 검사 스크립트](../../../Scripts/Audit/Audit-SpellbladeShoulderSurface.py)는 해당 데이터나 PIE 최종 본 포즈를 받아 선택한 두 파츠의 표면 교차를 검사한다. 좌표가 공유되는 스키닝 파츠에 사용하며 헤어 카드의 투명 영역, 물리, LOD 전환은 별도 검증이 필요하다.

`-AuditClothingSurface`는 같은 형식으로 현행 몸체·lower와 제작 원본의 대응 메시를 비교할 수 있도록 LOD0 전체 표면을 내보낸다. 오른쪽 팔꿈치의 레이스는 lower의 `M_pdw_00_lb_0001_dec` 섹션이다. 같은 비전투 전진 프레임에서 몸체 표시만 바꾸면 레이스 밖의 피부 얼룩이 사라진다. 팔꿈치 주변 기준 자세의 교차 삼각형 쌍은 원본 0개, UE5 메시 70개였으며, 비전투 전진 19개 표본 모두 교차했다. 양쪽 메시의 가까운 정점 사이 기준 간격 중앙값은 약 0.2mm였고, 웨이트 차이 중앙값은 0이었다.

바인드 자세에서 이미 교차하므로 팔꿈치의 소매와 피부 관계를 의상 제작에서 정리하고 실제 굽힘 포즈와 LOD에서 확인한다. 반경 오프셋과 근접 표면 기준 웨이트 전달은 검증 포즈의 교차를 제거하지 못해 저장하지 않았다. 로컬 중앙 보관소의 `SpellbladeRigAuditClothingResults`와 `SpellbladeRigAuditSleeve`에서 측정과 후보 결과를 찾을 수 있다.

후속 검사에서 레이스 재질이 불투명하고 오른쪽 소매의 501개 면이 몸체와 동일한 삼각형 구조를 공유함을 확인했다. `-TrialSleeveSurface`는 대응하는 몸체 면에 기존 레이스 재질, UV와 탄젠트를 옮기고 의상 쪽의 대응 면을 제거한다. 바깥 장식과 레이스 사이의 열린 부분은 원래 재질을 유지한다. `-ApplySleeveSurface`로 저장한 `SK_Spellblade_body_StarterOutfit`과 `SK_Spellblade_lower_StarterOutfit`은 시작 의상의 한 쌍으로 `BP_Spellblade`에서 사용한다. 다른 의상은 범용 몸체와 각자의 파츠를 사용한다. 기준 몸체와 lower, 제작 FBX, 공유 Skeleton 및 마스터 ABP는 이 의상의 생성 입력이다.

팔꿈치 주변 기준 자세의 교차는 70쌍에서 9쌍, 비전투 전진 표본의 최고치는 127쌍에서 15쌍으로 줄었다. 남은 장식과 피부의 기하 교차는 일부 표본에 남는다. 새 파츠로 비전투 전진, 전투 W/A/S/D, 대각선, 방향 전환 및 정지, 발도·납도, Z/X/C, 기본 1타와 찌르기를 포함해 16개 렌더링 PIE 사례를 통과했다. 검수 캡처에서 신고된 오른쪽 팔꿈치 피부 얼룩은 관측되지 않았다. 몸체의 LOD0/1/2에서 레이스 재질 섹션을 확인했으며 실제 원거리 LOD 전환과 다른 의상은 별도 검증 범위다.

전투 가드의 오른손 과굴곡은 `-TrialCarryWrist`로 양손과 칼의 원래 위치를 기준으로 팔꿈치 방향을 다시 계산했다. `-ApplyCarryWrist`는 현재 Blend Space의 다섯 시퀀스에서 오른쪽 상완·전완·손목 트랙만 베이크한다. 렌더링 PIE의 W 이동에서 오른손목 굽힘 중앙값은 48.3°에서 36.6°로 줄었다. 찌르기 원시 시퀀스에는 약 2.1초에 팔꿈치가 급변하는 키가 있지만, 유일하게 이를 참조하는 몽타주는 0–1.26초만 재생한다. 이 후반 키는 제작 원본에 유지했다. 검증 수치와 저장 전 패키지는 로컬 중앙 보관소의 `SpellbladeSurface` 기록을 따른다.

변형 복원 전 X의 견갑과 얼굴 교차는 원본 1/82, 직접 리타깃 70/82, 당시 연결 시퀀스 단독 70/82였다. C는 각각 3/83, 41/83, 39/83이었다. 분리형 파츠의 렌더링 PIE에서는 정지·전후좌우 가드에 교차가 없었고, X/C와 발도·기본 1타의 일부 구간에 교차가 있었다. 원본 쇄골의 부모는 `Bip01-Neck`이며 현재 견갑은 UE5 쇄골에 붙은 legacy 가지를 따라간다. 원본 시전의 쇄골 트위스트 변화는 26.5–39.7°였고 직접 리타깃에서 0°였다. 원본의 견갑·얼굴 변형을 흉추 기준으로 함께 맞춘 오프라인 시험 프레임에서 교차가 사라졌다.

`-TrialCastShoulderDeformation -FbxRoot=<Greatsword_A 폴더>`는 임시 복제본에서 원본의 목·머리와 왼쪽 쇄골·쇄골 트위스트 변형을 흉추 기준으로 복원한다. 변형 궤적은 0.12초 반경에서 대칭으로 평활화하며, 이 갑옷에서 측정한 1cm 얼굴 여유를 작성한다. `-ApplyCastShoulderDeformation`는 같은 키를 연결된 Z/X/C 시퀀스에 저장한다. 손과 무기를 구동하는 UE5 본의 키와 몽타주를 그대로 사용한다. 저장본 단독 검사에서 견갑과 얼굴의 교차는 Z 0/104, X 0/163, C 0/166이었다. 변경 전 패키지는 `SpellbladeShoulderDeformBefore_*` 및 1cm 적용 직전의 `SpellbladeShoulderFitBefore_*`로 복원할 수 있다.

변형 복원 직후 평지 렌더링 PIE 23개 입력 시나리오를 통과했다. Z/X/C의 정지·이동·중단 9개 사례에서 분리형 견갑과 얼굴의 교차는 기록된 2,558프레임에서 0이었다. 정상 시전 효과 6회와 중단 후 양손 운반 복귀를 확인했다. X/C 시전 중 변형 머리 본과 칼날 근사 선분의 최소 거리는 각각 17.1cm와 18.1cm였다.

X의 별도 머리 움직임은 원본에서도 약 0.2초 동안 흉추 대비 83°의 각거리를 이동했다. 원본과 복원 후 단독 시퀀스의 최고 속도는 각각 약 576°/s와 435°/s였다. X 제작은 초반 0.86초의 목·머리 변형 경로를 누적 각거리 기준으로 다시 배치해 방향의 연속성과 제스처 종료 자세를 보존한다. 새 단독 시퀀스의 같은 구간 최고 속도는 약 189°/s이며, 견갑과 상부 갑옷 모두 163개 샘플에서 얼굴 교차가 없었다. 직전 시퀀스는 `SpellbladeCastLeftGazeBefore_*`로 복원한다.

`-AuditLongbladeActionShoulderStages`는 발도·납도·기본 1타의 원본 갑옷 및 직접 리타깃을 평가한다. `-TrialLongbladeActionDeformation`은 원본 목·머리, 쇄골 및 왼쪽 위팔 트위스트를 복원한 후보를 저장 없이 평가한다. `-ApplyLongbladeActionDeformation -DeformRole=<Draw|Sheathe|BasicCut01>`은 검증한 동작을 하나씩 저장한다. 발도 후보의 교차는 견갑 4/69→0/69, 상부 갑옷 13/69→0/69였다. 납도 상부 갑옷은 원본 0/66, 직접 리타깃 20/66, 수정 전 시퀀스 26/66, 변형 복원 후 0/66이었다.

기본 1타의 견갑은 원본과 변형만 복원한 후보에서 모두 41/106개 샘플이 턱 주변에 교차했다. 원본에서 확인한 교차 구간에 견갑을 기존 쇄골 피벗 기준으로 열고 앞뒤로 부드럽게 복귀시키자 견갑과 상부 갑옷 모두 0/106이었다. 게임에 연결된 발도·납도·기본 1타의 변경 직전 패키지는 각각 `SpellbladeDrawDeformBefore_*`, `SpellbladeSheatheDeformBefore_*`, `SpellbladeBasicShoulderFitBefore_*`로 복원한다.

세 동작과 X의 시선 수정 적용 후 25개 입력 시나리오를 통과했다. 발도·납도 정지와 이동, 중단·재발도, 기본 1타, X 정지·이동·중단의 2,468개 기록 프레임에서 분리형 견갑 및 상부 갑옷의 얼굴 교차는 0건이었다. 정상 발도·납도마다 검 부착이 한 번씩 전환되고 발도 중단 후에는 납도 소켓으로 복귀했다. X 진입의 머리 최고 속도는 정지 513→270°/s, 이동 515→274°/s였다. 이 검사에서는 기본 1타와 이동 납도의 칼끝 프로브가 각각 평지 아래 33.0cm, 4.1cm까지 내려가는 구간을 추가로 발견했다.

### 실제 장착 궤적과 지면 여유

`-AuditLongbladeWeaponArc -FbxRoot=<Greatsword_A 폴더>`는 원본 무기 본, 직접 리타깃 및 연결 시퀀스를 실제 Longblade 그립과 칼끝 프로브로 비교한다. 기본 1타의 직접 리타깃은 발끝 대비 약 39cm까지 내려갔고 납도는 초반 스윙에서 약 8cm 아래로 내려갔다. 기본 1타 몽타주의 타격 창은 0.480–0.690초이고, 지면 관통은 타격 창 끝부분과 후속 자세에 걸쳤다. 납도 장착 전환은 1.067초였으며 위험한 초반 스윙과 분리되어 있었다.

`-TrialLongbladeWeaponArc -ArcRole=Sheathe`는 손 소켓이 검을 소유하는 납도의 전완 궤적 후보를 저장 없이 평가한다. `-ApplyLongbladeWeaponArc -ArcRole=Sheathe`는 검증을 통과한 납도 시퀀스의 오른쪽 전완 로컬 키만 저장한다. 손목의 전완 상대 키, 루트 이동 및 몽타주 노티파이는 유지한다. 손목 위치, 검과 머리·목의 간격, 등 소켓 전환 구간을 120Hz로 검사한다. 보정은 소켓 전환 0.40초 전에 끝나며 전환 구간의 칼끝 변화량은 0.000cm였다. 반복 실행은 연속 궤적이 이미 기준을 만족하면 저장 없이 끝난다.

납도 초기 후보의 좌우 이동은 지면 위였지만 후진 합성의 0.275초에서 −4.4cm를 추가로 재현했다. 최종 납도 제작은 초반 스윙의 키 높이 34cm, 연속 평가 높이 30cm를 사용하고 후기 장착 구간은 별도 지면 기준으로 검사한다. 이 수치는 이 검의 길이와 실제 이동 합성에서 측정한 제작 여유다. 기본 1타는 연속 평가에서 6.7cm를 확보했다. 기본 1타 타격 창 끝의 판정점은 최대 32.6cm, 수평으로 20.7cm 이동했다. 실제 레벨 NPC에 기본 1타를 입력해 체력 100→90과 판정 성공을 확인했고, 타격 중 시각 칼끝과 Leader 판정점의 최대 차이는 0.001cm 미만이었다.

후진 Z에서도 −5.3cm를 재현해 Buff 제작 높이를 23→35cm로 조정했다. 이 추가 수정의 전완 회전은 최대 4.7°, 손목 위치 변화는 1.8cm였고 머리·목 간격은 유지됐다. X/C 패키지의 바이트는 그대로였다. 평지 PIE 38조건에는 Z/X/C의 정지·전후좌우 15조건과 시전 중단, 이동 기본 1타, 정상·이동·중단 발도와 좌우·후진 납도, 방향 전환 및 대시를 포함했다. 모든 조건의 입력·몽타주·복귀 검사를 통과했고, 시전 칼끝의 최저점은 Z 4.1cm, X 4.5cm, C 12.2cm였다. 손 고정 1타와 납도의 지면 여유는 각각 6.9cm, 12.1cm 이상이었다. 안정 구간 왼손 위치 오차는 최대 0.002cm 미만이었고 A/D의 왼손목 굽힘 최대는 각각 23.1°, 18.2°였다.

기본 1타의 흉추 상대 전완·손 회전 최고 속도는 수정 전 약 2,442/2,123°/s, 수정 후 약 2,437/2,122°/s였다. 궤적 수정으로 기존 베기의 최고 회전 속도가 증가하지 않았다. 직접 UBT 빌드와 `SecondaryHandContact`, `CanonicalMeleeTrace`, `PlayerLocomotion.ProductionGraph`, `PrimaryGripAttachment` 네이티브 검사를 통과했다. 기본 1타·납도·Z 제작 명령을 재실행한 뒤 세 생산 패키지의 SHA-256이 모두 동일했고, `VerifyDirectBodyUpperMontages`와 `VerifyCastLayer`도 통과했다. 38조건 시험의 연속 동일 스킬 입력은 완료 후 6초 동안 유지되는 버프 태그에 막혔으므로, 실제 태그 수명을 보존한 채 다른 스킬과 교대로 재배치했다.

기존 손 고정 방식에서 기본 2타의 칼끝은 −53.2cm까지 내려갔다. `-AuditLongbladeGripFrames`로 비교하니 원본에는 손과 검 사이의 상대 회전이 약 57° 변하는 구간이 있었고, 새 리그에도 `Bip_Weapon_R` 트랙이 남아 있었다. 일반 UE5 보조 본 `ik_hand_gun`의 흉추 기준 위치는 이 물리 무기의 원본에서 113–160cm 벗어났다. 실제 검을 `hand_r`에 고정하던 장착 정책이 공격의 무기 궤적을 덮어쓴 원인이었다.

기본 3타는 각 공격 에셋에서 `SourceAnimation`을 명시한다. 장착 프로필의 `WeaponSource_Longblade`는 `Bip_Weapon_R`에 놓이고 레퍼런스 자세의 손바닥 위치를 기준으로 5.168cm 이동시켰다. 회전은 무기 본에서 가져온다. 기존 Presentation의 몽타주 소유권으로 해당 공격에서만 전환하며 두 손은 원본 FK를 사용한다. 같은 본 공간의 실제 칼끝 프로브를 세 근접 판정에 쓴다. 준비, 시전과 장비 전환은 기존 손·등 장착을 사용한다. `-TrialLongbladeSourceDrive`, `-ApplyLongbladeSourceDrive`, `-VerifyLongbladeSourceDrive`는 실제 장착 프로필과 세 공격 정의, 몽타주를 점검한다. 손 고정에 맞추던 기본 1타의 임시 전완 제작은 제거했다.

저장본으로 다시 실행한 평지 3연타에서 칼끝 최저점은 1~3타 각각 20.1/22.9/47.2cm였다. 타격 구간의 오른손 접촉 오차와 화면 칼끝 대비 Leader 판정점 오차는 0.001cm 미만이었다. 공격 취소 시 소스 소켓에서 손 소켓으로 한 번 복귀한 후 3연타를 다시 수행했다. 실제 레벨 NPC는 기본 1타에 체력 100→90으로 감소했다. 교체 전 여덟 패키지와 당시 기본 1타 시퀀스의 복원 위치는 중앙 보관소의 `SpellbladeActionArcSourceBefore_*`와 `SpellbladeActionArcSourceDriveBackup.json`에 있다.

공격 진입 전체를 다시 샘플링하니 1타 첫 0.1초 안에 오른손과 검이 정지 11.5cm, 이동 8.5cm까지 벌어졌다. 이전 무기의 월드 변환을 진입 시 한 번 저장해, 움직이는 손과 별개로 검을 블렌드하던 경로였다. 두 소켓이 같은 직접 재생 메시를 쓰고 기본 공격의 오른손이 FK를 소유할 때는 매 프레임의 손 장착 변환과 무기 본 변환을 블렌드한다. 별도 메시 또는 접촉 IK를 쓰는 무기는 기존 진입 경로를 사용한다. 정지·좌우 이동·중단·3연타에서 타격 전 진입 및 손 소켓 복귀까지 오른손과 검의 최대 오차는 0.16cm였다.

38조건의 표면 검사에서 이전 대시 전방·좌측에 각각 18/54, 19/56개 견갑 교차 프레임이 있었다. 대시의 원본 목·머리·어깨 변형 본을 복원한 저장본에서, 전방 63개·좌측 64개 샘플의 견갑 및 상부 갑옷 교차는 0건이었고 두 방향 모두 1,000cm 이동했다. 이 작업은 대시의 루트 키를 건드리지 않았다. 오른쪽·후진 납도 진입과 Z 후진 복귀의 미세 교차는 별도 시험 대상으로 남아 있다. 납도의 접촉 IK를 끈 비교에서도 교차가 남았고, 조준 뒤 슬롯을 사용한 비교에서는 교차 규모가 줄었다.

원본 FBX와 원본 갑옷의 견갑 교차는 기본 2타 17/111, 3타 42/113개 샘플에서도 재현됐다. 이 원본 조합의 상부 갑옷 교차는 두 타 모두 0건이었다. 2·3타에 원본 변형을 복원한 저장본은 실제 3연타의 상부 갑옷 교차를 없앴다. 기존 견갑은 같은 재생의 2타 16/27, 3타 15/35, 복귀 5/117개 샘플에서 얼굴을 통과했다.

`-TrialLongbladePauldronFit`은 실제로 그리는 모듈러 `SK_Spellblade_sho`의 임시 복제본을 빌드하고, `-ApplyLongbladePauldronFit`은 같은 제작을 저장한다. 견갑의 3,602개 소스 정점에 흉추 지지를 배분하면서 기존 스킨 영향의 30%를 남긴다. 위쪽 가장자리는 13cm 높이 범위에서 최대 바깥쪽 6cm, 아래쪽 2cm까지 완만하게 이동한다. 장갑·장식 섹션, 리그 본과 무기 접촉은 이 메시 편집의 대상에서 제외한다. 단일 LOD의 제작 결과를 사용하며 별도 원본 LOD와 대체 스킨 프로필이 들어오면 명령을 중단한다. 복원은 `SpellbladeActionArcPauldronBefore_*`를 사용한다. 새 메시의 내보내기 표면에서 3연타·복귀와 실제 렌더를 비교했다. 얼굴 교차와 옷 아래 가려지는 몸체의 교차 수는 별도로 판정한다.

후진 Z의 복귀 포즈 한 프레임에서 상의 칼라와 얼굴의 삼각형 한 쌍이 교차했다. `-TrialLongbladeCollarFit`과 `-ApplyLongbladeCollarFit`은 실제 상의 `SK_Spellblade_upper`의 앞 칼라 가장자리 167개 소스 정점을 3.25cm 반경에서 최대 0.40cm 내린다. 칼라의 스킨 웨이트와 시전 타이밍은 유지한다. 복원은 `SpellbladeActionArcCollarBefore_*`를 사용한다.

같은 장비 몽타주를 조준 뒤의 기존 슬롯으로 옮긴 A/B에서 견갑 교차가 줄었다. 다만 우측·후진 납도의 머리 회전 최고 속도가 각각 207→310°/s, 392→562°/s로 증가했다. 해당 슬롯의 가지에만 관성 노드를 붙인 별도 시험은 같은 몽타주 그룹의 다른 슬롯에서도 관성화 요청이 발생해 오류를 냈다. 두 실험의 장비 몽타주와 마스터 패키지는 복원했다. 공용 슬롯 그룹은 여러 슬롯에 요청을 전달하므로 관성화를 적용하려면 그룹 소비 경로 전체를 점검해야 한다. [Epic의 Inertialization 및 레이어 합성 설명](https://dev.epicgames.com/documentation/unreal-engine/animation-blueprint-blend-nodes-in-unreal-engine)

납도에는 장비 레이어 수명 결함도 있었다. 전투 태그가 제거되는 순간 무기 레이어가 풀리면서 납도 슬롯의 진입 포즈가 비전투 이동으로 교체됐다. 이제 전환 컴포넌트가 현재 납도 몽타주의 블렌드 완료·블렌드아웃·취소를 소유한다. 이전 재생의 콜백은 몽타주와 재생 리비전으로 걸러낸다. 마스터는 공용 이동 포즈를 한 번 캐시해 기존 장비 링크드 레이어와 두 입력 블렌드에 전달한다. 납도 중에는 엔진의 실제 몽타주 가중치로 장비 자세의 기여를 연속해서 낮추고, 이후 장비 레이어를 해제한다. 기존 시전·장비 슬롯, 하체 이동 그래프와 직업 상속은 유지한다. `-ApplyWeaponCarryLayerBlend`와 `-VerifyWeaponCarryLayerBlend`로 연결을 제작·검증한다. 마스터 교체 전 패키지는 `SpellbladeActionArcWeaponLayerBefore_*`로 복원한다.

2인 리슨 PIE에서 호스트가 관찰하는 원격 권위 폰은 자신의 발도 복제 콜백을 받지 않아 공격 중에도 검을 등에 두고 있었다. 서버가 받은 발도 표현 신호를 해당 호스트 관찰자에도 기존 표현 처리로 전달하고, 조기 신호가 빠지면 전투 상태 확정 시 기존 발도 표현을 재생한다. 수정 후 로컬 호스트·자율 프록시·리슨 서버의 원격 권위 폰·시뮬레이션 프록시에서 발도, 1타 소스 무기 소켓, 납도 블렌드 해제 및 등 복귀를 관측했다. 이 시험은 같은 프로세스의 2인 리슨 PIE에서 수행했다.

최종 마스터로 평지 38개 입력을 재생했다. 이 포즈의 3,388개 샘플을 저장된 견갑과 상의로 검사했고 두 메시의 얼굴 교차는 각각 0건이었다. 칼라 수정 뒤 실제 후진 Z 두 회차는 552개 프레임을 모두 검사했다. 안정 A/D의 왼손목 굽힘 최대는 23.2°와 17.8°였고, 정지 가드의 중앙값은 8.3°였다. 전방·좌측 대시는 950cm에 약 0.35초에 도달하고 1,000cm에서 끝났다. 최종 소스 그립의 진입·복귀, 2인 네트워크의 네 관찰 경로, 전환 소유권·레이어 수명·손 접촉·공용 그래프·무기 장착·근접 판정 자동화 6개를 통과했다. 경사와 분리 프로세스의 전용 서버, 다른 체형·갑옷 조합은 이 표면 검증 범위 밖이다.

실제 촬영과 측정 원자료, 소스 단계 비교, 실패한 후보와 변경 전 복원본은 중앙 ArchiveStore의 `INDEX.csv`에서 `SpellbladeActionArc` 접두어로 찾을 수 있다.

이 조치는 리타깃 이후 실제 검과 체형에 맞추는 애니메이션 제작 보정이다. 변형 본의 전달 누락과 운반 접촉의 이중 보간 수정은 앞 절의 원인 수정에 해당한다. 변경 직전의 두 시퀀스는 중앙 보관소의 `SpellbladeActionArcBefore_*` 별칭으로 복원할 수 있다. `BasicCut01`은 `DirectBody/CombatRevision`, `Sheathe`는 `DirectBody/Equipment`의 같은 이름 패키지로 복원한다.

Longblade의 `WeaponGrip_L`은 `Bip_Weapon_R` 루트 기준의 접촉점이다. 공용 소켓 방향은 준비 루프와 UE5 몸체의 `PalmGrip_L`에서 가져왔다. 기존 `-ApplyCarryContact`는 준비 자세의 양손 위치와 팔꿈치 방향을 전 방향에 적용하는 비교용 제작 경로다. 현재 연결된 다섯 루프를 다시 만들 때는 위의 원본 리타깃 미리보기와 설치 절차를 사용한 뒤 Ready의 팔꿈치를 검증한다. 제작과 런타임 검증에서는 손바닥 위치·방향, 손목 축 비틀림 및 전완과 손 사이 꺾임을 별도로 평가한다.

Master ABP는 공용 이동과 몽타주 순서를 맡고, 장비가 선택하는 Longblade 링크드 레이어는 방향별 상체 포즈를 제공한다. 손가락과 팔꿈치는 제작 단계에서 정하며 런타임 손 접촉 솔버는 포즈가 섞인 뒤의 오차를 줄인다. Epic의 Two Bone IK는 손의 접촉점과 팔꿈치 방향을 따로 제어한다. Ubisoft의 GDC 사례는 몸과 무기 모션을 합성한 뒤 두 손의 접촉을 계산한다. 커뮤니티 제작자 Kris는 그립 유형별 포즈를 먼저 두고 IK로 남은 간격을 보정한다. [Epic Two Bone IK](https://dev.epicgames.com/documentation/unreal-engine/animation-blueprint-two-bone-ik-in-unreal-engine), [Ubisoft GDC 발표](https://media.gdcvault.com/gdc2015/presentations/Therriault_David_InYourHands.pdf), [그립 제작 사례](https://forums.unrealengine.com/t/hand-ik-with-different-grips/1318018)

MMORPG의 확장성 사례로 New World는 공통 실행 경로의 상태와 비용을 줄이고, 그 위의 개별 액션은 제작 및 검증하는 방식을 공개했다. 이 자료는 공통 실행 계층과 무기별 제작 데이터의 역할을 나누는 데 참고했다. [New World 전투·애니메이션 기술 발표](https://www.newworld.com/en-gb/news/articles/upgraded-combat-and-animation-system-deep-dive)

`LeftHandCarryIK`는 운반 포즈가 기존 몸체 손 접촉 솔버에 전달하는 가중치다. 솔버는 같은 입력 포즈의 오른손을 기준으로 왼손목 목표를 만든다. 무기가 오른손에 붙은 전투 상태에서 운반 접촉을 사용한다. 전투 스타일의 `Override Passive Left Grip Release Slots`와 `Passive Left Grip Release Slots`는 어떤 몽타주 슬롯에서 자동 운반 그립을 풀지 정한다. 명시한 설정을 현재 게임플레이 스타일, 애니메이션 스타일, 전직, 기본 직업 순으로 찾는다. 덮어쓰기를 켠 빈 목록은 해당 스타일에서 자동 해제할 슬롯이 없음을 뜻한다. 별도 설정이 없으면 Spellblade의 기존 `DefaultSlot`, `UpperBody`, `CastUpperBody`가 적용된다. 슬롯 목록은 이미 연결된 몽타주에만 적용된다. 새 슬롯을 사용하려면 해당 스켈레톤과 AnimGraph에도 등록해야 한다.

설정된 슬롯의 몽타주가 시작되면 왼손은 해당 포즈를 따르고, 블렌드아웃의 남은 가중치에 맞춰 운반 접촉이 돌아온다. 동작 중 양손 접촉이 필요하면 `LeftHandIK` 커브나 양손 그립 노티파이 구간으로 지정한다. 독립 무기 모션과 접촉 복귀는 각자의 접촉 규칙을 사용한다.

Longblade 공격 데이터 29개와 관련 몽타주 34개에서 기존 추가 왼손 IK 커브와 양손 그립 노티파이를 조사했다. 현재 무기를 붙인 포즈에서 손바닥이 벗어나 있더라도 원본이 손을 놓는다는 뜻은 아니다. 원본의 손과 무기 사이 상대 변환이 유지되는 구간을 먼저 찾고, 실제 몽타주가 사용하는 세그먼트와 몸체·검에 대조한다. 접촉 요청이 없고 해제 보간이 끝난 프레임에는 왼손목 목표 변환을 생성하지 않는다.

단독 PIE에서 전투 정지 및 W/A/D 이동 69개 표본의 왼손 그립 가중치는 모두 1이었다. 정면 이동 대시, 기본 1타, 공중 V, Z/X/C의 시작 직후 이전 평가 프레임을 제외한 본 구간 656개 표본은 가중치 0이며 유효한 왼손목 목표가 없었다. 각 동작 종료 뒤 전투 운반 그립이 복귀했다.

정면 이동 대시 원본의 손·검 상대 회전은 시작 프레임 대비 약 2.2° 이내이고 준비 루프 시작과는 약 173° 차이가 난다. 대시용 역그립을 `AS_SpellbladeDirect_MovementDash`의 양손·왼팔과 `Bip_Weapon_R`에 저작했다. 대시 몽타주는 기존 Weapon Motion 상태에서 이 무기 본을 사용한다. 양손 IK 가중치는 0이고, 일반 장착으로 복귀할 때 기존 접촉 핸드오프를 사용한다. 진입과 종료 블렌드 사이인 0.090–0.390초에 무기 본이 검을 구동한다. 공용 손바닥·검 그립 소켓은 운반 자세에서 사용한다. 시퀀스의 120Hz 표본에서 왼손바닥 접촉 오차는 최대 0.183cm와 0.433°였다.

전용 서버 PIE의 평지 대시 본 구간에서 왼손바닥과 검 손잡이의 오차는 최대 0.142cm였고 양쪽 손 IK는 0이었다. 진입과 종료를 포함한 표본의 칼끝은 바닥에서 최소 42.6cm 위에 있었다. 진입 직후에는 장착이 넘어오는 동안 손과 손잡이가 잠시 벌어졌으며, 본 구간과 구분한다. 종료 후 운반 그립이 복귀했고 서버·클라이언트 위치 차이는 0.002cm 이하였다.

활성 세그먼트 후보에는 발도의 후반, 기본 2타 후반, 공중 V의 복귀, Flurry 4와 일부 Bash의 복귀가 있다. 원본에서 손과 무기가 함께 움직이는 구간의 후보이며 각 동작의 손바닥 방향과 칼끝 궤적을 별도로 확인한 뒤 적용한다. 시전 손과 타격 때 분리되는 손은 원본 동작의 자유도를 유지한다.

후속 적용에서는 발도 후반, 납도 시작, Bash 1·3의 타격 이후를 양팔·손가락 키로 저작했다. 발도는 몽타주 진입이 끝난 뒤 기존 손 장착을 사용하며, 1.61초부터 접근해 1.93초에 준비 그립에 도달한다. 납도는 준비 그립에서 출발해 첫 0.30초 안에 왼손을 푼다. Bash는 소스 시퀀스의 8배속 구간을 포함하므로 그립 보간을 몽타주 재생 시간으로 환산했다. 바뀐 네 시퀀스의 120Hz 표본에서 그립을 잡는 구간의 왼손바닥 위치 오차는 최대 1.51cm였고, 기존 머리·척추·하체·루트 위치는 동일했다. 공중 V, 기본 2타, Flurry 4, Bash 2·4는 팔 도달 범위, 손 경로 이동량 또는 실제 복귀 속도를 기준으로 시험본을 적용하지 않았다.

최종 평지 PIE의 접촉 구간에서 왼손바닥 오차는 발도 0.01cm 미만, 납도 1.11cm, Bash 1·3 각각 0.40cm와 0.03cm였다. 발도·납도와 공중 V는 Enhanced Input으로 확인했고 Bash 1·3은 해당 몽타주를 직접 재생해 손과 검의 궤적을 확인했다. 네 수정 구간의 왼손 IK 가중치는 0이었다.

240Hz 시퀀스 검사에서는 X 진입 시 원본 키와 압축 평가가 같았다. PIE에서 손 접촉을 끈 비교에서는 같은 구간의 쇄골 트위스트 최고 속도가 1,368→212°/s였다. 이미 합성 가중치가 사라진 운반 접촉이 두 번째 보간에 남아 왼팔을 당겼다. 운반 가중치를 포즈 블렌드에서 직접 가져오고 장비 및 액션 접촉의 보간을 별도로 유지한다. 몽타주와 제작된 운반 포즈가 겹칠 때 순수 운반 접촉만 손바닥의 거리 4–12cm에서 점진적으로 풀린다. 최종 PIE에서 X 진입의 견갑 트위스트 최고 속도는 정지 1,480→210°/s, 이동 1,388→187°/s였다. A/D와 시전 중단 후 안정 구간의 왼손 위치 오차는 표기 정밀도에서 0.00cm였다. 최종 23개 입력 시나리오 중 Z/X/C의 정지·이동·중단 9개 사례에서 견갑과 얼굴의 교차는 2,692개 기록 프레임에서 0건이었다. X 진입의 변형 머리 본 최고 속도는 접촉을 끈 대조에서 약 513°/s, 최종 실행에서 약 512°/s였다.

이동 클립의 과한 숙임은 제작 단계에서 흉추 피치부터 정리한다. 그 흉추 기준으로 머리·목과 양팔을 함께 옮긴 다음 시선과 그립을 작성한다. 준비 포즈가 가슴·머리의 비교 기준이며 골반과 하체 포즈는 공용 이동에서 평가한다. 수정 전 루프와 링크드 레이어 복원 매핑은 `SpellbladeGazeBefore_*`에 있다.

최종 렌더링 PIE에서 정지 가드의 가슴·머리 피치 중앙값은 이전 준비 자세 기준 약 −20°에서 0° 부근으로 복귀했다. A/D 지속 이동의 가슴 대비 머리 피치 중앙값은 각각 31→25°, 52→23°였다. Z/X/C 여섯 조건의 완료 효과는 적용됐고, 시전 복귀의 가슴 상대 머리 각속도는 조건마다 차이가 있었다. 전후 값과 옆모습은 중앙 ArchiveStore의 `SpellbladeGazeFinalVerification` 및 `RenderGazeFinal`로 확인할 수 있다.

렌더링 PIE의 정지·네 방향 이동·정지 복귀 153개 표본에서 왼손 위치·방향 오차는 각각 0.01cm와 0.01° 미만이었다. Z/X/C 및 기본 공격의 본 구간에서 운반 가중치는 0.07 이하였다. 납도 및 발도 취소 뒤 등 부착 표본의 운반 가중치는 0이었다. 운반 클립에서 뼈 기준 자세 대비 손목 축 회전 최대치는 약 175°에서 32°로 줄었다. 실행 기록과 저장 전 6개 패키지의 복원 매핑은 중앙 ArchiveStore에서 `LongbladeGrip` 및 `LongbladeGripBefore_*`로 찾을 수 있다.

후속 렌더링 PIE에서 A/D 초기 이동의 왼손 꺾임 최대치는 각각 54→39°, 54→46°였고 후진은 122→38°였다. D의 초기 이동 중앙값은 22→44°였다. 이 비교에서 손목 꺾임은 손의 기준 자세 축과 전완 사이의 각도다. 정착한 D 이동의 준비 자세 대비 가슴 회전 중앙값은 177→0°, D→A 반전 뒤에는 −11→3°였다. 실제 하체에서 `Loop_LL`, `Loop_RL`, `Pivot_RL_LL`이 평가되는 것을 확인했다. 평지 20개 사례와 정지·이동 시전 효과를 재검증했다. 새 무기와 리그 조합, 경사, 원격 플레이는 이 검증 범위 밖이다. 이번 검증 기록과 이전 루프·레이어 복원 매핑은 `SpellbladeWrist` 및 `SpellbladeWristBefore_*`로 찾을 수 있다.

`DA_CombatStyle_SpellbladeKit`의 `Lock Facing During Swing`은 공격 노드가 실제로 시작될 때 카메라 수평 방향을 읽고, 해당 타의 재생 중에는 카메라 입력이 몸 방향을 바꾸지 않게 한다. 버퍼 입력의 방향을 저장하지 않으므로 다음 타는 전환이 승인된 시점의 방향을 사용한다. 질주 공격은 이동 입력으로 방향을 잡는다. 잠금은 실행 중인 근접 어빌리티의 수명을 따르며 피격·취소·장비 해제 후에는 정상 조향으로 돌아간다. 루트 키의 회전과 무기 포즈는 애니메이션이 계속 소유한다.

## 콤보·복귀·연출 제작 기준

- 커맨드 세트가 입력 조합을 선택하고, 콤보 그래프가 연계 목적지를 선택한다. 일반 베기는 휘두르기 직후 창을 열고 버퍼된 입력을 소비한다. 후속 입력이 없으면 남은 짧은 복귀가 재생된다. 새 직업이나 무기는 해당 세트의 커맨드와 그래프에서 같은 원시 입력을 다르게 해석할 수 있다.
- 기본 1·2·3타 원본은 `pdw_01_01_att_normal_01`, `pdw_01_01_att_normal_02`, `pdw_01_01_att_normal_r_02`다. 3타 후보 `normal_03`에는 도약이 있어서 접지 자세를 유지하는 `normal_r_02`를 선택했다.
- 몽타주 노티파이가 연계·타격·연출의 제작 시점을 표시한다. GAS가 플레이어 근접 공격을 실행 중이면, 큐 방식의 타격·연출 노티파이도 콤보 창과 같은 몽타주 실행 식별자 검사를 통과해야 한다. 공격이 특정 섹션을 재생하는 경우 섹션도 확인한다. 유효한 자연 블렌드아웃을 허용하고, 종료는 발급받은 실행별 토큰으로 처리한다. 서버가 판정을 확정하고, 연출은 기존 복구 상태와 Niagara 프로필을 사용한다.
- 공격 판정과 콤보 창 이후 정지 자세가 길면 몽타주의 해당 구간만 조정한다. 원본 시퀀스, 타격·연계 타이밍, 복귀 포즈는 보존한다. 새 공격은 복귀 동작과 이동 허용 시점을 함께 검수한다.
- 검 공격 몽타주의 `Spellblade VFX` 트랙에 연출 창을 둔다. 일반 검 공격은 `Trail`, R/T는 `Release`를 사용한다. 두 큐는 현재 같은 Niagara 시스템을 `WeaponGroundProbe_Tip`에 붙인다. 프로필에서 별도로 교체할 수 있다. 판정은 서버의 기존 melee sweep에서 처리한다.

[복귀 구간 제작 스크립트](../../../Scripts/Authoring/Trim-SpellbladeRecovery.py)는 실제 연결된 공격 몽타주에서 타격·연계·연출 이벤트와 루트 이동이 끝난 뒤에만 블렌드아웃을 허용한다. 원본 시퀀스의 복귀 포즈는 보관한다. T의 타격 창은 2.51초에 끝나고 몽타주는 3.04초에 종료하므로 강공격의 짧은 회복 구간이 남는다. 이 조정은 일반 복귀 시간에 적용한다. 공격 진행 중 대시 취소와 입력 버퍼는 별도 정책이다.

후속 `Project_JSpellbladePolish` 적용에서는 위 표의 트림을 출발점으로 지상 공격의 원본 꼬리를 최대 0.22초 연장하고, 자연 블렌드아웃을 길게 했다. 타격·콤보 노티파이와 블렌드아웃 시작은 기존 시간에 둔다. 위 스크립트는 이전 트림 시점의 제작 기록이다.

## 발도·납도

Longblade 장비 → Longblade 전투 스타일 → `DA_SpellbladeKit_WeaponProfile`에서 전용 전환 몽타주를 선택한다. 발도·납도는 실제 몸체에 맞춰 오프라인 리타깃한 `AS_SpellbladeDirect_Draw`와 `AS_SpellbladeDirect_Sheathe`를 기존 `UpperBody` 슬롯에서 재생한다. 두 시퀀스의 루트 모션은 꺼져 있고 GASP가 하체 보행을 유지한다. 공용 무기 부착 노티파이가 같은 무기 액터의 위치를 전환한다. 손으로 옮긴 후 발도가 중단되면 기존 전환 종료 경로에서 다시 등에 부착한다. 장비 상태와 능력 부여는 기존 장비 시스템이 처리한다.

Z·X·C는 `Greatsword_A`의 원본 모션을 실제 Spellblade 몸체로 직접 리타깃한 시퀀스에서 작성한다. `GreatSword_Test`는 원본 메시·리그의 출처다. 시전은 원본과 리타깃의 흉추 기준 머리 속도를 비교했고 두 결과의 최대치가 유사했다. 이전 몽타주의 구간별 가속은 이 움직임을 최대 4.6배로 재생했다. `-ApplyDirectBodyUpperMontages`는 목과 머리 궤적을 흉추 기준으로 다듬은 `AS_LongbladeCast_*`를 `CastUpperBody`에 1배속 단일 구간으로 연결한다. 준비 자세에서 0.38초에 걸쳐 들어가고 복귀 블렌드는 0.40초다. 원본 및 리타깃 원자료는 제작 비교에 사용한다. `-VerifyDirectBodyUpperMontages`는 실제 스타일의 발도·납도·시전 경로를 다시 연다.

`-ApplyCastLayer`는 시전 슬롯을 마스터 그래프의 이동 기울기와 조준 오프셋 뒤, 최종 포즈 캐시 앞에 설치한다. `spine_01`부터 20%씩 올려 상부 흉추와 쇄골·팔·목에는 시전 포즈를 적용하고, 회전은 캐릭터의 루트 기준으로 합성한다. 골반과 다리는 이동 포즈가 구동하고 접촉 솔버는 최종 몸체에서 실행된다. `UpperBody`는 발도·납도 및 해당 슬롯을 쓰는 공격을 담당한다. 제작 시 `-VerifyCastLayer`와 `-VerifyDirectBodyUpperMontages`로 구조와 참조를 함께 확인한다. [Lyra 상하체 레이어](https://dev.epicgames.com/documentation/unreal-engine/animation-in-lyra-sample-game-in-unreal-engine), [ALS Refactored 제작자의 합성 설명](https://github.com/Sixze/ALS-Refactored/discussions/19), [GASP와 Mover를 사용한 커뮤니티 구현](https://github.com/SAM-tak/GASP-ALS-R), [상체 합성 회전 재현 사례](https://forums.unrealengine.com/t/layered-blend-per-bone-rotation-issues/1033630)

이전 `Idle02` 수정 및 발도·납도 목 배분의 표본은 중앙 ArchiveStore의 INDEX에서 `UpperBody`로, 원본 준비 자세 및 시전 시간 비교는 `LongbladeMotion`으로 찾을 수 있다. 교체 전 에셋 복원 매핑은 `LongbladeMotionBefore_*`를 사용한다.

렌더링 PIE 14개 사례에서 양손 준비, 네 방향 이동과 정지 복귀, Z/X/C 효과 적용, 기본 1타, 발도 중단과 재발도를 확인했다. 정지 중 양손 그립 위치 오차는 표본에서 0.01cm 미만이었다. 7–25ms 프레임 구간의 흉추 상대 머리 최대 속도는 Z 1066→305°/s, X 852→524°/s, 이동 중 C 1033→399°/s였다. 전진의 칼끝 프로브 최저점은 평지 기준 −8.4→+15.3cm였다. 시전과 기본 1타 일부의 칼끝 관통은 남아 있다. 원격 플레이, 경사 및 전체 콤보 검증은 별도다.

시전 레이어 교체 후 렌더링 PIE 19개 사례에서 정지·이동 중 Z/X/C의 완료 효과와 운반 자세 복귀, 기본 1타, 발도·납도·발도 취소 및 재발도를 확인했다. 시전 시작과 복귀를 제외하고 같은 몽타주 시각의 리타깃 클립과 비교했다. 여섯 조건에서 상부 흉추·양쪽 쇄골·머리의 루트 기준 회전 오차 중앙값은 14–58°에서 0.2–0.7°로 줄었다. 전방 대시 두 번의 950cm 도달은 0.44–0.45초에서 약 0.40초로 단축됐고, 몽타주 종료 시 이동은 약 1,000cm였다. 측면 대시와 원격 플레이는 이 비교의 범위 밖이다. 검증 기록은 중앙 ArchiveStore에서 `SpellbladeCast`로, 교체 전 일곱 패키지 복원 매핑은 `SpellbladeCastBefore_*`로 찾을 수 있다.

| 전환 | 몽타주 | 무기 부착 |
| --- | --- | --- |
| 발도 | `AM_SpellbladeKit_Draw` | `Bip_Weapon_R_Attach_In` → 오른손 그립 |
| 납도 | `AM_SpellbladeKit_Sheathe` | 오른손 그립 → `Bip_Weapon_R_Attach_In` |

새 무기에서는 장비 프로필의 발도·납도 슬롯과 전용 상체 레이어를 같이 검수한다. 전환 시점의 손바닥과 실제 등 그립이 어긋나면, 전환 클립에서 해당 손의 닿는 구간을 보정한다. Longblade는 발도 0.70초와 납도 1.07초 주변의 오른팔 키를 실제 등 그립에 맞춰 오프라인 베이크했다.

`longblade`와 `aiguillette`의 발도·납도 메시 네 개가 `M_Spellblade_Weapon`을 사용한다. 원본 `aiguillette`는 검과 함께 움직이는 보조 파츠다. 앞·좌·우 원본의 `Bip_Weapon_R` 회전을 손목과 검지·중지·새끼손가락이 만드는 손 좌표계로 옮겨 비교했다. 세 방향에서 같은 장착 회전이 나왔고, 이전 `WeaponGrip_R_Aligned` 회전과는 약 158.6° 차이였다. 발도 메시의 소켓 회전과 해당 공격들의 칼끝 오프셋을 함께 보정했다. 현재 정지와 이동은 같은 준비 그립 계열을 사용한다.

그립 각도는 Unreal의 Output Log에서 `py "<프로젝트 폴더>/Scripts/Authoring/Preview-SpellbladeGrip.py"`를 실행해 미리 본다. 레벨 뷰포트에서 `F`로 선택된 Spellblade에 초점을 맞춘다. 캐릭터 공통 각도는 `SK_Spellblade_Complete`의 `PalmGrip_R`, Longblade에만 필요한 각도는 `SK_Spellblade_longblade`의 `WeaponGrip_R_Aligned`에서 조정한다. 프리뷰는 실제 장착과 같은 손 접점, 무기 루트 기준과 장착 계산을 사용하며 저장 전 회전도 반영한다. 같은 명령을 다시 실행하면 프리뷰가 닫힌다. 각도를 확정한 뒤에는 발도·납도, 왼손 접점과 공격 데이터의 칼끝 오프셋을 확인한다.

왼손목 회전을 보존하는 다섯 지속 가드에서는 `WeaponGrip_L`의 0° 회전도 유효하다. 이 경우 접점 위치를 검증하며, 제작 키가 이미 정한 손목 회전에 맞춰 소켓을 다시 회전시키지 않는다.

## 공격 루트 모션

현재 Longblade 공격과 이동 대시는 기존 GAS 몽타주와 Mover의 레이어드 이동을 사용한다. 원본의 기본 베기 1~3타 `Bip01`은 한 클립 안에서 수평으로 최대 약 14~20cm 움직이지만 클립 끝에 누적되는 이동은 0~8cm 수준이다. 대시 반복 클립의 수평 루트는 정지 상태다. 이 테이크들은 발과 골반 움직임을 기준으로 실제 게임 이동 키를 별도 제작했다. 편집기 데이터 검증은 루트 모션 정책을 지정한 공격 몽타주에 해당 시퀀스 설정이 빠졌으면 오류를 낸다.

| --- | --- | ---: |

| 우클릭 | 0.27–0.64초 | 60cm |

현재 공격과 이동 대시는 시간과 누적 거리를 제작 키로 관리한다. 중간 키를 통과할 때 앞뒤 구간이 같은 속도를 공유하게 하고, 이동의 시작과 끝에서만 속도를 0으로 내린다. 기본 1·2타와 찌르기의 전진은 다음 연계 창 전에 끝난다. 이동 대시의 1,000cm 키는 시퀀스 0.315초에 도달한다. 재베이크는 현재 장착 스타일이 재생하는 시퀀스를 찾아 루트의 XY 키만 교체한다. 후속 렌더링 PIE에서 전방 950cm 도달은 약 0.40초에서 0.352초로 단축됐고 몽타주 종료 이동은 1,000cm였다. 후속 조정 직전 패키지는 `SpellbladeDashBeforeFollowup_*`으로 복원할 수 있다. [루트 제작 스크립트](../../../Scripts/Authoring/Refine-SpellbladeRootMotion.py)

Caps 확장 7개 타격 시퀀스와 E Flurry 4타·복귀는 `Project_JSpellbladePolish -ApplyAttackTravel`로 별도 제작한다. 원본 최상위 본의 XY를 첫 프레임 기준으로 추출하고, 원본의 높이와 회전은 루트 바로 아래 본에 옮긴다. Mover가 캡슐을 이동시키는 동안 메시 루트는 고정된다. Mover의 추출은 자연 블렌드아웃이 시작되면 끝나므로, 마지막 발걸음까지 이동이 있는 몽타주는 마지막 키에서 블렌딩을 시작한다. E 1~3타는 이미 있던 58/36/26cm 이동 키에 공격 데이터의 정책을 맞췄다. F 발차기는 시작과 종료의 지지 위치가 비슷해서 체중 이동을 포즈에 유지한다. `-VerifyAttackTravel`은 활성 공격의 데이터 정책과 몽타주가 일치하는지, 새 이동이 수평으로 추출되는지 확인한다.

공중 공격은 `State.Movement.InAir`로 선택한다. 공중 좌·우클릭은 상체 슬롯의 수평 이동과 Mover의 중력·착지를 사용한다. 공중 V의 `Project_JMontageVerticalMotion` 메타데이터는 원본 하강 구간만 Mover에 넘긴다. 기존 낙하 모드의 충돌·착지 판정은 계속 실행되고, 루트 구간 이후 아직 공중이면 중력이 다시 이어진다. 원본의 착지 후 웅크림과 일어나는 높이 변화는 포즈에 남긴다. 시각 무기는 오른손 포즈에서 구동한다. 검 판정은 Leader의 `hand_r`에 붙은 `PalmGrip_R`과 Longblade 그립 기준의 칼끝 오프셋을 사용한다. 서버는 기존 melee sphere sweep을 평가한다. 기존 대검의 `ik_hand_gun` 기반 소켓은 대검에서 계속 사용한다.

디딤을 검수할 때는 접지 후보 발의 바닥 기준 변위와 캡슐 이동을 함께 본다. 여러 시퀀스를 일괄 샘플링한 뒤, 발볼이 낮은 상태가 연속된 구간을 후보로 모아 같은 구간에서 수정 전후를 비교한다. 발볼 높이만으로 발이 고정된 순간을 확정할 수는 없다. 발을 바꿔 딛거나 발끝으로 회전하는 구간은 별도로 본다. 경사, 장애물에 막힌 발, 회전 중 디딤은 플레이에서 별도로 확인한다.

위 수치는 저장된 시퀀스를 24Hz로 평가한 결과다. 2·3타의 반대 발 전후 이동 폭은 각각 0.7·0.8cm, T의 반대 발은 2.8cm 증가했다. 발끝 회전과 옆 디딤은 포즈에 남겼다. 우클릭 강공격은 47cm 안에서 곡선만 옮겼을 때 대표 구간 변위가 거의 같아 이동 거리를 60cm로 늘렸다. 이 동작의 접지를 더 다듬으려면 디딤 포즈도 함께 검토한다. 공중 공격은 타격 구간에 맞춰 수평 이동을 배치하고 착지는 플레이에서 따로 확인한다.

## 입력 실측과 연결 기준

Unreal의 저장된 `IMC_Default`에서 F는 `IA_Interact`, Left Shift는 `IA_Sprint`, 좌·우클릭은 기존 공격 IA, Q/R/T는 기존 스킬 IA다. 제작 전 `IMC_Default` 및 `IMC_MouseLook`에서 E/Z/X/C/V 매핑이 비어 있는 것을 확인했다. UI·탑승·캐릭터별 추가 컨텍스트의 점유는 별도 실기 검증 항목이다.

초기 제작은 Z로 4연격을 시작했고, 실제 키로 Finisher, Kick, Flurry 1→4를 전용 서버 PIE에서 확인했다. 마지막 Flurry는 전용 복귀 뒤 공격 상태를 해제했다. 후속 제작에서 E/X/C의 액션을 추가하고, 4연격의 진입을 E, 버프를 Z/X/C로 배치했다.

F는 기존 상호작용 바인딩에서 한 번 처리한다. 유효한 지상 Longblade 전투 커맨드가 F를 소유하면 발차기로 전달하고, 그 외에는 기존 상호작용으로 전달한다. Shift+우클릭은 입력 조합 우선순위에서 결정하고 실제 질주 여부와 분리한다. 질주·공중 공격은 Mover의 이동 상태와 유효한 장비 스타일에서 승인한다. 콤보 중에는 현재 노드에 작성된 전이를 사용한다.

## 연결 전 검수

새 Unreal 프로세스에서 54개 패키지와 BS 샘플 10개를 재확인했다. 30개 시퀀스 각각에서 17개 시점의 본 변환을 평가했다. 대표 발차기의 무기 기준 본과 오른손 본 사이 거리는 원본 7.4–14.4cm, 초기 변환 88.2–119.0cm였다. 별도의 미저장 리그에서 명시적 무기 FK 체인을 시험한 결과도 64.8–105.8cm여서 이 매핑은 채택하지 않았다. 이는 본 사이 거리이며 메시의 칼 손잡이 접촉 측정은 아니다. 최종적으로 원본 무기 프레임의 시간별 움직임과 새 무기의 실제 손잡이·등 부착 축을 함께 검수해야 한다.

검토 몽타주는 원본 길이 전체를 담고 있다. 접촉 프레임을 확인한 뒤 공격 시작·활성·필수 복귀, 디딤발, 취소 구간을 설정한다. 새 무기의 실제 메시를 붙여 손·등 소켓 전환, 칼날 방향과 03→04의 연결을 본다. 공중 기술에서는 실제 착지와 몽타주 루트 이동을 구분하고 공통 GASP 이동·복귀 계약에 연결한다.

### 루트와 무릎

`Force Root Lock`의 Ref Pose 모드가 새 클립의 수직 루트 키까지 덮어쓰면서, 캡슐은 평지에서 Z 98.15cm를 유지한 채 발볼 본이 −91.38cm까지 내려갔다. 루트 XY만 베이크한 뒤 같은 지상 시나리오의 발볼 최솟값은 +1.61~+1.65cm였다. 수직 키와 골반·발볼 높이는 베이크 전후 최대 0.001cm 미만 차이였다. 이 방법은 시퀀스 자체에 적용하고 공용 AnimBP와 캐릭터 캡슐 설정은 유지한다.

원본 FBX와 Manny 변환본 30개, 2,709프레임의 양쪽 무릎을 비교했다. 최대 굽힘 차이는 2.66°, 충분히 굽힌 상태에서 인접 프레임의 굽힘 평면 회전이 원본보다 더 커진 최대치는 3.63°였다. 원본에도 단일 프레임에서 큰 굽힘 변화가 있다. `GroundSkill` 오른쪽 0.100초에서 92.72° → 92.76°, `AirLight` 왼쪽 0.100초에서 74.64° → 73.90°, `Light04` 오른쪽 0.633초에서 42.75° → 41.76°였다. 공중 공격에는 기존 상체 슬롯을 적용했고, 4타와 `GroundSkill`은 발 디딤과 착지 구간을 다시 제작할 후보로 보존한다.

실제 몸체에서 3타 1.145초 부근의 왼쪽 무릎 전후 이동은 후처리 적용 시 한 프레임 최대 44.93cm, 임시 해제 시 2.17cm였다. 튄 프레임에서 왼발 밑창 보정은 16.45cm를 적용했으며 발목 이동은 0.25cm였다. 공용 Manny에 맞춰 베이크한 포즈를 다른 다리 비율의 실제 몸체로 재생하면서 접지 보정에 큰 차이를 넘겼다. 지상 활성 7개 시퀀스를 실제 몸체의 레퍼런스 메시로 다시 오프라인 리타깃했다. 공용 하체 모션 매칭, 몸체 후처리, 망토·머리의 표현 경로는 그대로 사용한다.

같은 3연타 입력에서 왼쪽 무릎의 프레임 간 최대 전후 이동은 몸체 맞춤 베이크 전 42.87cm, 적용 후 2.72cm였다. 최종 평지 지상 시나리오 7개의 발볼 최솟값은 +1.64~+1.71cm이며 캡슐 높이는 98.15cm로 일정했다. 공중 우클릭의 발볼 최고 높이는 전신 슬롯 사용 시 367.90cm, 상체 슬롯 사용 시 111.06cm였다. 이 값은 해당 테스트 맵의 월드 Z이며, 경사·이동 발판·다른 신발·네트워크 재생은 별도 검증 항목이다.

전용 전투 점프 시퀀스와 R 홀드 차징은 미연결 후보다. 공격별 시각 무기 접촉과 원격 재생은 별도 검증 항목이다.

## 전투 Idle 자세 시안

`Project_JSpellbladePolish -TrialReadyGuard`는 현재 장비 데이터의 오른손 장착 기준과 무기의 왼손 접촉 소켓을 읽고, Ready 복제본의 양팔 포즈를 계산한다. 기존 칼 방향으로 양손 그립 전체를 가슴 쪽으로 16cm 내린 뒤 팔꿈치 방향, 양팔의 도달 거리와 이동 클립 사이의 회전 범위를 검사한다. 양팔 트랙만 베이크한다. `-SaveReadyGuardReview`를 붙이면 `SourceTransient/StanceAudit/AS_LongbladeReadyChestGuardReview`에 검토본을 저장한다. 같은 이름의 검토본이 있으면 저장을 중단한다.

검토할 때는 PIE에서만 전투 Blend Space의 속도 0 샘플 다섯 개를 시안으로 교체한다. 정면·후면 실루엣과 정지에서 이동으로 넘어가는 양손 접촉을 확인한다. 현재 런타임 경로는 공용 Master ABP, Spellblade 레이어의 쇄골 이하 합성, 무기 장착 및 왼손 접촉 보정으로 구성된다.

평지 PIE 비교에서 정지 손잡이의 머리 본 기준 높이 중앙값은 +1.3cm에서 −12.6cm로, 왼쪽 팔꿈치의 어깨 본 기준 높이는 +6.7cm에서 −3.5cm로 바뀌었다. W/A/D, 이동 후 정지, 대각선 및 W→A에서 가드가 잡힌 프레임의 양손 접촉 오차는 0.01cm 미만이었다. 왼손목 굽힘 지표의 정지 중앙값은 14.8°에서 35.6°로 늘었다.

검토 승인 후 `-InstallReadyGuardReview`로 양팔 여섯 트랙을 기존 `AS_LongbladeStance_Ready`에 옮겼다. 전투 Blend Space의 속도 0 샘플은 기존 Ready 경로를 유지하고, 이동 시퀀스·ABP·그립 소켓에는 변경이 없다. 교체 전 시퀀스는 중앙 보관소의 `SpellbladeReadyInstallBefore_*`로 복원할 수 있다.

설치에 썼던 검토용 시퀀스도 중앙 보관소로 옮겼다. 활성 Blend Space는 설치된 Ready를 사용한다. 검토본이 다시 필요하면 중앙 명세에서 원래 `SourceTransient/StanceAudit` 경로로 복원하거나, 현재 자세를 기준으로 새 시안을 생성한다.
