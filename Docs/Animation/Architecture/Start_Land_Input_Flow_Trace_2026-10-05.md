# Start·착지 입력 변경의 실행 흐름 진단 — 2026-10-05

## 목적과 범위

Start·착지 도중 WASD 또는 카메라 방향을 바꿀 때 어느 계층이 동작을 유지·취소하고, 외부 Blend Stack에서 MM으로 언제 복귀하는지 확인한다. 이번 변경은 읽기 전용 진단이다. 선택 정책, 취소 임계값, 블렌드 시간, ABP·PSS 에셋을 변경하지 않는다. 자연스러움 개선이나 실제 플레이 검증을 완료했다는 뜻은 아니다.

## 사용

Development 에디터의 콘솔에서 `p.ProjectJ.AnimFlow 1`을 실행한다. 기본값은 `0`이고 Shipping에서는 로그 기능을 제외한다. 기본 대상은 로컬 제어 캐릭터의 공용 소스 메시다.

- `1`: 상태·선택 리비전·입력 유무·누적 제어 yaw 3도 변화는 즉시 기록한다. 일회성 동작 도중과 마지막 변화 뒤 1초는 최대 10Hz로 추가 기록한다. 즉시 변화 기록에는 10Hz 제한을 적용하지 않는다.
- `2`: 위 기록과 함께 안정된 Idle/Cycle도 10Hz로 기록한다. 장시간 켜 두지 않는다.
- `p.ProjectJ.AnimFlow.Actor BP_GreatSword_C_0`: 정확한 액터 객체 이름으로 제한한다. 명시적 이름을 설정하면 해당 원격 캐릭터도 허용한다. 이름은 월드마다 다를 수 있다.
- `p.ProjectJ.AnimFlow.Actor ""`: 로컬 캐릭터 선택으로 돌아간다.
- `p.ProjectJ.AnimFlow 0`: 기록을 중지한다.

`Saved/Logs/Project_J.log` 또는 해당 세션 로그에서 `AnimFlow`를 찾는다. 문제가 발생한 전후 약 2초와 입력 순서를 함께 보관한다. 로그는 기본 비활성이고, 진단을 위해 숨김 캐릭터를 깨우거나 검색 요청을 만들지 않는다. 군중 성능 측정은 진단을 끈 상태에서 수행한다.

## 기록의 의미

| 기록 | 확인 대상 |
| --- | --- |
| `Decision` | 기존 분기에서 실제 발생한 Start·Land의 종료 판단, 표시 hold 진입·종료, 입력 각도 취소. 같은 프레임의 상태 계층과 표시 계층을 구분한다. |
| `Published` | 최신 공개 snapshot, 이동·착지 리비전, 로컬/복제 역할, 예산 tier, 이동·제어·목표 yaw, 궤적 유효성과 나이. `Fresh=0`은 숨김 등의 샘플 생략 경로에서 정책을 재전달한 기록이다. |
| `Policy` | 일회성 동작 선택·요청 리비전, 표시 override, 선택 시작 시간, 추정 경과·잔여 시간, EarlyTransition, 방향 보정 허용 조건, 제어 yaw 변화와 취소 기준, 요청 PSD. |
| `Evaluated` | worker가 소비한 snapshot 번호, 그래프 traversal 수, 강제 재검색의 실제 소비 수와 요청 번호, 대표 MM 캐시 결과, 소스 메시의 접촉·워핑 커브. |
| `ExternalStack` | 평가 후 생성 ABP에 있는 외부 Blend Stack의 실제 재생 시간·애셋·활성 여부·블렌드 가중치. 최대 8개 스택, 각 첫 2개 플레이어만 기록한다. |

`Snapshot`은 이 진단 세션의 전달 순번이다. `WorkerSnapshot`/평가의 `Snapshot`과 비교해 새 입력이 실제 업데이트에 도달했는지 본다. 같은 프레임 여러 계층을 비교할 때 `Frame`과 `Actor`를 함께 사용한다. `Published`가 항상 실제 평가 직전에 호출되는 것은 아니므로 순번과 소비한 snapshot의 프레임도 함께 확인한다.

`ReselectSearches`는 강제 재검색 요청을 처리하면서 하나 이상의 노드가 실제 검색을 수행한 횟수다. 전체 정기 검색 횟수나 노드별 검색 횟수가 아니다. 선택 애니메이션이 그대로여도 실제 검색이면 증가한다. `Traversals` 증가만으로 검색했다고 판정하지 않는다. 비활성 노드와 포즈 히스토리가 없는 업데이트는 검색 성공으로 세지 않는다. `FromHistory`는 마지막 확인된 강제 검색 요청이 외부 포즈 히스토리 질의를 요구했는지 나타낸다.

`Policy`의 `ReselectPending=1`은 아직 필요한 실제 검색이 남았다는 뜻이다. `ReselectRequest`는 처리 후에도 비활성 노드의 이후 소비를 위해 유지될 수 있으므로 번호가 존재하는 것만으로 미처리 상태라고 판정하지 않는다. `ReturnQuery`는 해당 요청의 포즈 히스토리 요구이고 `Evaluated`의 `FromHistory`는 마지막 실제 검색의 기록이다.

`CachedAnim`은 대표 MM 노드의 저장된 결과이며 최종 화면 기여를 보장하지 않는다. `ApproxElapsed`도 외부 스택의 실제 시계가 아니다. `ActualTime`이 반복해서 시작 시간으로 돌아가는지 별도로 비교한다. `LastInputWorld`는 소비된 월드 공간 이동 입력이며 원시 WASD 이벤트가 아니다. 원격 `ControlYaw`도 실제 마우스 이벤트가 아니라 복제된 제어 방향이다.

`OrientationGate`, `TIPSteeringGate`는 C++의 허용 조건이다. 개별 ABP 노드의 최종 alpha, 콜백 실행, MM 내부 스택, 리타깃 후 최종 몸체 포즈는 이 로그만으로 확인할 수 없다. 해당 단계는 Animation Rewind/노드 디버그와 정상 속도의 화면 비교로 확인한다.

## 먼저 재현할 입력

OTM과 Strafe를 각각 다음 순서로 비교한다. 각 전환의 초반·중간·종료 직전에 입력을 바꾸고, 입력하지 않은 경우를 기준으로 둔다.

1. 정지 → Start 중 카메라만 천천히/빠르게 회전. WASD 유지 상태의 회전도 별도로 실행한다.
2. Start 중 네 방향 변경·반대 방향 변경·입력 해제. 반대 키를 겹쳐 누른 경우도 확인한다.
3. 정지 착지 후 이동 시작, 이동 착지 중 방향 변경·카메라 회전·입력 해제.
4. Start·착지 도중 OTM↔Strafe 전환. 물리적 착지 한 번에 Land 리비전 또는 실제 스택 재생이 반복되는지 확인한다.

## 판단 전에 고려할 점

- 이동 상태 종료와 표시 hold 종료는 별도 책임이다. 취소가 늦은 경우와 취소는 됐지만 포즈 연결이 거친 경우를 구분한다.
- 카메라 회전은 OTM의 이동 방향과 Strafe의 바라보는 방향에 다르게 영향을 준다. 월드 입력 yaw와 제어 yaw를 같은 의미로 해석하지 않는다.
- 작은 방향 보정과 반대 방향 Pivot의 역할을 구분한다. 이미 확정한 Pivot은 기존 이동 의도 기준을 유지한다.
- `EarlyTransition`·접촉 커브의 실제 자산 존재와 외부 스택 시계를 확인한다. 선택 리비전 변화와 같은 자산의 재시작도 구분한다.
- 몽타주·루트 모션·점프/착지·가이트 변경의 소유권을 지킨다. 취소 반응만 빨라져도 공격·착지가 중복되거나 발이 미끄러질 수 있다.
- 오래된 snapshot, 저프레임, 원격 복제 간격, tier 전환을 고려한다. 재검색 요청은 실제 필요한 업데이트까지 보관하고 snapshot 자체는 최신 것으로 교체한다.
- MM 복귀 첫 검색이 직전 외부 자세·속도와 이어지는지 확인한다. 즉시 검색과 애니메이션 이름 변화만으로 자연스러움을 판정하지 않는다.
- 최종 리타깃 몸체의 발 접지·골반/발 회전·방향 응답 지연은 화면/포즈 기록이 필요하다. 이 진단은 자연스러움 점수를 산출하지 않는다.

## 구현 위치

`Project_JCharacterAnimInstance.FlowTrace.cpp`는 게임 스레드에서 로그와 외부 스택 읽기를 담당한다. proxy에는 읽기 전용 세션 카운터만 추가한다. 상태·입력 취소 분기에는 이유 기록만 연결하며 기존 분기 조건을 유지한다. 샘플러의 시간 리셋·yaw wrap·재활성화와 실제 엔진 검색의 진단 카운터를 자동 테스트로 검증한다.

## 이번 검증

직접 UnrealBuildTool.exe로 `Project_JEditor Win64 Development` 빌드가 성공했다. NullRHI 자동 테스트 11개가 성공했고 실패는 0개다. 범위는 새 FlowTrace 샘플러, 실제 엔진 검색과 반환 요청 수명·worker 예산, Strafe Pivot의 네 방향·연속 역전, 방향 전환과 일회성 동작의 모드 연속성이다. 보고서는 `Saved/Automation/AnimFlow/index.json`, 실행 로그는 `Saved/Logs/AnimFlow_Automation.log`다.

실제 플레이에서 진단을 켜고 Start·착지 입력을 재현하는 단계는 아직 진행하지 않았다. 이 검증은 ABP 콜백의 실제 실행, 최종 리타깃 몸체 연결, GASP 대비 자연스러움 개선을 판정하지 않는다.

## 사용자 실행 로그 확인: 22:10~22:11

사용자가 남긴 `Saved/Logs/Project_J.log`에서 PIE 로컬 캐릭터의 월드 시간 4.494~25.277초를 확인했다. `Published`/`Policy`/`Evaluated`는 각각 630행, 외부 스택 686행, 판단 기록 37행이다. 실제 플레이 기록은 아래 실행 흐름을 확인하며 최종 몸체의 자연스러움을 수치로 판정한 것은 아니다.

- 카메라 방향 임계값으로 Start 5회와 Land 2회가 취소됐다. Start 기준은 15도, Land 기준은 25도였다. 이 기록에는 `MoveYawThreshold` 취소가 없다. 원시 입력 이벤트를 기록하지 않으므로 WASD 단독 변경을 충분히 재현했는지는 확정하지 않는다.
- Start 취소 프레임 879/1062/1831/2004/2177의 다음 프레임에 대표 MM 가중치가 1이며 이동 Cycle DB 결과가 나타났다. 동작 중 작은 회전을 계속 보정하는 구조와 임계값을 넘으면 동작을 종료하는 구조를 구분해서 후속 조정한다.
- **이동 착지 취소가 Idle을 경유한다.** 프레임 1293과 1538 모두 속도 500, 이동 입력 활성 상태에서 표시가 Idle로 바뀌며 Idle DB를 요청했다. 첫 사례는 프레임 1294~1300에서 Idle 결과, 1301에서 이동 Cycle 결과가 나타났다. 두 번째는 1539~1545에서 Idle 결과, 1546에서 이동 Cycle 결과가 나타났다. 기록상 Idle 결과를 약 60ms 경유한다.
- 원인은 취소 분기에서 `LocomotionContext.bIsMotionMatchingMoving`으로 복귀 상태를 고르는 데 있다. `IsMotionMatchingMovingForContext`는 `bIsInAir || IsLandingStateActive()`일 때 false를 반환한다. 착지 표시를 먼저 취소한 시점에는 물리적 착지 의미가 아직 남아 있으므로 이동 중이어도 Idle로 결정된다. 착지 진행 상태와 착지 표시 취소 후 지상 이동 의도를 별도 판단해야 한다. 공통 이동 플래그의 착지 예외를 무작정 제거하지 않는다.
- 선택 유지 도중 동일 자산의 외부 재생 시간이 시작 시간으로 반복 복귀한 사례는 관측되지 않았다. MM 복귀 후 기존 외부 스택의 자산·시간이 남아 있는 것은 비활성 경로의 캐시일 수 있으므로 재시작으로 판정하지 않는다. 이 기록에는 착지 도중 OTM↔Strafe 전환이 없어서 해당 중복 재생 경로의 검증은 남아 있다.
- Strafe Start의 `OrientationGate=1`, `TIPSteeringGate=0`; OTM Start·Land의 두 gate는 0이다. 작은 방향 변화의 보정 범위가 후속 비교 대상이지만, 실제 노드 alpha와 보정량은 이 기록만으로 확정하지 않는다.
- **강제 검색 완료 판정은 추가 검증이 필요하다.** 프레임 880/1063/1294 등 실제 대표 DB·애니메이션 결과가 바뀌어도 `ReselectSearches=0`, `ReselectPending=1`이 유지됐다. 이후 traversal이 프레임당 두 번에서 한 번으로 바뀐 구간부터 완료 기록이 나타났다. 따라서 초반 카운터 0을 검색 실패로 해석하면 안 된다. 엔진은 연결 레이어에서 그래프 업데이트로 재진입할 수 있고, 현재 proxy의 arm/complete 처리는 재진입 깊이를 구분하지 않는다. 내부 traversal의 완료 처리가 외부 traversal의 검색 전에 arm 상태를 해제할 가능성을 먼저 검증해야 한다. 카운터뿐 아니라 요청 수명·검색 우회 정책도 영향을 받을 수 있다.

후속 우선순위는 이동 착지 취소의 지상 복귀 상태, 연결 레이어를 포함한 검색 완료 판정, 그다음 Start·Land 방향 보정과 중단 임계값이다. 이번 로그 확인에서는 소스 정책과 자산을 변경하지 않았다.

이후 사용자 요청으로 [착지 복귀·연결 레이어 검색 수정](Landing_Return_Linked_Search_2026-10-05.md)을 진행했다. `GroundIntent` 진단과 내부 traversal 카운터를 추가했으며, 수정 후 `Traversals`는 외부 traversal 수, `NestedTraversals`는 연결 레이어 재진입 수다. 위 실행 기록의 기존 traversal 값은 수정 전 의미로 보존한다.
