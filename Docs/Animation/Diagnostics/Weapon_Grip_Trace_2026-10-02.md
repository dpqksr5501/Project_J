임의 목표 도달은 관절 제한이나 preferred angle만으로 보장하지 않는다. 손목만 clamp하면 무기 접촉 간격은 남는다. 나머지 차이는 몸체별 공격/리타깃 조정 또는 명시적 외형 궤적 적응 정책으로 해결해야 한다. `VisualHand` 공격은 별도 손 주도 방식이지만 소스 궤적이 바뀌므로 모든 공격을 조용히 교체하지 않는다. 기존 품질 게이트와 서버 판정 소유권을 유지한다.

## 3. 공격 → Idle 팔꿈치 복귀 구분

사용자가 지적한 증상은 주로 공격 후 팔꿈치 복귀였다. 스윙 중 완전 신전의 도달 문제와 구분한다.

t=19.722~19.847 접촉 복귀는 약 0.125초인데 상체 포즈 복귀는 t≈19.972까지 계속됐다. 어깨도 크게 이동했다. 팔꿈치 각도는 88.9 → 97.3 → 94.1도, 유효 plane dot은 0.99~1.00으로 이 구간에 측정된 평면 뒤집힘은 없다. 월드 팔꿈치 속도는 약 250cm/s이며 Alpha 0 이후도 높았다. 입력 포즈 기여를 분리한 로그는 아니었다.

코드에서 자동 종료가 `Montage_IsActive`를 사용했다. 로컬 UE 5.8에서는 stopped가 목표 블렌드 가중치 0을 뜻하며 현재 기여 가중치 0과 다르다. 블렌드 아웃 진입에서 복귀가 시작되고, 당시 별도 타이머는 손목 목표를 컴포넌트 공간에 고정했다.

수정은 outgoing instance의 실제 가중치를 복귀 envelope로 쓰고 현재 독립 소스 접촉을 따라가도록 했다. 노티파이/몽타주 미확보 경로는 타이머, 명시적 0초는 snap을 유지했다. Timing에 `recoveryClock`, `sourceInstance`, `sourceMontage`, `sourcePosition`, `sourceWeight`, `sourceStopped`를 추가했다. `GetCurrentActiveMontage`에 나타나지 않는 블렌드 아웃 instance도 관찰한다.

### 체형 비율에 대한 사용자 설명

사용자는 Right Grip Alpha 연결과 임포트 팔이 원본보다 길다는 점을 설명했다. 캡처에서 원본 팔 길이는 비교 측정하지 않았다. 보이는 팔 50.63cm / 목표 72.75cm만으로 마네킹보다 길거나 짧다고 단정하지 않는다.

Palm→손목 보정은 해당 몸체 기준이며 마네킹 오프셋을 쓰지 않는다. 이 보정 자체는 상완/하완 비율과 어깨 궤적을 적응시키지 못한다. 당시 FABRIK는 프로필의 정적 Elbow Target을 사용하지 않았다. 입력 포즈 변화, 솔버 굽힘 변화, 뒤쪽 물리 영향을 구분해 진단한다. 새 가이드는 현재 pre-IK 또는 몸체 작성 가이드를 사용하고 이전 최종 IK 팔꿈치를 피드백하지 않는다.

참고: [Epic FABRIK](https://dev.epicgames.com/documentation/en-us/unreal-engine/fabrik), [IK Rig 솔버](https://dev.epicgames.com/documentation/en-us/unreal-engine/ik-rig-solvers-in-unreal-engine), [Control Rig FBIK](https://dev.epicgames.com/documentation/en-us/unreal-engine/control-rig-full-body-ik-in-unreal-engine). 로컬 `AnimNode_Fabrik.cpp`에서도 `BRS_CopyFromTarget`이 목표 회전을 tip에 적용함을 확인했다.

## 4. FABRIK 비활성 비교와 Guided 도입

사용자는 FABRIK를 끄면 팔꿈치가 자연스러워지지만 손이 무기를 놓친다고 보고했다. 접촉 보정 경로를 조사할 근거이며 특정 수학적 flip 원인을 단독으로 증명하지는 않는다.

Guided Hand IK는 현재 입력 굽힘 방향, 실제 두 구간 길이와 보정된 손목 회전으로 해석적 팔 계산을 수행한다. 이전 최종 포즈 피드백은 없다. 초기 직접 UBT와 범위 테스트 2개 통과 후 사용자가 오른팔 FABRIK 경로를 Guided로 교체해 비교했다. 팔 길이 밖 목표는 여전히 별도 문제다.

### 남은 문제와 해석 제한

- 계산 396개 중 178개가 최대 도달 경계다. 팔 50.633cm, 목표 최대 72.851cm, 손목 목표 오차 최대 22.218cm. 방향 spike와 독립인 몸체/궤적/어깨 제약이다.
- 스윙 중 최대 팔꿈치 이동은 31.295cm/~16.7ms다. 해당 입력 팔꿈치 28.075cm, 목표 61.717cm 이동이 두 쌍에서 반복됐다. 늦은 직선 방향 반전과 다른 현상이다. 빠르게 작성된 스윙이 시각적으로 잘못됐는지, 소스와 리타깃 중 원인이 무엇인지는 로그만으로 단정하지 않는다.
- HandAttached 원시 Palm–Grip 오차는 약 2.2cm다. 작성된 Body Offset을 고려한 뒤 Visual 부착/Palm 보정을 결정한다. 현재 사용자는 Idle에서 검이 약간 뜨는 모습을 보고했고 Visual 소켓 프리뷰로 부착을 조정하는 절차를 안내했다.
- 복귀 palmErr 최대 11.5cm, wristErr 12.8cm는 독립 소스 목표 기준이다. 표시 검은 Visual 부착으로 블렌드하므로 이 값이 같은 크기의 화면 손–검 분리를 증명하지 않는다.
- 약 120Hz 실행에서 Guided는 짝수 프레임, Final은 홀수 프레임으로 샘플링됐다. 이 실행에는 동일 프레임 Input/Probe/Final 비교가 없다. 이전 556개 동일 평가 비교를 이 캡처에 적용하지 않는다.
- 정지 공격 두 쌍과 Idle 복귀 후 이동만 있다. 이동 공격, 캔슬, 장비 교체, 다른 체형·무기, 원격 저빈도와 군중 성능은 검증하지 않았다.

## 7. 실제 접촉 진단 보강

기존 GripTrace 샘플에서 `[GripTrace][WeaponContact]`를 양손 접촉에 추가했다. 화면 무기의 실제 소켓을 직접 읽되 IK 목표로 사용하지 않는다.

| 필드 | 의미 |
| --- | --- |
| socketErr | 원시 Palm–실제 무기 소켓 거리(cm) |
| calibratedErr | 몸체 오프셋 적용 후 실제 접촉 거리(cm) |
| rotationErr | 보정된 실제 접촉 방향 오차(도) |
| goalGap | 보정된 실제 접촉과 독립 IK 목표 거리 |
| valid / 소켓·side·mode·alpha·액터·메시·월드·frame | 비교 대상과 시각 식별 |

누락 소켓은 valid=0, 오차 -1이다. 기존 스위치와 빈도로 제한하며 목표·알파·복제·물리·에셋은 바꾸지 않았다. 추가 후 직접 UBT가 성공했다. 이후 캡처는 물리적 접촉과 독립 목표의 의도적 해제를 구분해 분석해야 한다.

## 8. 커밋 시점 상태

Palm 기준 공통 변환, 몸체 프로필 모드, 보조 뼈 체인과 LOD/누락 정책은 구현·범위 자동화로 확인했다. 사용자가 `DA_HGP_Greatsword`를 만들고 양팔 역할/Palm 이름/Disable Contact IK를 입력한 화면을 제공했다. 런타임 ABP 할당과 노드 모드 전환 절차를 안내했으며, 바이너리 에셋의 실제 저장 연결은 사용자 에디터에서 확인한다.

Idle 부착을 Palm–WeaponGrip으로 자동 정렬하는 기능과 제한된 상체 Reach는 구현하지 않았다. 실행 소유권은 분리되어 있지만 Idle Visual 부착과 공격 접촉의 수동 작성 중복은 남는다. 다음 작업에서 공통 접촉 기준의 Idle 부착 계산을 검토한다.
