# 메인 오픈 월드 — 레벨 디자이너 인계

2026-10-19 환경 라이브러리 이관 작업 사본 기준. 레벨 제작을 인계하기 위한 안내다. **라이브러리 반입과 월드의 최종 아트 품질은 별개다.** 원경 숲·산·도시·마을·물·최종 성능은 기존 보류 상태다. 현재 자산 검증과 과거 월드 검증을 구분한다. 세부 상태는 [최신 인수인계](WORLD_HANDOFF_2026-10-18.md)가 기준이다.

## 1. 먼저 열어볼 곳과 현재 전환 상태

| 항목 | 현재 상태 / 사용 방법 |
|---|---|

WP 전용 엔진 복제 도구의 복구 후 실행 로그는 `Success - 0 error(s), 4 warning(s)`이며, 새 맵과 이전 맵의 외부 액터 패키지는 각각 2,717개다. **패키지 수 일치는 액터 내용·인스턴스 수·참조 무결성·PIE 동작의 동등성 증명이 아니다.** 전환 담당자가 새 맵의 재로드와 아래 계약을 확인한 뒤 편집 기준 맵을 확정한다.

최신 폴더 정리는 새 맵 재로드·액터/인스턴스 배치 보존·Source/도구 참조 갱신·Legacy 삭제·옛 경로 정리를 확인했다. 이후 실제 제작은 MainWorld에서 이어가되, 기존 HLOD 전환·전체 PIE·Cook·성능과 최종 아트의 보류 항목은 별도로 검증한다.

## 2. 월드의 규모와 보존해야 할 기준

- 약 8×8km이며 실제 저작 범위는 8,064×8,064m다. 현재 범위를 대륙 전체의 완성 크기로 고정하지 않는다.
- 높이 원본은 4033×4033 표본, 간격 2m의 R16이다. 원본 파일은 `Content/World/MainWorld/Source/HM_MainWorld.r16`이며, 이번 문서 작성 시 SHA256 `bc3a7957a44629beb807d4a453443e9d02e48981be0cfb93d5054432c077f8c8`을 재확인했다.
- Source 평면 좌표는 남서쪽 원점에서 동/북 방향의 m 단위다. manifest 기준 Unreal 평면 좌표 변환은 `Xcm=-403200+100×Xm`, `Ycm=-403200+100×Ym`다. 높이는 별도 R16/지형 규격을 따른다. Source 수치를 그대로 cm 위치로 붙여 넣지 않는다.
- 주요 장소는 정착지 9·사냥터 9·보스 2로 총 20곳이다. [ID 대응표](../WorldGen/01_EXISTING_TO_TARGET_MAPPING.csv)의 target_id와 stable_id가 다를 수 있다. 예를 들어 기획 S03 임업 마을의 StableID는 S04, 기획 S08 시작 취락의 StableID는 S00이다.
- 장소 이름·외형을 바꿀 때 기존 StableID를 재번호화하지 않는다. 폴더 이름 변경과 `RegionId`/`EncounterId` 변경도 별개다. 현재 `Starter.Lv1_30` 같은 내부 식별자는 남아 있으며 별도 참조 이행 없이 일괄 치환하지 않는다.
- 원본 높이·장소 ID·기존 C++ 계약을 보존한다. 산 개선은 우선 식생·재질·적합한 암석 조형과 비파괴 저작으로 검토한다. 기존 base 높이를 전체 재생성하는 작업은 별도 변경으로 다룬다.

## 3. C++와 레벨 제작의 역할

Python/JSON은 **오프라인 제작 입력과 도구**다. 게임은 이미 저장된 Landscape, Actor, Data Asset을 사용한다. JSON만 수정해도 플레이 중 배치가 바뀌는 구조는 아니다.

| 코드 / 위치 | 실제 역할 | 디자이너가 지킬 연결 |
|---|---|---|
| [WorldDefinition](../../Source/Project_J/World/Project_JWorldDefinition.h) | `UPrimaryDataAsset`. RegionId, Places, Connections, 저작 범위·seed·SourcePlanHash, 시간·스트리밍 튜닝을 보관한다. | 장소 좌표·반경·레벨·경계와 저장된 공간을 함께 유지한다. 변동 킬 수·보상·퀘스트 진행을 DA에 저장하지 않는다. |
| [WorldState](../../Source/Project_J/World/Project_JWorldState.cpp) | 서버가 시간 기준과 강우 전환 상태를 소유·복제한다. 항상 로드되는 월드 상태 액터다. | 해당 월드의 Definition 연결을 유지한다. 같은 상태를 쓰는 두 번째 관리자나 Level Blueprint 타이머를 추가하지 않는다. |
| [WorldEnvironment](../../Source/Project_J/World/Project_JWorldEnvironment.cpp) | WorldState를 읽어 태양 방향·밝기, 안개, MPC의 Rain/WorldHour를 갱신한다. Dedicated Server에서는 표현 Tick을 끈다. | State/Sun/Fog/Parameters와 ClearSunIntensity를 확인한다. PIE에서 조명이 달라지면 수동 조명값 외에 이 writer도 조사한다. 강우 상태 구현이 비·번개 이펙트 완성을 의미하지 않는다. |
| [WorldStreamingComponent](../../Source/Project_J/World/Project_JWorldStreamingComponent.cpp) | PlayerController에 추가된 로컬 WP 소스. 현재 위치와 이동 예측 위치를 준비하며 기존 Controller 소스를 끄지 않는다. DA가 없으면 추가 소스가 활성화되지 않는다. | 기본 코드값은 예측 3초·준비 반경 600m·예측 최대 600m다. 실제 DA override를 확인한다. 이 수치를 수목 표시 거리나 HLOD 거리로 사용하지 않는다. |
| [WorldEncounter](../../Source/Project_J/World/Project_JWorldEncounter.h) | 항상 로드되는 서버 보스 이벤트 소유자. NPCClass 비동기 로드·스폰과 단계·종료 정리를 담당한다. | 같은 EncounterId 소유자를 복제 배치하지 않는다. 보스 전투 자체는 NPC의 기존 GAS/AI가 담당한다. |
| [WorldAuthoringLibrary](../../Source/Project_JCharacterEditor/Public/Project_JWorldAuthoringLibrary.h) | 에디터 전용 Landscape 가져오기·높이 재가져오기·visibility patch·스플라인 리본 제작 보조다. | 게임 중 지형 생성기가 아니다. `ReimportRegionHeightmap`은 base edit layer 교체이므로 독립 레이어 편집으로 오인하지 않는다. |

보스 두 곳은 기존 인계 기준 NPCClass 미지정 상태이며 활성 전투·보상 완료가 아니다. 사냥터의 스폰·순찰 후보와 NoCollision 미리보기 경계도 실제 AI/리스폰/전투 봉쇄벽이 아니다. 연결 세부 사항은 [게임플레이 공간 통합](../WorldGen/07_GAMEPLAY_SPATIAL_INTEGRATION.md)을 따른다. 이번 폴더 정리에서는 게임 동작을 바꾸지 않았고, 이동한 Door Blueprint의 C++ 테스트 경로와 기존 테스트의 누락 include만 갱신해 에디터 빌드·집중 회귀를 통과했다.

## 4. 안전하게 편집하는 순서

1. 전환 상태를 확인하고 편집할 맵 하나를 확정한다. 작은 구역부터 WP 셀을 로드한다. 전체 월드·여러 라이브러리 에디터를 동시에 여는 것은 기존 메모리 문제를 재현할 수 있다.
2. 장소의 StableID, Source 프로필, 기존 소유 액터·PCG·수동 편집 범위를 확인한다. 건물 메시만 바꿀지 도로·입구·지형·충돌까지 바꿀지 정한다.
3. 건축·도로·숲 변경을 한 구역에서 저장하고 재로드한다. `__ExternalActors__`/`__ExternalObjects__`는 WP 저장 패키지이므로 탐색기에서 개별 이동·이름 변경하지 않는다.
4. 반복 배치 도구를 실행하기 전에 입력 경로와 덮어쓰기 조건을 읽는다. 일부 도구는 로컬 Saved 체크포인트를 소비한다. 새 PC에서 그대로 재실행할 수 있다는 보장은 없다. [제작 도구 안내](../../Scripts/World/README.md)를 먼저 확인한다.
5. 수동 편집한 구역은 Source/저작 기록과 대응시킨다. 전역 PCG Generate나 전체 builder 재실행으로 수동 수정이 보존된다고 가정하지 않는다. 현재 PCG 숲은 수동 GenerateOnDemand 흐름이다.
6. 시각 결과는 같은 카메라의 근경·중경·원경과 PIE에서 확인한다. 이동·전투·Nav·스트리밍·시각 품질의 결과를 따로 기록한다.

공급자 원본 재질은 공용 사용 여부를 확인하고, 월드 전용 튜닝은 소유 MI/복사본에 둔다. 에셋 이동·이름 변경은 Content Browser 또는 엔진 API로 수행하고 참조를 갱신한다. 20자 초과만을 이유로 공급자 이름을 일괄 변경하지 않는다.

## 5. 수목·지피가 멀리서 사라질 때

**생성 여부 → 로드 여부 → 렌더 cull/LOD → HLOD 대체 여부** 순서로 분리한다. 특정 취락의 나무만 보이는 현상과 산에 애초 나무가 없는 현상은 동시에 존재할 수 있다.

| 확인 | 판단과 후속 조치 |
|---|---|
| 해당 위치에 인스턴스가 실제 있는가 | 가까이 이동하고 해당 셀을 로드해 수량·좌표를 확인한다. 없으면 Source 마스크·고도·경사·제외 영역과 생성 결과를 조사한다. HLOD로 미생성 수목을 복구할 수 없다. |
| Low 품질에서만 줄어드는가 | 현재 설정에는 Low grass.DensityScale=0.2 / foliage.DensityScale=0.35, Medium은 각각 0.65가 있다. 실제 적용 CVar와 컴포넌트의 density scaling 허용을 확인한다. 설정 파일 작성과 재시작 적용 검증은 다르다. |
| 로드된 나무도 거리별로 사라지는가 | 컴포넌트 cull·메시 LOD/원경 재질을 확인한다. 과거 큰 나무의 4km cull을 0/0으로 저장했으나 아래 복구 예외가 남아 있다. 0/0은 WP 언로드를 막는 설정이 아니다. |
| 원본 언로드 뒤 프록시가 나오는가 | HLODLayer 할당 외에 HashSet의 파티션/HLODSetups 허용 등록, 해당 구역 입력 포함, 프록시 최신성·표시 전환을 확인한다. 단순 HLOD 개수와 빌드 반환값으로 성공 판정하지 않는다. |

기존 `S00_Tree_25_28_34`는 별도 HLOD layer=None / 최대 표시 거리 0 상태였다는 진단이 있다. 전체 숲과 같은 조건의 비교 대상이 아니므로 해당 나무가 원경에서 보인다는 이유로 전체 숲 HLOD가 정상이라고 판단하지 않는다.

이전 인계의 수목 합계는 기존 PCG 69,692 + Nature 13,066 = 82,758그루이며 장소별 수동 나무는 별도다. 북동부 보강이 전체 산림의 완성을 뜻하지 않는다. 새 맵에서 이 수량·변환 보존을 다시 확인해야 한다.

수목 cull 변경 스크립트의 출력 경로 오류로 외부 액터 한 패키지에 JSON이 기록된 문제를 발견해 유효 백업으로 복구했다. 정책 JSON은 올바른 Source 위치로 분리했다. **복구한 액터는 변경 전 cull 값일 수 있으므로 해당 액터의 cull 0/0 재적용과 수량 보존 확인이 남아 있다.** 대상은 이전 맵의 `C/LL/S6WI6M7W1QA7CE59LOV348.uasset`이며 새 맵 대응 액터를 엔진에서 확인한다. 파일을 직접 덮어써서 다시 수정하지 않는다.

기존 WP는 RuntimeHashSet / MainGrid, 셀 252m·원본 로딩 768m라는 인계 기록이 있다. Forest HLOD의 허용 목록 등록 누락은 수정했지만 이후 프록시 빌드·PIE 전환은 미검증이다. HLODLayer의 legacy loading_range=5km를 HashSet의 실제 로딩 거리로 해석하지 않는다. 전체 HLOD 빌드는 Embree/MeshUtilities 메모리 고갈로 크래시한 이력이 있으므로, 메모리 여유와 대표 구역 시험 없이 전역 빌드를 반복하지 않는다.

지피는 기존 인계 기준 180~300m 거리 범위이며 중원경 전환 품질이 부족하다. 후속 아트에서는 가까운 풀 메시, 중경 군집·관목, 먼 지표 색·법선·숲 덩어리를 함께 설계한다. 모든 풀을 수 km까지 표시하는 것을 기본 해법으로 삼지 않는다.

## 6. 남은 공간·아트 작업과 권장 제작 방향

아래는 **후속 제안이며 구현 완료 사항이 아니다.** 목표는 채워 넣은 오브젝트 수보다 지형·생활·이동·시야가 읽히는 공간이다. [v4 기획](Project_J_8x8km_WorldGen_Completion_Expansion_v4.md), [v5 복구 지시](Project_J_World_Visual_Quality_Recovery_Codex_v5.md), [목표 월드맵](초반%20지역%208×8km%20판타지%20월드맵.png)을 함께 본다.

| 대상 | 현재 문제 | 다음 제작 방향 |
|---|---|---|
| 산악 | 단순한 둥근/급한 윤곽, 빈 중턱, 반복 암석 조형의 실패 이력이 있다. | 표고·경사·노출면에 따른 산림선, 계곡의 식생 집중, 능선의 암반과 완경사 수림을 구분한다. 같은 작은 암석을 전역에 반복 배치해 산을 덮지 않는다. |

MMORPG 관점에서는 초행자의 랜드마크, 복귀 동선, 사냥터 우회로, 파티 집결, 이동 병목과 카메라 여유를 함께 검토한다. 대규모 동접·서버 간 이동·경제/NPC 생활 구현이 이미 준비됐다고 가정하지 않는다. 건물 내부·수직 동선·군중 밀도는 실제 게임플레이·Nav·렌더 예산을 확인한 구역부터 확장한다.

## 7. 에셋 반입 범위

최신 요청의 원본은 `assets`, `MedievalVillage`, `MedievalVillageMegascansS` 세 프로젝트다. **GameAnimationSample/GASP는 전부 제외한다.** 환경 제작용 지형·건물·바위·나무·풀·소품과 필수 재질/텍스처 의존성만 채택한다. 효과/Niagara, 캐릭터·캐릭터 애니메이션, 오디오, 샘플 UI·입력·GameMode·데모 맵은 반입하지 않는다. 깃발·천 등 환경 소품의 SkeletalMesh와 필수 Skeleton/PhysicsAsset은 캐릭터 자산과 구분한다. 공유 환경 재질이 실제 사용하는 텍스처는 Demo/Effects 폴더에 있다는 이유만으로 제외하지 않는다.

원본을 보존하고 격리한 5.8 작업 프로젝트에서 엔진 API로 이동·참조 갱신·마이그레이션한다. 공급자 Config·C++·플러그인 코드를 함께 가져오지 않는다. 중복은 텍스처 픽셀·편집 속성, 메시 렌더 LOD/고해상도 원본/충돌, 재질·Blueprint 그래프 및 의존 경로를 비교한다. 동일 이름이나 경로 변경 후 파일 바이트 차이만으로 중복 여부를 결정하지 않는다. 기존 튜닝과 다른 자원은 `/Game/Map_Resource/Variants`에 보존한다.

환경 라이브러리는 `/Game/Map_Resource`의 공급자별 폴더를 사용한다. 후속 사용자 요청으로 기존 `/Game/Meshes`, `/Game/Materials`, `/Game/Megascans`, `/Game/ThirdParty`의 환경 자원도 엔진에서 이동·참조 재저장했다. 월드 전용 렌더 자원은 `/Game/Map_Resource/MainWorld`에 두고 manifest의 `resource_content_root`를 따른다. 환경 재질이 요구하는 설치 엔진의 `Water`, `Volumetrics` 콘텐츠 플러그인을 활성화했다. 이는 강·호수·바다 구현 완료를 의미하지 않는다.

검증을 마친 제작 대상 분류는 다음과 같다. 이 수는 조사한 전체 원본 파일 수나 데모 콘텐츠 수가 아니다. 세부 근거와 호환성 제한은 최신 인수인계의 마감 기록을 따른다.

| 원본 | 제작 자산 | 신규 반입 | 기존 자산 재사용 |
|---|---:|---:|---:|
| assets | 4,532 | 4,049 | 483 |
| MedievalVillage | 944 | 829 | 115 |
| MedievalVillageMegascansS | 2,080 | 404 | 1,676 |
| 합계 | 7,556 | 5,282 | 2,274 |

반입 당시에는 환경 구름용 StaticSparseVolumeTexture 3개, StaticMesh 2,213개, Texture2D 2,947개, MaterialInstance 1,346개, Material 262개, FoliageType 254개, Blueprint 126개 등이 포함됐다. 신규 중 543개는 기존 튜닝과 다른 변형이다. 이후 기존 환경 자원 2,195개와 별도로 남아 있던 효과 공유 노이즈·상호작용 자원도 Map_Resource로 모았다. 이 표와 수는 원본 반입 당시의 선정 집계이며 후속 통합·중복 재사용 이후 현재 파일 수와 같지 않다.

Packed Blueprint 56개가 사용하는 제작용 원본 레벨은 54개이며 외부 액터 453개를 함께 보존했다. 이 레벨은 편집·재조립용이므로 기본 플레이 맵이나 데모 맵으로 취급하지 않는다. 실제 배치에는 Blueprint를 사용하고, 원본 조립 레벨은 해당 프리팹을 수정할 때만 연다.

구형 `MeshToPoints`를 사용하는 PCG 그래프 12개는 원본을 UE5.8에서 읽어도 메시 입력이 남지 않는 호환성 제한이 있다. 기존 그래프·기본 메시 자원은 보존하며, PCG 재생성은 현대 노드로 변환·검증하기 전까지 보류한다. 베이크된 Packed Blueprint의 사용과 이 구형 PCG 생성기의 재실행을 혼동하지 않는다.

Content Browser의 공유 컬렉션 `Env_All`은 후속 통합을 반영한 환경 자원 7,647개를 찾으며 경로 유효성 검사를 통과했다. 월드 전용 환경 자원도 포함한다. 원본별 모음은 `Env_Assets`/`Env_Village`/`Env_Mega`, 프리팹과 편집용 레벨은 `Env_Prefabs`다. `Env_LegacyPCG`는 위 호환성 보류 자료이며 기본 모음에서 제외했다. 컬렉션은 경로 목록이므로 메시·텍스처를 다시 복제하지 않는다.

실제 소비자가 효과 시스템에만 한정된 재질·텍스처 등 48개와 EQS 샘플 표식 1개는 제작 목록에서 제외하고 `/Game/Developers/IntakeHold`에 보존했다. 원래 프로젝트에 있던 효과 자산은 건드리지 않았다. 환경 재질에도 쓰이는 공유 노이즈는 제외하지 않았다. 격리 자료는 로컬 보관하며 이번 커밋에서 제외한다. 제작용 라이브러리나 게임 진입점에 연결하지 않는다.

성채 부품의 빈 convex 충돌체를 엔진 Auto Convex로 복구했다. 식생의 Voxelize 형상 보존에는 `Config/DefaultEngine.ini`의 `r.Nanite.Foliage=1`이 필요하다. UE5.8 실험 기능이며 재시작 후 적용된다. 전체 자산 7,556개 등록·필수 참조와 경고 대상 19개 식생·수정 충돌체의 새 프로세스 검사는 오류 0·경고 0이었다. 전체 셰이더·실제 시각 품질·성능 합격을 뜻하지 않는다. 효과·소리 결합 Blueprint, 원본 필수 의존성이 없는 도로 재질과 데모 자산은 채택 범위에서 제외한다. 해당 건물·소품 메시 자체는 보존했다.

### Elderboom 원본 대조 — 2026-10-19

`Content/Map_Resource/ElderboomVillage`의 기존 자산을 원본 ElderBoomHollowMassiveMed와 대조했다. 환경 제작 자산380개는 모두 기존 반입분과 속성·필수 참조가 일치하며, 신규 반입0·신규 변형0·환경 누락0이다. 메시56개의 렌더/원본 LOD·충돌 형상과 전체 텍스처205개(환경192+효과13)의 원본 픽셀도 일치했다. 원본과 실제 프로젝트 파일은 변경하지 않았다. `Env_Elderboom`에서 환경380개를 찾으며 `Env_All`에도 기존 항목을 보존해 추가했다. 기존 효과29개와 데모 맵2개도 보존했지만 이번 환경 제작 범위의 합격 집계에는 넣지 않는다. 에셋 동등성 검사가 전체 셰이더·Niagara 동작·PIE·Cook·성능 합격을 의미하지는 않는다. 이전 세 원본의7,556개 반입 집계와 이번 기존380개 재사용을 구분한다.

## 8. 디자이너의 완료 확인과 기술 담당 인계

구역별로 맵·StableID·바꾼 에셋, 사용한 카메라와 품질 설정, 저장/재로드 결과, 미완료 항목을 짧게 남긴다. 대표 시점은 지상 플레이 시점·마을 진입·숲 가장자리·산악 원경으로 잡는다. 같은 시간대·해상도·화질·로드 상태에서 전후를 비교한다.

- 공간: 입구·문·계단·교량·부두 지지, 건물 충돌, 길과 보스 우회로, 실제 플레이어 이동·카메라를 확인한다. 기존 도보 통과를 최종 레벨 디자인 합격으로 확대하지 않는다.
- 스트리밍: 에디터 전체 로드 화면과 PIE 원본 언로드/HLOD 표시를 따로 확인한다. 고속 이동·텔레포트·탈것은 별도 조건이다.
- 표현·성능: 텍스처 예산 경고, GPU/프레임 시간·Game/Draw, 메모리·commit 여유와 하드웨어/화면 조건을 함께 남긴다. 현재 최종 환경의 유효한 성능 합격 수치는 없다. 예전 SP71 측정을 최신 결과로 쓰지 않는다.
- 인계: 누락 참조, 중복 이벤트 소유자, DA/Source 불일치, Nav·AI·퀘스트/보상 미연결은 기술 담당에게 구체적인 위치와 재현 조건을 전달한다.

이 문서는 현재 소스·Config·manifest·엔진 이관 영수증과 기존 인계를 대조해 작성했다. 환경 반입은 에디터 commandlet의 저장·재로드·참조·프리팹 장면·Blueprint 컴파일로 검증했다. 이번에 월드 PIE·Cook·전체 셰이더·성능 시험은 실행하지 않았다. 로컬 `Saved/WorldMigration`, `Saved/AssetIntake`, 이전 검증 캡처는 Git 제외 자료이므로 다른 PC에 자동 전달되지 않는다.
