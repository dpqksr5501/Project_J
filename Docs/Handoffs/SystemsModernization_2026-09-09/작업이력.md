## 1. 방향과 책임 분리

초기 목표는 멀티스레드·비동기 기술을 이해하고 프로젝트에 필요한 경계를 단계적으로 적용하는 것이었다. 기존 애니메이션은 이미 엔진 병렬 경로를 사용하고 있었다. 따라서 모든 UObject 코드를 Worker로 옮기기보다 다음 구조를 사용했다.

```text
GT: Actor/ASC/World 상태 → 값 스냅샷
Worker: UE::Tasks + ParallelFor 타깃 점수 계산
GT: epoch/revision/weak owner 재검증 → 판단/행동
GT: bounded Nav/asset 요청 → 엔진 비동기 계산/로딩 → GT 완료 적용
GT: animation snapshot/proxy → 엔진 animation update/evaluation → GT 결과 반영
ABA: 선택적 포즈 빈도 조절, 공격 경계에서는 즉시 일반 경로 복귀
```

GT 데이터 수집·적용과 Worker 값 계산을 분리하고, 논리적 취소와 실제 작업 종료를 구분했다. queue/in-flight/완료 적용의 상한, weak 참조/세대, 재진입, teardown을 기능과 함께 구현했다. 작은 입력의 병렬 overhead도 측정 결과로 남겼다.

## 3. A: 부하와 장비 경계

타깃 계산의 배치는 여러 요청마다 root task를 만드는 비용과 큐 전달 지연을 줄였다. 단일 계산을 무조건 병렬화하면 작은 입력에서는 더 느릴 수 있었다. A 실행은 두 프로세스의 합계 고유 34개 테스트 최종 통과이며, 34개가 한 번에 무중단 통과했다고 기록하지 않는다.

Navigation은 64 requests/16 actual in-flight/dispatch4/delivery8/GT 0.5ms soft budget. 취소돼도 완료 전 실제 탐색 예약을 유지한다. 우선순위는 유한 시간 가산으로 기아를 줄이며, 실패 재시도는 개체별 분산 지수 backoff를 쓴다. 동적 장애물 시험은 실제 Recast를 사용하되 수동 invalidate/Build를 포함했다. 이 기반을 C에서 확장한다.

장비 해제 병목은 style 변경 시 이전 profile로 새 weapon actor가 생겼다가 profile=None에서 다시 파괴되는 중간 상태였다. 표현 설정을 함께 적용하고 동일 표현의 Refresh는 기존 Actor를 유지하게 했다. Actor 생성/파괴는 GT에 유지했다.

### 실제 ABA 등록 정책

BaseCharacter의 기본 Mesh 컴포넌트를 budget-capable subclass로 교체했다. 월드 서비스는 weak registry 한 번의 정책 pass로 적격 비전투·비로컬 캐릭터를 등록한다. 공격은 공통 CombatHitValidation 경계에서 즉시 등록을 해제하고 visibility/URO/Notify 보호를 적용한다. 몽타주 재생·로컬 플레이어·DS·physics 등은 제외한다. 종료 후 원래 상태를 복원하고 다시 적격이면 등록한다. 별도 thread/pool은 추가하지 않았다.

엔진 unregister가 URO와 Tick을 켜는 부분까지 감안해 기존 값을 보존했다. OnAnimInitialized/OnMontageStarted 재바인딩, EndPlay/OnWorldCleanup 해제를 처리했다. 기본 프로젝트 기능은 on이며 플러그인은 runtime에도 활성화했다. 개발용 비교의 0.1ms를 운영 예산으로 지정하지 않았다.
