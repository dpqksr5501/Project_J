# 기본 대검 200명 렌더 부하 측정 — 2026-10-24

기본 대검 **200개를 표시하는 추가 GPU 비용은 약 0.48–0.68ms**였다. 정지·이동·동시 공격의 장면 전체 GPU 시간은 각각 6.34/6.29/6.64ms였다. 반면 이 standalone 권위 Avatar 합성 부하의 Game Thread는 약 1.8–2.0초로 매우 느렸고, 대검을 숨겨도 전체 프레임은 거의 같았다. 이 장면의 주병목은 CPU 측이며, 결과를 실제 원격 플레이어 200명의 클라이언트 FPS나 운영 서버 수용량으로 해석하지 않는다.

Ryzen 7 9800X3D / Radeon RX 9070 XT, 동일한 소스·바이너리·에셋에서 표시 → 숨김 → 숨김 → 표시 4회를 완료했다. 표시/숨김 모두 각 2회이며 동작·장착·렌더 관찰 검증을 통과했다. [수치 JSON](Data/Weapon200_20261024/Summary.json), [자료 SHA-256](Data/Weapon200_20261024/SHA256.json), [종료 후 지문 검사](Data/Weapon200_20261024/Postflight.json)에 반복별 수치·조건·원자료 연결을 보존한다.

아래는 **장면 전체 GPU 시간의 실행별 평균을 다시 평균한 값**이다. 추가 비용은 표시−숨김이며 대검 200개의 합계다.

이동 GPU는 표시 6.352/6.236ms, 숨김 5.862/5.758ms였다. 역순 반복에서도 추가 비용이 관찰됐다. 한 개당 비용을 단순 나눗셈으로 일반화하거나, 8–12% GPU 증가를 같은 비율의 FPS 저하로 바꾸지 않는다. 더 가까운 카메라, 높은 해상도, 다른 조명·그림자·GPU·스킨에서는 달라진다.

## 전체 프레임과 CPU 병목

| 동작 | 전체 Frame 숨김→표시(ms) | Game Thread 숨김→표시(ms) |
| --- | ---: | ---: |
| 정지 | 1869.216 → 1866.735 | 1833.632 → 1829.426 |
| 이동/방향 전환 | 1868.261 → 1873.124 | 1837.131 → 1838.343 |
| 200명 동시 공격 | 2156.469 → 2130.990 | 2031.087 → 2014.275 |

이 합성 장면의 실제 전체 처리율은 정지/이동 약 0.54FPS, 동시 공격 약 0.47FPS다. **200명 장면 전체가 목표 프레임을 만족했다는 결과가 아니다.** 숨김에서도 같은 수준으로 느리고, Frame 차이는 약 −1.2%~+0.3%로 작고 방향도 일관되지 않았다. GPU 수 ms와 대조되는 CPU 측 비용/대기가 지배적이다. 캐릭터·애니메이션·Cloth·Mover·게임플레이 중 정확히 어느 CPU 작업이 얼마를 차지하는지는 이번에 분리 프로파일링하지 않았다. 실제 네트워크 클라이언트의 SimulatedProxy 경로는 별도 측정이 필요하다.

네 실행의 전체 프로세스 peak working set은 각각 약 4.99GiB, private bytes는 16.63–16.66GiB였다. 이 값에는 시작·로딩·200 Avatar 전체가 포함되며 **무기 VRAM 또는 인원당 메모리가 아니다.** 숨김에서도 무기 Actor와 텍스처 참조를 유지하므로 메모리 해제 비교가 아니다.

## 검증과 보존

- direct UBT Editor 빌드 성공(345.67초). 1명 실RHI 숨김 스모크에서 전체 이동/전투/복귀와 로컬 품질·메시 검사를 먼저 통과했다.
- 200명 4회 모두 종료 코드 0, `success=1`, 모든 Avatar의 이동·방향 전환·착지와 실제 동시 공격·복귀 검사를 통과했다. 로컬 품질 표본은 실행당 100개였다.
- 최종 선택 표본은 총 216개다. 실행당 정지/이동/점프/복귀 각 12개와 동시 공격 6개이며, 낮은 표본 수의 p95를 안정적인 최악 프레임 보장으로 해석하지 않는다.
- 선택 표본의 몸체는 로컬 LOD0 1개와 LOD2 199개로 양쪽 모두 동일했다. 무기 200개 모두 정확한 새 메시와 자동 LOD 설정을 유지했다. 실제 렌더 관찰은 표시 200/숨김 0이었으며 몸체는 모두 200개였다. Nanite 의상 1,400개·의상 1,600개·활성 망토 200개가 유지됐다.
- 4회 manifest의 source/config/scripts/plugins/binary provenance와 보호 에셋 지문이 동일했다. 종료 후에도 소스·바이너리와 보호 파일 40개의 SHA-256이 같았다. 생산 에셋·품질 설정은 이 작업에서 저장/변경하지 않았다.
- 준비 중 PoseSearch 비동기 인덱스 안내와 큰 frame delta에 대한 AutomationController 안내는 원 로그에 유지한다. 측정 프로세스의 Python 오류·assert/ensure는 없었다. 실행 프로세스는 모두 정상 종료했다.
- 반복별 frames/workload CSV·결과·검증·프로세스 메모리 원자료는 동반 Data 하위에, 전체 실행 로그·manifest는 로컬 `Saved/Validation/WholeProjectAudit_20261013/Weapon200_*_20261024`에 유지한다. 새 PC에서 로컬 로그가 제공된다고 주장하지 않는다.

## 조건과 범위

현재 생산 `BP_GreatSword` 200개와 `SM_Greatsword_Basic` 200개를 기존 `Project_JRenderedCrowdFixture`에서 구성한다. 로컬 소유 1명과 AI가 조종하는 권위 Avatar 199명, Manny source·리타깃 몸체·의상 8개씩·활성 망토 Cloth를 포함한다. 의상 7개씩의 저장된 Nanite 경로를 양쪽 모두 사용한다. 서버/클라이언트 역할이 분리된 원격 200명이나 접속 200개의 부하가 아니다.

UE 5.8.4 Development Editor의 `-game -RenderOffscreen`, DX12 실제 RHI, 1280×720, ScreenPercentage 100, DynamicRes off, Epic 품질, VSync off, FPS cap 0이다. 간이 바닥·DirectionalLight·고정 FOV65 카메라와 20×10 배치를 사용한다. CPU/GPU 하드웨어와 실행 지문은 동반 수치 JSON에 기록한다. 에디터 전용 Python은 이 native headless 실행에만 비활성화한다.

표시 → 숨김 → 숨김 → 표시 순서로 새 프로세스에서 반복한다. 숨김은 장비를 해제하지 않고 무기 StaticMeshComponent의 visibility만 바꾼다. 장비 Actor·전투/능력·손/독립 무기 궤적·캐릭터·의상 물리는 유지한다. 따라서 차이는 주로 무기 메시와 그 그림자의 렌더 비용이며 무기 시스템 전체 CPU/VRAM의 제거 실험이 아니다. 표시/숨김 양쪽에서 정확한 메시 경로·장착 수·visibility를 검사하고 자동 LOD 설정과 실제 렌더 관찰 수를 CSV에 기록한다.

준비 8게임초 후 정지·왕복 이동/방향 전환·점프/착지·R 동시 공격·복귀를 각 8게임초 실행한다. 통계는 각 구간의 2–7게임초를 사용하고 스크린샷 요청 및 뒤 2프레임을 제외한다. 공격은 실제 몽타주 200개가 재생 중인 표본만 쓴다. 모든 Avatar의 이동 100cm 초과·방향 전환·착지·몽타주 종료와 로컬 몸체 LOD0/IK/retarget/예측 품질, Nanite 1,400개·의상 1,600개·활성 망토 200개를 검사한다. 무기는 로컬·원격 모두 기존 화면 크기 LOD를 사용한다.

프레임·Game/Render/RHI thread·GPU 시간은 병렬 실행 지표이므로 더하지 않는다. 구간별 실행 평균에 같은 가중치를 주며 p95는 nearest rank다. 낮은 프레임률의 표본 수, 지연된 GPU 카운터, 클럭/열/스케줄링 편차와 단순 조명/카메라 조건을 고려해야 한다. 전체 프로세스 peak 메모리는 시작·로딩을 포함하며 무기의 순수 VRAM이나 인원당 메모리가 아니다.

재사용 도구: `Scripts/Validation/Measure-RenderedCrowd.ps1`의 `-Count 200 -Movement -LocalPlayer -NaniteMode 1 -WeaponVisibility 0/1 -ExpectedWeaponMesh /Game/Weapons/Greatsword/Basic/SM_Greatsword_Basic.SM_Greatsword_Basic`, 집계는 `Scripts/Validation/Summarize-WeaponCrowd.py`를 사용한다. 게임플레이/에셋의 최적화나 저장 설정 변경은 이 측정 작업에 포함하지 않는다.
